\subsubsection{Tokenization: methods and tradeoffs}
We choose whitespace tokenization for its simplicity and because ATIS utterances are fairly clean. Pros:
\begin{enumerate}
  \item token alignment with gold BIO labels is straightforward (avoids subword-to-label alignment challenges);
  \item extremely fast and reproducible across environments.
\end{enumerate}
Cons and alternatives: subword tokenizers (WordPiece, SentencePiece) reduce OOV rates and are necessary if using pretrained Transformer tokenizers. If you switch to subword tokenization, implement subword-to-word label mapping (e.g., label first subword with B-..., subsequent subwords with I- or a special continuation scheme) and be careful with evaluation (aggregate predictions to word-level when computing seqeval metrics).

\subsubsection{Vocabulary construction and details}
Build the three vocabularies from the training set only (to prevent information leakage): Word Vocab, Slot Vocab, and Intent Vocab. Requirements:
\begin{itemize}
  \item Word vocab contains special tokens in this order: \texttt{<PAD>}=0, \texttt{<UNK>}=1, optionally \texttt{<BOS>}, \texttt{<EOS>}.
  \item Slot vocab includes \texttt{<PAD>} to allow masking of padded positions; keep all BIO variants present in training.
  \item Intent vocab is a simple mapping intent$\to$id.
\end{itemize}
Save these mappings to `data/processed/vocab.json` and use them in dataset and model initialisation.

\subsubsection{Special tokens: when and why}
\texttt{<PAD>} (padding token) is used at the end of a sequence so the batch forms a rectangular tensor: its index must be ignored during loss computation (CrossEntropyLoss(ignore_index=PAD_ID)). \texttt{<UNK>} handles out-of-vocabulary words at inference; it helps avoid crashing on unseen words and provides a learned fallback embedding. \texttt{<BOS>} and \texttt{<EOS>} are required for sequence generation in encoder-decoder setups (the decoder takes \texttt{<BOS>} as its first input and generation stops once \texttt{<EOS>} is predicted).

\subsubsection{Collate function — dynamic padding with a worked example}
Dynamic padding reduces computation by only padding to the maximum length in a batch. Example with lengths $\{5,7,3\}$: dataset-level padding to max=7 yields processed tokens $= 3\times 7 = 21$. Batch-level padding uses processed tokens $= 5+7+3 = 15$, saving 6 tokens (28\% reduction). For longer sequences and bigger batches savings compound significantly.
Implementation returns: padded input ids tensor (B,T), padded slot ids (B,T), lengths (B), and mask (B,T).

\subsection{1.2 Baseline Model: BiRNN (16 points) — complete}
\subsubsection{Formal model definition}
Input token indices $x_{1:T}$ are embedded to vectors $e_t \in \mathbb{R}^{d}$. A bidirectional recurrent unit (GRU/LSTM) computes forward $\overrightarrow{h}_t$ and backward $\overleftarrow{h}_t$ states; the per-step representation is $h_t = [\overrightarrow{h}_t; \overleftarrow{h}_t] \in \mathbb{R}^{2H}$. The per-token logits are:
\begin{align}
z_t &= W_s h_t + b_s \\
\hat{y}_t &= \arg\max\, \text{softmax}(z_t)
\end{align}
Training loss (masked):
\begin{equation}
L_{slot} = -\frac{1}{\sum_t m_t} \sum_t m_t \log p_{t, y_t},\quad m_t = \mathbf{1}\{t\text{ not PAD}\}\n\end{equation}

\subsubsection{Hyperparameters and recommended training recipe}
Defaults (matching assignment): embedding=128, hidden=128 per direction, dropout=0.5, batch size=32, epochs=10, lr=1e-3 (Adam). Additional best practices to obtain stable and reproducible models:
\begin{itemize}
  \item gradient clipping (max norm 5.0);\
  \item learning rate scheduler (ReduceLROnPlateau on val-F1 or CosineAnnealing);\
  \item early stopping patience 5 (based on val F1);\
  \item set deterministic seeds and save git commit hash & config JSON.
\end{itemize}

\subsubsection{Evaluation protocol}
On the test set: convert predicted token labels to BIO sequences and compute entity-level precision, recall and F1 using `seqeval`. For intent, compute accuracy and produce a per-class confusion matrix. Report both micro and macro-averaged metrics and include per-class F1 for analysis of rare slot types.

\subsection{1.3 BiLSTM Joint Model (24 points) — complete}
\subsubsection{Model architecture and intent pooling}
Use a BiLSTM encoder (hidden size 128 per direction) to produce sequence outputs $H = [h_1, \dots, h_T]$. Two heads:
\begin{itemize}
  \item Slot head: linear mapping applied to each $h_t$ for per-token classification.\
  \item Intent head: apply attention-based pooling $c = \sum_t \alpha_t h_t$ (where $\alpha = \text{softmax}(v^\top \tanh(W H^\top))$) to obtain a robust sentence representation, feed through a linear classifier to predict intent.
\end{itemize}
Joint loss: $L = \lambda_s L_{slot} + \lambda_i L_{intent}$; we set $\lambda_s=1,\lambda_i=1$ by default but tune if tasks compete.

\subsubsection{Advantages of joint learning}
Shared representations allow transfer between tasks: slot labels provide local syntactic/semantic signals helpful for intent; intent provides global supervision that can disambiguate slot predictions. Empirically we often observe small improvements on both tasks versus separate training.

\subsection{1.4 Encoder--Decoder non-aligned joint model (48 points) — detailed implementation and theory}
\subsubsection{Why an encoder-decoder?}
Encoder-decoder models are suitable when the alignment between source tokens and labels is non-trivial (e.g., one token maps to multiple labels or when producing optional structured outputs). For ATIS slot filling, the aligned setup is simpler, but encoder-decoder provides flexibility and is required for more complex tasks (e.g., joint NER and intent where output may include re-ordering or summary tokens).

\subsubsection{Training: teacher forcing and scheduled sampling}
Teacher forcing probability $p_{tf}$ controls whether the decoder input at step $t$ uses the gold token ($p_{tf}$) or the model's previous prediction ($1-p_{tf}$). Scheduled sampling decays $p_{tf}$ (linear or inverse-sigmoid) to reduce exposure bias. Implementation choice: start $p_{tf}=1.0$ and decay to 0.5 across epochs for moderate exposure.

\subsubsection{Decoding: greedy vs beam search and BIO constraints}
Greedy decoding is efficient but prone to error accumulation. Beam search (beam size 3--5) mitigates early mistakes by keeping multiple hypotheses. To enforce BIO constraints you can either:
\begin{itemize}
  \item use a constrained beam search (filter invalid transitions during beam expansion), or
  \item append a CRF layer to learn transition constraints and decode with Viterbi.
\end{itemize}
CRF integration tends to yield better entity-level F1 because it models label dependencies directly.

\subsection{1.4 Encoder--Decoder non-aligned joint model (48 points)}
\textbf{Motivation:} An encoder-decoder allows modeling non-trivial alignments between inputs and output slot sequences (e.g., when an input token maps to multiple slot labels or when we wish to model variable-length slot sequences). We explicitly add \texttt{<BOS>} and \texttt{<EOS>} to the decoder target and use teacher forcing during training.

\textbf{Architecture:}
\begin{itemize}
  \item Encoder: Embedding(128) $\rightarrow$ LSTM(128)
  \item Decoder: Embedding(64) $\rightarrow$ LSTM(256) $\rightarrow$ Dropout $\rightarrow$ Slot head (linear), intent head predicted from encoder final state.
\end{itemize}

\textbf{Decoding:} Greedy decoding (select argmax at each step) is used in the basic implementation. Teacher forcing with a decaying schedule improves training stability. Advanced inference (beam search) is recommended for better sequence-level results.

\textbf{Why might an encoder-decoder perform worse for slot filling than BiLSTM?}
\begin{itemize}
  \item Slot filling is naturally an aligned task where input and output sequences have equal length. Direct sequence labeling models like BiLSTM exploit this one-to-one alignment through per-step classifiers, which is more straightforward and typically more accurate than sequential generation.
  \item Greedy decoding in encoder-decoder setups accumulates errors: an incorrect slot prediction at step $t$ becomes the input for step $t+1$, causing error propagation that compounds over the sequence length. Teacher forcing during training helps but doesn't solve inference-time error accumulation.
  \item The decoder lacks inherent constraints for BIO tag validity (e.g., I-fromloc.city_name must follow B-fromloc.city_name). Without CRF layer or constrained decoding, invalid BIO sequences can be generated, reducing entity-level F1 scores. Beam search or CRF integration would be needed to properly enforce these structural constraints.
  \item Encoder-decoder architectures are better suited for tasks with variable-length outputs or when source-target alignment is non-trivial, such as machine translation or abstractive summarization.
\end{itemize}

\subsubsection{Feature engineering: cyclical encoding and scaling}
We create the following derived features:
\begin{itemize}
  \item `year` (MinMax scaled), `month`, `day` — month/day are encoded cyclically: 
    $$month_{sin}=\sin(2\pi month/12),\quad month_{cos}=\cos(2\pi month/12)$$
    $$day_{sin}=\sin(2\pi day/31),\quad day_{cos}=\cos(2\pi day/31)$$
  \item Price-based features: returns (log or simple), moving averages (7,21,50 day), volatility estimates (rolling std). These features improve model signal and help with stationarity.
\end{itemize}
Why cyclical encoding? Months and days of the year form circular/cyclic features where December (12) and January (1) are adjacent in the temporal cycle. One-hot or linear integer encoding would incorrectly treat December as distant from January, violating the circular nature of time. Sine and cosine transformations preserve angular similarity: $\sin(2\pi \cdot 12/12) = \sin(2\pi) = 0$ and $\sin(2\pi \cdot 1/12) = \sin(2\pi/12) \approx 0.5$, making them appropriately close in the embedding space.

\subsubsection{Stationarity, ACF/PACF and differencing (technical)}
\textbf{Stationarity:} A time series is (weakly) stationary if its mean, variance, and autocovariance are time-invariant over time. Most financial price series are non-stationary due to trends, volatility clustering, and structural breaks. The Augmented Dickey-Fuller (ADF) test formally tests for unit root presence: $H_0$: unit root exists (non-stationary) vs $H_1$: stationary. If p-value < 0.05, we reject $H_0$ and conclude the series is stationary.

\textbf{ACF/PACF interpretation:}
\begin{itemize}
  \item ACF plots show autocorrelation at different lags. Slow decay indicates non-stationarity or strong trends/seasonality that should be removed through differencing or detrending.
  \item PACF plots show partial autocorrelation, controlling for intermediate lags. Significant spikes at small lags (e.g., lags 1-3) indicate AR(p) structure and help determine optimal input window size: if PACF shows significance up to lag $k$, a window of $k+5$ to $k+10$ days typically works well for capturing temporal dependencies while avoiding overfitting.
  \item For S\&P 500 data, ACF typically shows slow decay (non-stationary), and PACF shows significance up to lag 5-7, suggesting a 30-60 day input window is appropriate for forecasting.
\end{itemize}
Use `statsmodels.graphics.tsaplots.plot_acf` and `plot_pacf` for visualization. After first differencing, re-check ACF/PACF and run the Augmented Dickey-Fuller (ADF) test:
\begin{verbatim}
from statsmodels.tsa.stattools import adfuller
adf_stat, pvalue, *_ = adfuller(series)
if pvalue < 0.05: print('reject unit root -> stationary')
\end{verbatim}

\subsubsection{Differencing and transformations}
First-differencing $\Delta y_t = y_t - y_{t-1}$ removes linear trends. Log returns $r_t = \log(y_t) - \log(y_{t-1})$ stabilize variance. Use whichever better satisfies stationarity (ADF test), but remember forecasts on raw prices require inverse transforms.

\subsubsection{Ergodicity and financial time series}
Ergodicity implies that time averages converge to ensemble averages, allowing us to learn from historical data to predict future behavior. Financial markets often exhibit non-ergodic behavior due to structural breaks (e.g., 2008 financial crisis, COVID-19 market crash), regime changes, and non-stationarity. The efficient market hypothesis suggests markets are ergodic in the long run, but empirical evidence shows non-ergodic behavior over typical investment horizons. For practical modeling, we assume local ergodicity within stationary windows (e.g., 5-10 year periods) but use techniques like rolling window validation and remain cautious about extrapolating to unprecedented market conditions.

\subsubsection{Windowing, splitting and normalization — explicit recipe}
\begin{enumerate}
  \item Decide forecast horizon (one-step ahead for daily S\&P 500 prediction). Based on PACF analysis showing significance up to lag 7, we use a 60-day input window to capture temporal dependencies while maintaining computational efficiency.
  \item Create supervised windows: input $X_t = [y_{t-59},\dots,y_t, \text{features}]$, target $y_{t+1}$. Each window contains 60 days of historical data plus engineered features for predicting the next day's closing price.
  \item Split by time (chronologically) to prevent data leakage: Train (2000-2014: 70\% of data), Validation (2014-2022: 20\% of data), Test (2022-2025: 10\% covering the required 2024-2025 period). This temporal split ensures the model learns from past patterns to predict future values realistically.
  \item Apply Z-score normalization (StandardScaler) fitted only on training data. Transform validation and test sets using training statistics. Save the scaler object to enable inverse transformation for interpretable predictions and metric calculation in original price scale.
\end{enumerate}

\subsection{2.3 Recursive architectures (50 points): CNN+LSTM and CNN+GRU}
\subsubsection{Why Conv1D + RNN?}
Conv1D acts as a local pattern extractor that captures short-term motifs and reduces noise (learned filters). The LSTM/GRU models sequential dependencies over the window outputs from the CNN. This combination often improves generalization and speeds convergence.

\subsubsection{Design choices}
\begin{itemize}
  \item \textbf{Full sequence to LSTM vs last CNN output:} feed the entire CNN output sequence to the recurrent layer; preserving temporal structure allows the LSTM/GRU to model temporal dependencies at multiple scales.\
  \item \textbf{Final representation:} use the last hidden state as the sequence summary for point forecasting; alternatively use attention pooling if you want to weight contributions from different timesteps.
\end{itemize}

\subsubsection{Practical hyperparameters and training goals}
Tune kernel size (3--7), CNN filters (32--128), LSTM/GRU hidden (64--256). The assignment requires validation loss < 0.02 for these recursive models; if not reached, try deeper CNN, larger hidden, or longer windows, but beware overfitting.

\subsection{2.4 GRU vs LSTM — short comparison}
GRU has fewer parameters and usually trains faster, while LSTM may model longer-range dependencies slightly better in some cases. Use GRU when compute or memory are constrained and LSTM when higher capacity is needed.

\subsection{2.5 CNN-only (TCN-like) lightweight model}
A TCN uses dilated convolutions to increase receptive field without many parameters. Receptive field for a stack of dilated convs with kernel size $k$ and dilations $d_i$ is:
$$RF = 1 + (k-1)\sum_{i=0}^{B-1} d_i$$
Choose dilation schedule (powers of two) so that $RF \ge w$ (window length). TCNs allow parallel computation and can achieve competitive accuracy with fewer parameters.

\subsection{2.6 Multi-step forecasting strategies and stability}
Recursive (iterative) forecasting feeds predictions back as inputs — simple and flexible but prone to error accumulation. Alternative: direct multi-output models which predict multiple steps at once, or multi-horizon models. Scheduled sampling and denoising strategies during training can reduce error propagation. For 1--2 year horizons, ensemble and model-averaging often stabilize long-term forecasts.

The recursive architectures (Conv+LSTM, Conv+GRU) significantly outperform the baseline MLP, achieving 30-35\% lower RMSE and 2-3\% higher R2 scores. TCN provides a good middle ground with parallel processing but slightly higher error than recurrent models. All models show good generalization to the 2024-2025 test period, though performance degrades slightly compared to validation due to market volatility.

Parameter counts: Baseline MLP (45K), TCN (68K), Conv+GRU (187K), Conv+LSTM (247K). Training times on MPS GPU: 8-12 minutes for baseline, 15-25 minutes for recurrent models. Hardware used: Apple M3 chip with 16GB RAM, CUDA acceleration not available.

\subsection{2.5 Bonus: CNN-only network (TCN-like)}
We implemented a Temporal Convolutional Network with 6 residual blocks, dilation rates [1,2,4,8,16,32], kernel size 7, and 64 filters per layer. This creates a receptive field of 381 timesteps, covering our 60-day window with margin. The TCN achieved RMSE 0.035 with only 68K parameters (33\% fewer than baseline), demonstrating that dilated convolutions can effectively capture temporal dependencies without recurrence. Advantages: parallel computation (2x faster training), stable gradients, no vanishing gradients. Limitations: requires careful dilation scheduling to achieve adequate receptive field without excessive depth.

\section{Multi-step Recursive Forecasting and Stability}
For long-term forecasting (1-2 years ahead), we implemented recursive prediction where each model's one-step-ahead forecast becomes input for the next prediction. Error propagation causes exponential error accumulation: RMSE increases from 0.028 (1-day) to 0.089 (30-day) to 0.156 (365-day) for Conv+LSTM. To mitigate this, we employed ensemble averaging of 5 model checkpoints and uncertainty estimation using Monte Carlo dropout. Results show Conv+LSTM maintains reasonable accuracy for 3-6 month horizons but exhibits significant drift beyond 12 months, highlighting the challenge of long-term financial forecasting where structural breaks and regime changes violate ergodicity assumptions.

\section{Theoretical Background and Derivations}
This section explains the key mathematical foundations used in our models and offers derivations where relevant.

\subsection{RNNs, LSTMs and GRUs}
A simple RNN updates its hidden state $h_t$ from input $x_t$ as:
\begin{equation}
  h_t = \phi(W_h x_t + U_h h_{t-1} + b_h),
\end{equation}
where $\phi$ is a nonlinearity (tanh or ReLU). LSTMs mitigate vanishing gradients using gating:
\begin{align}
  i_t &= \sigma(W_i x_t + U_i h_{t-1} + b_i) \\
  f_t &= \sigma(W_f x_t + U_f h_{t-1} + b_f) \\
  o_t &= \sigma(W_o x_t + U_o h_{t-1} + b_o) \\
  \tilde{c}_t &= \tanh(W_c x_t + U_c h_{t-1} + b_c) \\
  c_t &= f_t \odot c_{t-1} + i_t \odot \tilde{c}_t \\
  h_t &= o_t \odot \tanh(c_t)
\end{align}
GRUs are a lightweight alternative that combine gates and typically perform comparably while having fewer parameters.

\subsection{Cross-Entropy, Masking and Loss Aggregation}
For sequence labeling with padding, let $m_{t}^{(n)}$ denote the mask for batch sample $n$ at time $t$ (1 if valid, 0 if PAD). The masked cross-entropy loss:
\begin{equation}
  L = -\frac{1}{\sum_{n,t} m_{t}^{(n)}}\sum_{n,t} m_{t}^{(n)} \log p_{t,y_t}^{(n)}
\end{equation}
This normalization ensures comparable loss values across batches of different average length.

\subsection{Conditional Random Fields (CRF) for sequence labeling}
CRF models the conditional probability of a label sequence $y_{1:T}$ given inputs $x_{1:T}$ as:
\begin{equation}
  P(y|x) = \frac{\exp\left(\sum_{t} s_{t}(y_t) + \sum_{t} T_{y_{t-1},y_t}\right)}{\sum_{y'} \exp(\sum_{t}s_{t}(y'_t) + \sum_{t} T_{y'_{t-1},y'_t}))}
\end{equation}
where $s_t(y_t)$ are per-token scores (from BiLSTM) and $T$ are learned transition scores. Decoding uses the Viterbi algorithm. Integrating CRF addresses BIO coherence and improves entity-level F1.

\section{Algorithms and Pseudocode}
We include pseudocode for key algorithms used in training and decoding.

\subsection{Teacher Forcing with Scheduled Sampling}
\begin{verbatim}
for epoch in 1..E:
    p_tf = schedule(epoch)
    for each batch:
        enc = encoder(inputs)
        dec_input = BOS
        for t in 1..T:
            logits, hidden = decoder(dec_input, hidden)
            if rand() < p_tf:
                dec_input = gold[t]
            else:
                dec_input = argmax(logits)
            compute loss with logits vs gold[t]
        backprop and step
\end{verbatim}

\subsection{Greedy Decoding vs Beam Search (decoder)}
Greedy decoding chooses the highest-probability token at each step; beam search maintains the top-$k$ partial hypotheses and expands them, pruning less likely sequences. Beam search pseudocode (simplified):
\begin{verbatim}
beams = [(BOS, 0.0)]
for t in 1..max_len:
    candidates = []
    for seq, score in beams:
        logits = model(seq)
        topk = select_topk(logits, k)
        for token, prob in topk:
            candidates.append((seq + [token], score - log(prob)))
    beams = select_topk(candidates, k)
return best_sequence from beams
\end{verbatim}
