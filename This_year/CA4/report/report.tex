\textbf{Tokenization.} We use whitespace tokenization for ATIS because utterances are short and pre-tokenized in most ATIS variants. For reproducibility we implement a small `WhitespaceTokenizer` (lowercasing optional). Alternative tokenizers (WordPiece/SentencePiece) are supported in the code base and can be used if subword generalization is desired.

\textbf{Vocabularies.} We build:
\begin{itemize}
  \item Word vocabulary (indexed with special tokens: \texttt{<PAD>}, \texttt{<UNK>}, and optionally \texttt{<BOS>}/\texttt{<EOS>} for decoder models).
  \item Slot vocabulary (BIO tags; e.g. B-fromloc.city_name, I-fromloc.city_name, O).
  \item Intent vocabulary (unique intent labels).
\end{itemize}

\textbf{Special tokens:} \texttt{<PAD>} is used to pad sequences in a batch to a uniform length; this token must be assigned a fixed id (conventionally 0). \texttt{<UNK>} is used when a word is not present in the training vocabulary (OOV) at inference or validation time. \texttt{<BOS>} and \texttt{<EOS>} tokens are needed for the encoder--decoder joint model which generates variable-length slot sequences.

\textbf{Train/Val/Test split and sampling:} When explicit `train/dev/test` files are present we use them; otherwise we shuffle the data and take 70\%/10\%/20\% splits preserving random seed for reproducibility. For sequence labeling experiments we avoid shuffling time sequences but random sampling over the utterance dataset is allowed.

\subsubsection{Collate function (dynamic padding)}
Our `collate_fn` pads each batch to the maximum length present in that batch using the pad id. Example: first batch padded length = 12, second batch = 8. Benefits of batch-level dynamic padding:
\begin{itemize}
  \item Reduced computation: less padding tokens processed by RNNs/embeddings.
  \item Lower memory use: smaller GPU memory footprint per batch.
  \item Improved efficiency for variable-length data (short utterances common in ATIS).
\end{itemize}
We also implement a `collate` that returns lengths and a boolean mask for loss and metric calculation to ignore padded positions.

\subsection{1.2 Baseline Model: BiRNN (16 points)}
\textbf{Model architecture:} Embedding(128) $\rightarrow$ Bi-RNN (128 hidden per direction) $\rightarrow$ Dropout(0.5) $\rightarrow$ Linear to slot label vocabulary per token. For the RNN cell we use either GRU or vanilla RNN if requested; in the final experiments we use GRU/LSTM variants.

\textbf{Training:} CrossEntropyLoss (per-token, with ignore\_index set to PAD id), optimizer Adam, lr 1e-3, batch size 32, epochs 10. We monitor training loss, validation loss, token accuracy and slot F1.

\textbf{Evaluation:} For slot filling we report sequence-level F1 using `seqeval` since token accuracy is biased by the majority O tag. We also provide classification report per slot-type (precision/recall/F1). We save per-epoch model checkpoints and the best model by validation F1.

\textbf{Expected outcomes:} BiRNNs perform well on aligned sequence labeling tasks; expected F1 on ATIS slot filling is usually high (over 80\% for strong models). The demo notebook includes a short run to generate figures for the report.

\subsection{1.3 BiLSTM Joint Model (24 points)}
\textbf{Model design:} Single shared Bi-LSTM encoder with two heads:
\begin{itemize}
  \item Intent head: mean pooling (or max pooling / using final hidden state) followed by a Linear classifier over intents.
  \item Slot head: linear layer applied to the sequence outputs (per-time-step logits over slot labels).
\end{itemize}

\textbf{Loss:} Combined loss: $L = L_{slot} + L_{intent}$ where $L_{slot}$ is cross-entropy over token labels (with padding ignored) and $L_{intent}$ is cross-entropy over intent classes. If needed, weights $\alpha$ or task uncertainty weighting can be added: $L = \lambda_s L_{slot} + \lambda_i L_{intent}$.

\textbf{Evaluation and comparison:} We report intent accuracy and slot F1. Joint models can improve intent detection thanks to shared representations; slot performance may also benefit due to auxiliary supervision.

\subsection{1.4 Encoder--Decoder non-aligned joint model (48 points)}
\textbf{Motivation:} An encoder-decoder allows modeling non-trivial alignments between inputs and output slot sequences (e.g., when an input token maps to multiple slot labels or when we wish to model variable-length slot sequences). We explicitly add \texttt{<BOS>} and \texttt{<EOS>} to the decoder target and use teacher forcing during training.

\textbf{Architecture:}
\begin{itemize}
  \item Encoder: Embedding(128) $\rightarrow$ LSTM(128)
  \item Decoder: Embedding(64) $\rightarrow$ LSTM(256) $\rightarrow$ Dropout $\rightarrow$ Slot head (linear), intent head predicted from encoder final state.
\end{itemize}

\textbf{Decoding:} Greedy decoding (select argmax at each step) is used in the basic implementation. Teacher forcing with a decaying schedule improves training stability. Advanced inference (beam search) is recommended for better sequence-level results.

\textbf{Why might an encoder-decoder perform worse for slot filling than BiLSTM?}
\begin{itemize}
  \item Slot filling is naturally an aligned task (input length $$ output length). Direct sequence labeling models exploit this alignment via per-step classifiers, which is simpler and often more accurate.
  \item Greedy decoding accumulates errors: an incorrect slot at step $t$ will be fed to the decoder as input for step $t+1$ (unless teacher forcing applied), causing error propagation.
  \item Decoder does not enforce BIO consistency (e.g., I- tags must follow B- tags of same type). A CRF or constrained decoding (or beam search) can mitigate this.
\end{itemize}

\section{Question 2: Stock Price Prediction using Recursive Architectures}
\subsection{2.1 Data Preprocessing (20 points)}
\textbf{Feature engineering:} We download ^GSPC via `yfinance`. Key features: Open, High, Low, Close. We add date-derived features (year, month, day) and cyclical encodings:
\begin{equation}
  x_{month\\_sin} = \sin\left(2\pi \cdot \frac{month}{12}\right), \quad x_{month\_cos} = \cos\left(2\pi \cdot \frac{month}{12}\right)
\end{equation}
Cyclical encoding is necessary to preserve proximity (e.g., December (12) and January (1) are close) which is lost if raw month indices are used.

We scale Year using MinMax and apply Z-score normalization for numeric features used in models (fit on Train, applied to Val and Test).

\textbf{Stationarity, ACF/PACF and differencing:} We compute ACF and PACF for Close to estimate temporal dependencies. If the ACF decays slowly and the ADF test indicates non-stationarity (p-value higher than threshold), we apply first differencing:
\begin{equation}
  y_t' = y_t - y_{t-1}.
\end{equation}
Differencing generally removes trends and slows the decay of the ACF, which helps make the series more suitable for models that assume stationarity. We include plots `sp500_acf_close.png` and `sp500_acf_close_diff.png` in the report.

\textbf{Ergodicity:} Ergodicity refers to equivalence between time averages and ensemble averages. Financial price processes are usually not strictly ergodic due to regime shifts and non-stationarity; in practice we assume local stationarity over short windows for modeling and forecasting.

\textbf{Windowing and splitting:} Using ACF/PACF results we choose an input window length (e.g., 30--90 days depending on decay) and a one-step or multi-step forecast horizon. We split chronologically: Train 70\%, Val 20\%, Test 10\% and ensure the test set covers 2024--2025. No shuffling is used to avoid information leakage. Normalization: fit Z-score scaler on Train and apply to Val/Test.

\subsection{2.2 Baseline MLP (10 points)}
\textbf{Architecture:} MLP with 2 hidden layers, each with BatchNorm and Dropout, ReLU activations. Optimizer: AdamW with weight decay. Loss: MSE. Save the model with lowest validation loss (early stopping by patience).

\textbf{Evaluation:} We compute RMSE, MAE, MAPE and R2 on the test set over the original scale (inverse transform predictions if necessary). Thresholds: validation loss < 0.70 (normalized) is the assignment success criterion for the baseline.

\subsection{2.3 Recursive Neural Network Models (50 points)}
\textbf{CNN+LSTM (LSTM variant):} We use Conv1D to extract local features across the window (it acts as a short-term pattern detector), then feed the full CNN feature sequence into an LSTM. The LSTM processes the sequence and we use the last hidden state for final prediction. Which to use: send the full sequence rather than only the last CNN output because the LSTM should model temporal dynamics over the entire window.

\textbf{Conv+GRU:} Replace LSTM with GRU to compare capacity and training speed. We keep parameter counts similar for fair comparison.

\textbf{Training target:} Validation loss < 0.02 is the assignment requirement for these recursive models; we report hyperparameters and parameter counts in the final report table.

\section{Multi-step Recursive Forecasting and Stability}
For long-horizon forecasts we perform recursive multi-step forecasting: predicted step $t+1$ is fed back as input for the next prediction. Error propagation and drift are common — use of teacher forcing during training or scheduled sampling and ensembling can reduce this problem. We present experiments and plots showing stability over 1--2 year horizons and discuss observed degradation.

\section{Evaluation Metrics and Implementation Notes}
\textbf{SLU metrics:} Slot F1 (seqeval), slot classification reports, intent accuracy and confusion matrices.

\textbf{Time-series metrics:}
\begin{align}
\text{RMSE} &= \sqrt{\frac{1}{n} \sum_{i=1}^n (y_i - \hat{y}_i)^2} \\
\text{MAE} &= \frac{1}{n} \sum_{i=1}^n |y_i - \hat{y}_i| \\
\text{MAPE} &= \frac{100}{n} \sum_{i=1}^n \left|\frac{y_i - \hat{y}_i}{y_i}\right| \\
R^2 &= 1 - \frac{\sum_i (y_i - \hat{y}_i)^2}{\sum_i (y_i - \overline{y})^2}
\end{align}
