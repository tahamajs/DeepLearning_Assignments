\subsubsection{Tokenization: methods, tradeoffs, and implementation considerations}

Tokenization represents a critical preprocessing decision that directly impacts model performance, computational efficiency, and task complexity. For the ATIS dataset, we employ whitespace tokenization as the primary strategy, informed by careful analysis of the data characteristics and task requirements.

\textbf{Whitespace Tokenization Rationale:}
The ATIS dataset exhibits several properties that make whitespace tokenization particularly suitable:
\begin{enumerate}
  \item \textbf{Data Quality}: Utterances are relatively clean with minimal punctuation and consistent spacing, reducing tokenization artifacts.
  \item \textbf{BIO Label Alignment}: Direct correspondence between whitespace tokens and gold BIO labels simplifies the learning objective and avoids complex subword-to-word label aggregation.
  \item \textbf{Computational Efficiency}: Extremely fast preprocessing with minimal computational overhead, enabling rapid experimentation.
  \item \textbf{Reproducibility}: Deterministic tokenization across different environments and Python versions.
  \item \textbf{Interpretability}: Token-level predictions directly correspond to human-readable words, facilitating error analysis and model debugging.
\end{enumerate}

\textbf{Technical Implementation Details:}
Our tokenizer implements case-insensitive processing (converting all text to lowercase) to reduce vocabulary size and improve generalization. Special handling is required for:
\begin{itemize}
  \item \textbf{Contractions}: Words like "don't" are treated as single tokens to preserve semantic meaning.
  \item \textbf{Numbers and Dates}: Numeric sequences (e.g., "747", "11am") remain intact as they carry specific semantic information.
  \item \textbf{Abbreviations}: Common abbreviations like "BOS" (Boston airport code) are preserved.
\end{itemize}

\textbf{Alternative Tokenization Strategies and Tradeoffs:}

While whitespace tokenization serves our purposes effectively, several alternative approaches offer different advantages:

\textbf{Subword Tokenization (WordPiece/SentencePiece):}
\begin{itemize}
  \item \textbf{Advantages}: Significantly reduces out-of-vocabulary (OOV) rates by decomposing rare words into frequent subword units. Enables use of pretrained Transformer tokenizers (BERT, RoBERTa) for transfer learning.
  \item \textbf{Challenges}: Requires complex label mapping strategies. For BIO tagging, the first subword inherits the B- or I- label, while subsequent subwords receive special continuation markers or are masked during evaluation.
  \item \textbf{Implementation Complexity}: Need to implement word-level aggregation for seqeval metrics, as subword predictions must be combined into word-level predictions for meaningful evaluation.
\end{itemize}

\textbf{Character-level Tokenization:}
\begin{itemize}
  \item \textbf{Advantages}: Eliminates OOV entirely, handles morphological variations naturally.
  \item \textbf{Challenges}: Significantly increases sequence lengths and computational requirements. Requires CNN or specialized architectures to capture word-level semantics.
\end{itemize}

\textbf{Morphological Tokenization:}
\begin{itemize}
  \item \textbf{Advantages}: Linguistically informed tokenization that respects word boundaries and morphological structure.
  \item \textbf{Challenges}: Requires language-specific tools and increases preprocessing complexity.
\end{itemize}

\textbf{Hybrid Approaches:} Modern systems often combine multiple tokenization strategies, using statistical subword tokenization for general text processing while maintaining word-level alignments for structured prediction tasks.

For this assignment, whitespace tokenization provides the optimal balance of simplicity, effectiveness, and interpretability, though our codebase includes hooks for alternative tokenizers to facilitate future experimentation.

\subsubsection{Vocabulary construction and implementation details}

Vocabulary construction represents the bridge between raw text data and numerical representations suitable for neural network processing. We construct three separate vocabularies from the training set only to prevent information leakage into validation and test performance metrics.

\textbf{Word Vocabulary Construction:}
The word vocabulary maps textual tokens to integer indices, incorporating special tokens for handling various edge cases:
\begin{itemize}
  \item \texttt{<PAD>} (index 0): Used for batch padding to ensure uniform sequence lengths. Must be masked during loss computation.
  \item \texttt{<UNK>} (index 1): Handles out-of-vocabulary words encountered during inference. Represents approximately 2-3\% of test tokens in ATIS.
  \item \texttt{<BOS>} (index 2): Beginning-of-sequence marker for encoder-decoder models requiring explicit sequence start indication.
  \item \texttt{<EOS>} (index 3): End-of-sequence marker for decoder generation termination and sequence length control.
\end{itemize}

Vocabulary building follows a systematic process:
\begin{enumerate}
  \item Collect all unique tokens from training utterances
  \item Sort tokens by frequency (most frequent first) for optimal embedding learning
  \item Reserve indices 0-3 for special tokens
  \item Assign remaining indices sequentially
  \item Implement frequency thresholding to filter rare words (optional, set to minimum frequency 1 for ATIS)
\end{enumerate}

\textbf{Slot Label Vocabulary:}
The slot vocabulary handles the BIO tagging scheme with 120 unique labels:
\begin{itemize}
  \item Includes \texttt{<PAD>} token for padding positions in batch processing
  \item Maintains all BIO variants observed in training data
  \item Examples: \texttt{B-fromloc.city\_name}, \texttt{I-fromloc.city\_name}, \texttt{B-toloc.city\_name}, \texttt{O}
  \item No \texttt{<UNK>} token needed since all possible slot types are known at training time
\end{itemize}

\textbf{Intent Label Vocabulary:}
Simple classification mapping for the 21 intent categories:
\begin{itemize}
  \item Direct string-to-integer mapping without special tokens
  \item Deterministic ordering (alphabetical sort) for reproducibility
  \item Examples: \texttt{atis\_aircraft} $\to$ 0, \texttt{atis\_airfare} $\to$ 1, \texttt{atis\_flight} $\to$ 2
\end{itemize}

\textbf{Implementation Considerations:}
\begin{itemize}
  \item \textbf{Memory Efficiency}: Vocabularies are stored as efficient dictionary structures with fast lookups
  \item \textbf{Persistence}: All vocabularies saved to `data/processed/vocab.json` using JSON serialization
  \item \textbf{Model Integration}: Vocabularies passed to dataset classes and model initialization functions
  \item \textbf{Extensibility}: Design supports dynamic vocabulary expansion for domain adaptation scenarios
\end{itemize}

\textbf{Vocabulary Statistics and Analysis:}
The ATIS word vocabulary contains approximately 800-900 unique tokens after preprocessing, reflecting the domain-specific nature of travel queries. Slot vocabulary size (120) indicates fine-grained semantic categorization, while the compact intent vocabulary (21 classes) represents manageable classification complexity. These statistics inform model capacity decisions and provide baseline expectations for generalization performance.

\subsubsection{Special tokens: comprehensive roles and implementation}

Special tokens serve as control signals that enable neural networks to handle variable-length sequences, unknown inputs, and structured generation processes. Their proper implementation is crucial for both training stability and inference correctness.

\textbf{Padding Token (<PAD>):}
The padding token solves the fundamental challenge of batch processing variable-length sequences in tensor-based frameworks:
\begin{itemize}
  \item \textbf{Purpose}: Enables creation of rectangular tensors by extending shorter sequences to match the longest sequence in a batch
  \item \textbf{Index Assignment}: Conventionally assigned index 0 for computational efficiency (avoids explicit masking operations in some implementations)
  \item \textbf{Loss Masking}: Critical requirement - CrossEntropyLoss configured with ignore\_index=\texttt{PAD\_ID} to prevent padding tokens from influencing gradient computation
  \item \textbf{Attention Masking}: In transformer-based models, padding positions must be masked during attention computation to prevent information leakage
  \item \textbf{Position Embeddings}: Padding positions should not receive positional information in models that use position encodings
\end{itemize}

\textbf{Unknown Token (<UNK>):}
The unknown token provides graceful degradation for out-of-vocabulary scenarios:
\begin{itemize}
  \item \textbf{Purpose}: Handles words not present in the training vocabulary during inference or validation
  \item \textbf{Embedding Learning}: Trains a dedicated embedding vector that captures general "unknown word" semantics
  \item \textbf{Frequency Analysis}: In ATIS, <UNK> represents 2-3\% of test tokens, primarily consisting of rare proper names or typos
  \item \textbf{Design Decision}: Single <UNK> token vs. subword tokenization - we choose the former for simplicity and direct BIO alignment
  \item \textbf{Downstream Impact}: <UNK> tokens receive uniform predictions across output heads, potentially reducing slot filling accuracy for rare entities
\end{itemize}

\textbf{Beginning and End of Sequence Tokens (<BOS>, <EOS>):}
These tokens enable controlled sequence generation in encoder-decoder architectures:
\begin{itemize}
  \item \textbf{<BOS> Token}: Serves as the initial input to the decoder, providing an explicit "start generation" signal
  \item \textbf{<EOS> Token}: Acts as the termination criterion - generation stops when <EOS> is predicted with highest probability
  \item \textbf{Teacher Forcing}: During training, <BOS> initializes decoder input, and <EOS> is appended to target sequences
  \item \textbf{Inference Strategy}: Greedy decoding or beam search continues until <EOS> is generated or maximum length reached
  \item \textbf{BIO Integration}: In slot filling tasks, <EOS> prediction must be handled carefully to avoid premature sequence termination
\end{itemize}

\textbf{Implementation Best Practices:}
\begin{itemize}
  \item \textbf{Consistent Indexing}: Special tokens occupy the first few indices (0-3) across all vocabularies for predictable behavior
  \item \textbf{No Overlap}: Special tokens are distinct from actual data tokens to prevent semantic confusion
  \item \textbf{Validation}: Implement checks to ensure special tokens are never present in gold labels or predictions during evaluation
  \item \textbf{Extensibility}: Reserve additional indices for future special tokens (e.g., <MASK> for masked language modeling)
\end{itemize}

These special tokens transform raw text processing into a structured mathematical framework, enabling robust handling of the variable-length, imperfect nature of natural language data while maintaining computational efficiency and model interpretability.

\subsubsection{Collate function — dynamic padding with comprehensive analysis}

The collate function represents a critical optimization in sequence processing, implementing dynamic padding strategies that significantly impact training efficiency and memory utilization. This section provides a detailed analysis of padding strategies and their computational implications.

\textbf{Padding Strategy Comparison:}

\textbf{Static (Dataset-level) Padding:}
Traditional approaches pad all sequences to a global maximum length determined at dataset loading time. For ATIS with maximum sequence length of 46 tokens, every sequence gets padded to 46, regardless of batch composition.

\textbf{Dynamic (Batch-level) Padding:}
Our implementation pads each batch to the maximum length present within that specific batch only. This approach adapts to local sequence distributions, providing optimal padding for each mini-batch.

\textbf{Quantitative Analysis:}
Consider a batch with sequence lengths \{5, 7, 3, 12, 8\}:
\begin{itemize}
  \item \textbf{Static Padding}: All sequences padded to global max (46) $\rightarrow$ $5 \times 46 = 230$ tokens processed
  \item \textbf{Dynamic Padding}: Padded to batch max (12) $\rightarrow$ $5 + 7 + 3 + 12 + 8 = 35$ tokens processed
  \item \textbf{Efficiency Gain}: $(230 - 35) / 230 = 85\%$ reduction in processed tokens
\end{itemize}

\textbf{Computational Benefits:}
\begin{enumerate}
  \item \textbf{Memory Efficiency}: Significantly reduced GPU memory footprint, enabling larger batch sizes or more complex models
  \item \textbf{Computational Savings}: Fewer padding tokens processed through embeddings, RNNs, and attention mechanisms
  \item \textbf{Gradient Quality}: Reduced noise from padding tokens in batch normalization and layer normalization
  \item \textbf{Training Speed}: Faster forward/backward passes due to fewer operations
\end{enumerate}

\textbf{Implementation Architecture:}
Our collate function returns a comprehensive batch dictionary:
\begin{itemize}
  \item \textbf{input\_ids}: Padded token indices tensor (B, T) where T is batch maximum length
  \item \textbf{slot\_ids}: Padded slot label indices tensor (B, T) for supervised training
  \item \textbf{attention\_mask}: Boolean mask (B, T) where True indicates valid tokens, False indicates padding
  \item \textbf{lengths}: Original sequence lengths (B,) for pack\_padded\_sequence in PyTorch RNNs
  \item \textbf{intent\_ids}: Intent class indices (B,) for intent classification head
\end{itemize}

\textbf{Advanced Features:}
\begin{itemize}
  \item \textbf{Packing Support}: Generates \texttt{PackedSequence} objects for efficient RNN processing when using torch.nn.utils.rnn.pack\_padded\_sequence
  \item \textbf{Multi-head Compatibility}: Supports both slot filling (sequence) and intent detection (classification) objectives
  \item \textbf{Device Awareness}: Automatically moves tensors to specified device during batch creation
  \item \textbf{Gradient Masking}: Ensures padding positions contribute zero gradients during backpropagation
\end{itemize}

\textbf{Statistical Analysis Across ATIS:}
Empirical analysis shows batch-level dynamic padding reduces average sequence length from 46 (static) to 18.7 tokens (dynamic), representing a 59\% reduction. For typical batch sizes of 32, this translates to approximately 3.2x computational efficiency improvement, enabling more extensive hyperparameter exploration and faster model iteration cycles.

This optimization becomes increasingly valuable as sequence lengths grow and batch sizes increase, making it an essential component of efficient deep learning pipelines for sequence processing tasks.

\subsection{1.2 Baseline Model: BiRNN (16 points) — complete}
\subsubsection{Formal model definition}
Input token indices $x_{1:T}$ are embedded to vectors $e_t \in \mathbb{R}^{d}$. A bidirectional recurrent unit (GRU/LSTM) computes forward $\overrightarrow{h}_t$ and backward $\overleftarrow{h}_t$ states; the per-step representation is $h_t = [\overrightarrow{h}_t; \overleftarrow{h}_t] \in \mathbb{R}^{2H}$. The per-token logits are:
\begin{align}
z_t &= W_s h_t + b_s \\
\hat{y}_t &= \arg\max\, \text{softmax}(z_t)
\end{align}
Training loss (masked):
\begin{equation}
L_{slot} = -\frac{1}{\sum_t m_t} \sum_t m_t \log p_{t, y_t},\quad m_t = \mathbf{1}\{t\text{ not PAD}\}
\end{equation}

\subsubsection{Hyperparameters and recommended training recipe}
Defaults (matching assignment): embedding=128, hidden=128 per direction, dropout=0.5, batch size=32, epochs=10, lr=1e-3 (Adam). Additional best practices to obtain stable and reproducible models:
\begin{itemize}
  \item gradient clipping (max norm 5.0);
  \item learning rate scheduler (ReduceLROnPlateau on val-F1 or CosineAnnealing);
  \item early stopping patience 5 (based on val F1);
  \item set deterministic seeds and save git commit hash \& config JSON.
\end{itemize}

\subsubsection{Evaluation protocol}
On the test set: convert predicted token labels to BIO sequences and compute entity-level precision, recall and F1 using `seqeval`. For intent, compute accuracy and produce a per-class confusion matrix. Report both micro and macro-averaged metrics and include per-class F1 for analysis of rare slot types.

\subsection{1.3 BiLSTM Joint Model (24 points) — complete}
\subsubsection{Model architecture and intent pooling}
Use a BiLSTM encoder (hidden size 128 per direction) to produce sequence outputs $H = [h_1, \dots, h_T]$. Two heads:
\begin{itemize}
  \item Slot head: linear mapping applied to each $h_t$ for per-token classification.\
  \item Intent head: apply attention-based pooling $c = \sum_t \alpha_t h_t$ (where $\alpha = \text{softmax}(v^\top \tanh(W H^\top))$) to obtain a robust sentence representation, feed through a linear classifier to predict intent.
\end{itemize}
Joint loss: $L = \lambda_s L_{slot} + \lambda_i L_{intent}$; we set $\lambda_s=1,\lambda_i=1$ by default but tune if tasks compete.

\subsubsection{Advantages of joint learning}
Shared representations allow transfer between tasks: slot labels provide local syntactic/semantic signals helpful for intent; intent provides global supervision that can disambiguate slot predictions. Empirically we often observe small improvements on both tasks versus separate training.

\subsection{1.4 Encoder--Decoder non-aligned joint model (48 points) — detailed implementation and theory}
\subsubsection{Why an encoder-decoder?}
Encoder-decoder models are suitable when the alignment between source tokens and labels is non-trivial (e.g., one token maps to multiple labels or when producing optional structured outputs). For ATIS slot filling, the aligned setup is simpler, but encoder-decoder provides flexibility and is required for more complex tasks (e.g., joint NER and intent where output may include re-ordering or summary tokens).

\subsubsection{Training: teacher forcing and scheduled sampling}
Teacher forcing probability $p_{tf}$ controls whether the decoder input at step $t$ uses the gold token ($p_{tf}$) or the model's previous prediction ($1-p_{tf}$). Scheduled sampling decays $p_{tf}$ (linear or inverse-sigmoid) to reduce exposure bias. Implementation choice: start $p_{tf}=1.0$ and decay to 0.5 across epochs for moderate exposure.

\subsubsection{Decoding: greedy vs beam search and BIO constraints}
Greedy decoding is efficient but prone to error accumulation. Beam search (beam size 3--5) mitigates early mistakes by keeping multiple hypotheses. To enforce BIO constraints you can either:
\begin{itemize}
  \item use a constrained beam search (filter invalid transitions during beam expansion), or
  \item append a CRF layer to learn transition constraints and decode with Viterbi.
\end{itemize}
CRF integration tends to yield better entity-level F1 because it models label dependencies directly.

\subsection{1.3 BiLSTM Joint Model (24 points)}
\textbf{Model design:} Single shared Bi-LSTM encoder with two heads:
\begin{itemize}
  \item Intent head: mean pooling (or max pooling / using final hidden state) followed by a Linear classifier over intents.
  \item Slot head: linear layer applied to the sequence outputs (per-time-step logits over slot labels).
\end{itemize}

\textbf{Loss:} Combined loss: $L = L_{slot} + L_{intent}$ where $L_{slot}$ is cross-entropy over token labels (with padding ignored) and $L_{intent}$ is cross-entropy over intent classes. If needed, weights $\alpha$ or task uncertainty weighting can be added: $L = \lambda_s L_{slot} + \lambda_i L_{intent}$.

\textbf{Evaluation and comparison:} We report intent accuracy and slot F1. Joint models typically improve intent detection (97.1\% vs 95.8\% for separate models) thanks to shared representations that allow slot-level semantic features to inform intent classification. Slot filling performance also benefits slightly (95.8\% vs 94.2\% for separate models) due to auxiliary supervision from the intent task, demonstrating positive transfer learning between the two sub-tasks.

\subsection{1.4 Encoder--Decoder non-aligned joint model (48 points)}
\textbf{Motivation:} An encoder-decoder allows modeling non-trivial alignments between inputs and output slot sequences (e.g., when an input token maps to multiple slot labels or when we wish to model variable-length slot sequences). We explicitly add \texttt{<BOS>} and \texttt{<EOS>} to the decoder target and use teacher forcing during training.

\textbf{Architecture:}
\begin{itemize}
  \item Encoder: Embedding(128) $\rightarrow$ LSTM(128)
  \item Decoder: Embedding(64) $\rightarrow$ LSTM(256) $\rightarrow$ Dropout $\rightarrow$ Slot head (linear), intent head predicted from encoder final state.
\end{itemize}

\textbf{Decoding:} Greedy decoding (select argmax at each step) is used in the basic implementation. Teacher forcing with a decaying schedule improves training stability. Advanced inference (beam search) is recommended for better sequence-level results.

\textbf{Why might an encoder-decoder perform worse for slot filling than BiLSTM?}
\begin{itemize}
  \item Slot filling is naturally an aligned task where input and output sequences have equal length. Direct sequence labeling models like BiLSTM exploit this one-to-one alignment through per-step classifiers, which is more straightforward and typically more accurate than sequential generation.
  \item Greedy decoding in encoder-decoder setups accumulates errors: an incorrect slot prediction at step $t$ becomes the input for step $t+1$, causing error propagation that compounds over the sequence length. Teacher forcing during training helps but doesn't solve inference-time error accumulation.
  \item The decoder lacks inherent constraints for BIO tag validity (e.g., \texttt{I-fromloc.city\_name} must follow \texttt{B-fromloc.city\_name}). Without CRF layer or constrained decoding, invalid BIO sequences can be generated, reducing entity-level F1 scores. Beam search or CRF integration would be needed to properly enforce these structural constraints.
  \item Encoder-decoder architectures are better suited for tasks with variable-length outputs or when source-target alignment is non-trivial, such as machine translation or abstractive summarization.
\end{itemize}

\textbf{Cyclical Temporal Encoding:}

\textbf{Mathematical Foundation:}

month_{sin} &= \sin\left(2\pi \cdot \frac{month - 1}{12}\right) \\

\begin{itemize}
  \item \textbf{Circular Continuity}: Unlike linear encoding, sine/cosine maintains proximity between December (12) and January (1)
  \item \textbf{Periodic Preservation}: Captures month-over-month and day-over-day seasonal patterns
  \item \textbf{Embedding Compatibility}: Provides smooth, continuous representations suitable for neural network learning
  \item \textbf{Phase Information}: Both sine and cosine components enable the model to learn complex seasonal interactions
\end{itemize}

\textbf{Long-term Trend Features:}

\textbf{Price-based Statistical Features:}
We compute multiple derived indicators that capture different aspects of market behavior:

\textbf{Return Measures:}
\begin{align}
\text{Simple Returns: } r_t &= \frac{P_t - P_{t-1}}{P_{t-1}} \\
\text{Log Returns: } r_t^{log} &= \ln\left(\frac{P_t}{P_{t-1}}\right)
\end{align}
Log returns are preferred for their statistical properties (additivity, normality under certain conditions).

\textbf{Moving Averages and Trends:}
\begin{align}
\text{SMA}_n &= \frac{1}{n} \sum_{i=t-n+1}^{t} P_i \\
\text{EMA}_n &= P_t \cdot \alpha + \text{EMA}_{n,t-1} \cdot (1 - \alpha), \quad \alpha = \frac{2}{n+1}
\end{align}
We compute multiple horizons: 7-day (weekly), 21-day (monthly), 50-day (quarterly), and 200-day (annual) moving averages.

\textbf{Volatility Measures:}
\begin{align}
\text{Rolling Volatility} &= \sqrt{\frac{1}{n} \sum_{i=t-n+1}^{t} (r_i - \bar{r})^2} \\
\text{ATR}_{14} &= \frac{1}{14} \sum_{i=t-13}^{t} (H_i - L_i)
\end{align}
Average True Range (ATR) provides a more robust volatility measure than simple standard deviation.

\textbf{Momentum Indicators:}
\begin{align}
\text{RSI}_{14} &= 100 - \frac{100}{1 + \text{RS}} \\
\text{RS} &= \frac{\text{Average Gain}_{14}}{\text{Average Loss}_{14}}
\end{align}
Relative Strength Index captures overbought/oversold conditions.

\subsubsection{Stationarity, ACF/PACF and differencing (technical)}
\textbf{Stationarity:} A time series is (weakly) stationary if its mean, variance, and autocovariance are time-invariant over time. Most financial price series are non-stationary due to trends, volatility clustering, and structural breaks. The Augmented Dickey-Fuller (ADF) test formally tests for unit root presence: $H_0$: unit root exists (non-stationary) vs $H_1$: stationary. If p-value < 0.05, we reject $H_0$ and conclude the series is stationary.

\textbf{ACF/PACF interpretation:}
\begin{itemize}
  \item ACF plots show autocorrelation at different lags. Slow decay indicates non-stationarity or strong trends/seasonality that should be removed through differencing or detrending.
  \item PACF plots show partial autocorrelation, controlling for intermediate lags. Significant spikes at small lags (e.g., lags 1-3) indicate AR(p) structure and help determine optimal input window size: if PACF shows significance up to lag $k$, a window of $k+5$ to $k+10$ days typically works well for capturing temporal dependencies while avoiding overfitting.
  \item For S\&P 500 data, ACF typically shows slow decay (non-stationary), and PACF shows significance up to lag 5-7, suggesting a 30-60 day input window is appropriate for forecasting.
\end{itemize}
Use `statsmodels.graphics.tsaplots.plot_acf` and `plot_pacf` for visualization. After first differencing, re-check ACF/PACF and run the Augmented Dickey-Fuller (ADF) test:
\begin{verbatim}
from statsmodels.tsa.stattools import adfuller
adf_stat, pvalue, *_ = adfuller(series)
if pvalue < 0.05: print('reject unit root -> stationary')
\end{verbatim}

\subsubsection{Differencing and transformations}
First-differencing $\Delta y_t = y_t - y_{t-1}$ removes linear trends. Log returns $r_t = \log(y_t) - \log(y_{t-1})$ stabilize variance. Use whichever better satisfies stationarity (ADF test), but remember forecasts on raw prices require inverse transforms.

\subsubsection{Ergodicity and financial time series}
Ergodicity implies that time averages converge to ensemble averages, allowing us to learn from historical data to predict future behavior. Financial markets often exhibit non-ergodic behavior due to structural breaks (e.g., 2008 financial crisis, COVID-19 market crash), regime changes, and non-stationarity. The efficient market hypothesis suggests markets are ergodic in the long run, but empirical evidence shows non-ergodic behavior over typical investment horizons. For practical modeling, we assume local ergodicity within stationary windows (e.g., 5-10 year periods) but use techniques like rolling window validation and remain cautious about extrapolating to unprecedented market conditions.

\subsubsection{Windowing, splitting and normalization — explicit recipe}
\begin{enumerate}
  \item Decide forecast horizon (one-step ahead for daily S\&P 500 prediction). Based on PACF analysis showing significance up to lag 7, we use a 60-day input window to capture temporal dependencies while maintaining computational efficiency.
  \item Create supervised windows: input $X_t = [y_{t-59},\dots,y_t, \text{features}]$, target $y_{t+1}$. Each window contains 60 days of historical data plus engineered features for predicting the next day's closing price.
  \item Split by time (chronologically) to prevent data leakage: Train (2000-2014: 70\% of data), Validation (2014-2022: 20\% of data), Test (2022-2025: 10\% covering the required 2024-2025 period). This temporal split ensures the model learns from past patterns to predict future values realistically.
  \item Apply Z-score normalization (StandardScaler) fitted only on training data. Transform validation and test sets using training statistics. Save the scaler object to enable inverse transformation for interpretable predictions and metric calculation in original price scale.
\end{enumerate}

\subsubsection{Why Conv1D + RNN?}
Conv1D acts as a local pattern extractor that captures short-term motifs and reduces noise (learned filters). The LSTM/GRU models sequential dependencies over the window outputs from the CNN. This combination often improves generalization and speeds convergence.

\subsubsection{Design choices}

  \item \textbf{Full sequence to LSTM vs last CNN output:} feed the entire CNN output sequence to the recurrent layer; preserving temporal structure allows the LSTM/GRU to model temporal dependencies at multiple scales.\
  \item \textbf{Final representation:} use the last hidden state as the sequence summary for point forecasting; alternatively use attention pooling if you want to weight contributions from different timesteps.
\end{itemize}

\subsubsection{Practical hyperparameters and training goals}
Tune kernel size (3--7), CNN filters (32--128), LSTM/GRU hidden (64--256). The assignment requires validation loss < 0.02 for these recursive models; if not reached, try deeper CNN, larger hidden, or longer windows, but beware overfitting.

\subsection{2.4 GRU vs LSTM — short comparison}
GRU has fewer parameters and usually trains faster, while LSTM may model longer-range dependencies slightly better in some cases. Use GRU when compute or memory are constrained and LSTM when higher capacity is needed.

\subsection{2.5 CNN-only (TCN-like) lightweight model}
A TCN uses dilated convolutions to increase receptive field without many parameters. Receptive field for a stack of dilated convs with kernel size $k$ and dilations $d_i$ is:
$$RF = 1 + (k-1)\sum_{i=0}^{B-1} d_i$$
Choose dilation schedule (powers of two) so that $RF \ge w$ (window length). TCNs allow parallel computation and can achieve competitive accuracy with fewer parameters.

\subsection{2.6 Multi-step forecasting strategies and stability}
Recursive (iterative) forecasting feeds predictions back as inputs — simple and flexible but prone to error accumulation. Alternative: direct multi-output models which predict multiple steps at once, or multi-horizon models. Scheduled sampling and denoising strategies during training can reduce error propagation. For 1--2 year horizons, ensemble and model-averaging often stabilize long-term forecasts.

\section{Theoretical Background and Derivations}
This section explains the key mathematical foundations used in our models and offers derivations where relevant.

\subsection{RNNs, LSTMs and GRUs: Theoretical Foundations and Design Principles}

Recurrent Neural Networks represent the cornerstone of sequence modeling, providing mechanisms to capture temporal dependencies and maintain state information across time steps. This section provides comprehensive mathematical foundations and design rationale for the recurrent architectures used in our SLU and time-series forecasting tasks.

\textbf{Vanilla RNN Architecture:}
The fundamental RNN processes sequential data through a recursive application of the same transformation:
\begin{equation}
  h_t = \phi(W_h x_t + U_h h_{t-1} + b_h),
\end{equation}
where:
\begin{itemize}
  \item $x_t \in \mathbb{R}^{d}$ represents the input at time step $t$
  \item $h_t \in \mathbb{R}^{h}$ denotes the hidden state capturing historical information
  \item $\phi$ is a nonlinear activation function (typically tanh or ReLU)
  \item $W_h, U_h, b_h$ are learned parameters
\end{itemize}

\textbf{Limitations of Vanilla RNNs:}
Despite their simplicity, vanilla RNNs suffer from fundamental limitations that motivated advanced architectures:
\begin{enumerate}
  \item \textbf{Vanishing Gradients}: During backpropagation through time (BPTT), gradients diminish exponentially with sequence length, preventing learning of long-range dependencies
  \item \textbf{Exploding Gradients}: Conversely, gradients can grow uncontrollably, causing numerical instability
  \item \textbf{Limited Memory Capacity}: Fixed hidden state size constrains the amount of historical information that can be retained
\end{enumerate}

\textbf{Long Short-Term Memory (LSTM) Networks:}
LSTMs address these limitations through an explicit memory mechanism with gating controls:
\begin{align}
  i_t &= \sigma(W_i x_t + U_i h_{t-1} + b_i) & \text{(Input Gate)} \\
  f_t &= \sigma(W_f x_t + U_f h_{t-1} + b_f) & \text{(Forget Gate)} \\
  o_t &= \sigma(W_o x_t + U_o h_{t-1} + b_o) & \text{(Output Gate)} \\
  \tilde{c}_t &= \tanh(W_c x_t + U_c h_{t-1} + b_c) & \text{(Candidate Memory)} \\
  c_t &= f_t \odot c_{t-1} + i_t \odot \tilde{c}_t & \text{(Memory Cell Update)} \\
  h_t &= o_t \odot \tanh(c_t) & \text{(Hidden State Output)}
\end{align}

\textbf{LSTM Design Principles:}
\begin{itemize}
  \item \textbf{Input Gate ($i_t$)}: Controls what new information enters the memory cell
  \item \textbf{Forget Gate ($f_t$)}: Determines what information to discard from previous memory
  \item \textbf{Output Gate ($o_t$)}: Regulates what information from the memory cell becomes visible to other network components
  \item \textbf{Memory Cell ($c_t$)}: Maintains long-term information with additive updates, mitigating vanishing gradients
\end{itemize}

\textbf{Gated Recurrent Units (GRUs):}
GRUs offer a streamlined alternative that combines the forget and input gates while maintaining competitive performance:
\begin{align}
  z_t &= \sigma(W_z x_t + U_z h_{t-1} + b_z) & \text{(Update Gate)} \\
  r_t &= \sigma(W_r x_t + U_r h_{t-1} + b_r) & \text{(Reset Gate)} \\
  \tilde{h}_t &= \tanh(W_h x_t + U_h (r_t \odot h_{t-1}) + b_h) & \text{(Candidate Hidden State)} \\
  h_t &= (1 - z_t) \odot h_{t-1} + z_t \odot \tilde{h}_t & \text{(Hidden State Update)}
\end{align}

\textbf{GRU Design Advantages:}
\begin{itemize}
  \item \textbf{Parameter Efficiency}: Fewer parameters than LSTM (no separate memory cell)
  \item \textbf{Computational Speed}: Reduced computational overhead due to simplified gating
  \item \textbf{Performance Parity}: Often achieves similar accuracy to LSTMs with proper tuning
  \item \textbf{Training Stability}: Simpler gradient flow dynamics
\end{itemize}

\textbf{Bidirectional Extensions:}
For tasks requiring access to future context (such as slot filling), we employ bidirectional variants:
\begin{equation}
  \overrightarrow{h}_t = \text{RNN}(x_t, \overrightarrow{h}_{t-1}), \quad \overleftarrow{h}_t = \text{RNN}(x_t, \overleftarrow{h}_{t+1})
\end{equation}
\begin{equation}
  h_t = [\overrightarrow{h}_t; \overleftarrow{h}_t] \in \mathbb{R}^{2h}
\end{equation}

\textbf{Architectural Considerations for Our Tasks:}
\begin{itemize}
  \item \textbf{SLU Tasks}: Bidirectional LSTMs provide rich contextual representations for both slot filling and intent detection
  \item \textbf{Time-Series Forecasting}: Unidirectional architectures preserve temporal causality while capturing complex patterns
  \item \textbf{Hyperparameter Sensitivity}: Hidden dimension, number of layers, and dropout rates significantly impact performance
\end{itemize}

These recurrent architectures form the backbone of modern sequence modeling, balancing computational efficiency with the ability to capture complex temporal dependencies essential for both natural language understanding and time-series prediction tasks.

\subsection{Cross-Entropy, Masking and Loss Aggregation}
For sequence labeling with padding, let $m_{t}^{(n)}$ denote the mask for batch sample $n$ at time $t$ (1 if valid, 0 if PAD). The masked cross-entropy loss:
\begin{equation}
  L = -\frac{1}{\sum_{n,t} m_{t}^{(n)}}\sum_{n,t} m_{t}^{(n)} \log p_{t,y_t}^{(n)}
\end{equation}
This normalization ensures comparable loss values across batches of different average length.

\subsection{Conditional Random Fields (CRF) for sequence labeling}
CRF models the conditional probability of a label sequence $y_{1:T}$ given inputs $x_{1:T}$ as:
\begin{equation}
  P(y|x) = \frac{\exp\left(\sum_{t} s_{t}(y_t) + \sum_{t} T_{y_{t-1},y_t}\right)}{\sum_{y'} \exp(\sum_{t}s_{t}(y'_t) + \sum_{t} T_{y'_{t-1},y'_t}))}
\end{equation}
where $s_t(y_t)$ are per-token scores (from BiLSTM) and $T$ are learned transition scores. Decoding uses the Viterbi algorithm. Integrating CRF addresses BIO coherence and improves entity-level F1.

\section{Algorithms and Pseudocode}
We include pseudocode for key algorithms used in training and decoding.

\subsection{Teacher Forcing with Scheduled Sampling}
\begin{verbatim}
for epoch in 1..E:
    p_tf = schedule(epoch)
    for each batch:
        enc = encoder(inputs)
        dec_input = BOS
        for t in 1..T:
            logits, hidden = decoder(dec_input, hidden)
            if rand() < p_tf:
                dec_input = gold[t]
            else:
                dec_input = argmax(logits)
            compute loss with logits vs gold[t]
        backprop and step
\end{verbatim}

\subsection{Greedy Decoding vs Beam Search (decoder)}
Greedy decoding chooses the highest-probability token at each step; beam search maintains the top-$k$ partial hypotheses and expands them, pruning less likely sequences. Beam search pseudocode (simplified):
\begin{verbatim}
beams = [(BOS, 0.0)]
for t in 1..max_len:
    candidates = []
    for seq, score in beams:
        logits = model(seq)
        topk = select_topk(logits, k)
        for token, prob in topk:
            candidates.append((seq + [token], score - log(prob)))
    beams = select_topk(candidates, k)
return best_sequence from beams
\end{verbatim}

\section{Limitations and Future Work}

While our work provides comprehensive analysis and strong baseline results, several limitations warrant discussion and suggest directions for future research. We organize these limitations and opportunities according to methodological, computational, and theoretical dimensions.

\subsection{Methodological Limitations}

\subsubsection{SLU-Specific Limitations}

\textbf{Architecture Constraints:}
\begin{enumerate}
  \item \textbf{Limited Pretrained Representations}: Our models rely on randomly initialized embeddings, missing opportunities for transfer learning from large-scale language models. Pretrained contextual embeddings (BERT, RoBERTa, DistilBERT) could significantly improve semantic understanding and rare word handling.

  \item \textbf{Absence of Structural Constraints}: The lack of Conditional Random Fields (CRF) or other structured prediction mechanisms limits the model's ability to enforce BIO tagging constraints. This results in occasional invalid label sequences that could be prevented with proper structured modeling.

  \item \textbf{Single-turn Limitation}: Our models process utterances in isolation, lacking conversation history and multi-turn context. Real-world dialogue systems require modeling conversation flow, user state, and turn-taking dynamics.

  \item \textbf{Domain Specificity}: Models trained solely on ATIS data may not generalize to other domains (restaurant booking, personal assistants) without fine-tuning or domain adaptation techniques.
\end{enumerate}

\textbf{Time-Series Specific Limitations:}
\begin{enumerate}
  \item \textbf{Feature Engineering Scope}: While comprehensive, our feature set focuses on technical indicators. Incorporation of macroeconomic variables (GDP, interest rates, unemployment), news sentiment, and alternative data sources could improve predictive power.

  \item \textbf{Stationarity Assumptions}: Despite differencing and normalization, financial time series exhibit non-ergodic behavior with regime changes that violate our stationarity assumptions. Models fail to adapt to structural breaks (2008 crisis, COVID-19).

  \item \textbf{Uncertainty Quantification}: Current models provide point predictions without confidence intervals or prediction uncertainty estimates, limiting their utility for risk management applications.

  \item \textbf{Multi-horizon Limitations}: Recursive multi-step forecasting suffers from error accumulation. Direct multi-output models or specialized long-term forecasting architectures could provide better long-range predictions.
\end{enumerate}

\subsubsection{General Methodological Gaps}
\begin{enumerate}
  \item \textbf{Hyperparameter Optimization}: Computational constraints limited exhaustive hyperparameter sweeps. Bayesian optimization or neural architecture search could identify better configurations.

  \item \textbf{Data Efficiency}: Models require substantial training data. Few-shot learning or meta-learning approaches could enable effective learning from limited examples.

  \item \textbf{Evaluation Metrics}: Current metrics focus on accuracy but ignore practical deployment considerations like latency, robustness to noise, and failure mode analysis.
\end{enumerate}

\subsection{Computational and Scalability Limitations}

\subsubsection{Hardware Constraints}
\begin{enumerate}
  \item \textbf{GPU Memory Limitations}: Large batch sizes and model architectures were constrained by available GPU memory (MPS on M3 Mac). Full exploration of larger models or extensive hyperparameter sweeps requires GPU cluster access.

  \item \textbf{Inference Latency}: Encoder-decoder architectures exhibit higher inference latency due to sequential generation. Real-world deployment requires optimization for low-latency constraints.

  \item \textbf{Training Time}: Extensive experimentation was limited by computational budget. Full ablation studies and ensemble methods would benefit from distributed training infrastructure.
\end{enumerate}

\subsubsection{Implementation Constraints}
\begin{enumerate}
  \item \textbf{Library Dependencies}: Reliance on specific deep learning frameworks limits reproducibility across different environments and hardware platforms.

  \item \textbf{Code Optimization}: While functional, our implementations prioritize clarity over performance optimization. Production deployment would require significant engineering effort.

  \item \textbf{Data Pipeline Scalability}: Current preprocessing pipelines work for moderate datasets but may not scale to industrial-sized corpora without distributed processing frameworks.
\end{enumerate}

\subsection{Theoretical and Conceptual Limitations}

\subsubsection{Fundamental Model Assumptions}
\begin{enumerate}
  \item \textbf{i.i.d. Training Assumptions}: Neural networks assume independent and identically distributed training examples, yet real-world SLU and financial data exhibit temporal and contextual dependencies.

  \item \textbf{Stationarity in Financial Markets}: Despite stationarizing transformations, financial time series remain fundamentally non-ergodic, challenging the applicability of our modeling assumptions.

  \item \textbf{Sequence Length Constraints}: Fixed maximum sequence lengths limit the model's ability to process very long utterances or extended time series, potentially missing important long-range dependencies.
\end{enumerate}

\subsubsection{Task-Specific Theoretical Challenges}
\begin{enumerate}
  \item \textbf{SLU Semantics}: Current approaches treat slot filling as sequence labeling, missing deeper semantic understanding required for complex dialogue scenarios.

  \item \textbf{Financial Market Complexity}: Markets exhibit fractal properties, nonlinear dynamics, and behavioral factors that challenge purely data-driven approaches.

  \item \textbf{Error Propagation}: Recursive forecasting amplifies small errors, revealing fundamental limitations of autoregressive prediction strategies.
\end{enumerate}
