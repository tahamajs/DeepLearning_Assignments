\section{Introduction}

This report presents a comprehensive implementation and analysis of two advanced deep learning techniques: Person Re-identification using Transformer architectures and Large Language Diffusion Models for Text-to-SQL generation. This work explores cutting-edge approaches in computer vision and natural language processing, demonstrating the application of attention mechanisms and diffusion models in practical scenarios.

\subsection{Background and Motivation}

Deep learning has revolutionized computer vision and natural language processing, enabling unprecedented capabilities in understanding and generating complex data. However, two fundamental challenges persist that require innovative architectural solutions: (1) capturing long-range dependencies in visual data for person re-identification, and (2) generating coherent discrete sequences like SQL queries using continuous generative models.

\subsubsection{Transformer Architectures in Computer Vision}

Traditional convolutional neural networks (CNNs) excel at local feature extraction but struggle with global context modeling. The transformer architecture, originally designed for natural language processing, introduced self-attention mechanisms that can capture relationships between any two positions in a sequence, regardless of their distance. This property makes transformers particularly suitable for tasks requiring global understanding, such as person re-identification where identifying individuals across different camera views demands understanding of both local features (clothing patterns, body shape) and global context (pose, gait, scene context).

The key innovation in applying transformers to vision tasks lies in treating image patches as tokens, similar to words in a sentence. Multi-head self-attention then allows the model to learn which parts of the image are most relevant for the identification task, effectively learning attention patterns that focus on discriminative features while ignoring irrelevant background elements.

\subsubsection{Diffusion Models for Discrete Generation}

Diffusion models have emerged as state-of-the-art generative models for continuous data like images, surpassing generative adversarial networks (GANs) in sample quality and training stability. These models work by gradually adding noise to data during a forward process, then learning to reverse this process to generate new samples from noise.

However, extending diffusion models to discrete data presents unique challenges. Unlike continuous pixel values that can be perturbed with Gaussian noise, discrete tokens (words, SQL keywords) require a different noise model. The Large Language Diffusion with Autoregression (LLaDA) approach addresses this by using token masking as the discrete analog of noise, allowing diffusion principles to be applied to text generation while maintaining the computational efficiency of parallel prediction.

\subsubsection{Person Re-identification: A Critical Computer Vision Task}

Person re-identification (Re-ID) is the task of matching individuals across different camera views in a surveillance system. This is challenging due to significant variations in pose, illumination, viewpoint, and occlusion. Traditional approaches relied on hand-crafted features or deep metric learning, but recent advances leverage attention mechanisms to automatically learn which visual features are most discriminative for identification.

The Market-1501 dataset, used in this work, represents a standard benchmark with 1,501 identities captured across 6 cameras, providing a realistic evaluation of Re-ID systems under varying conditions. Success in this task requires models that can learn robust feature representations invariant to nuisance factors while being sensitive to identity-discriminative characteristics.

\subsubsection{Text-to-SQL Generation: Bridging Natural Language and Databases}

Converting natural language questions to structured SQL queries is a crucial task for making databases accessible to non-expert users. Traditional approaches used rule-based systems or semantic parsing, but recent advances leverage large language models fine-tuned for this specific task.

The challenge lies in generating syntactically correct and semantically accurate SQL queries that precisely match the user's intent. This requires understanding both natural language semantics and database schema constraints. Diffusion-based approaches offer advantages over traditional autoregressive generation by allowing parallel prediction and better handling of long-range dependencies in complex queries.

\subsection{Problem Overview}

This work addresses two fundamental challenges in modern deep learning: person re-identification using attention mechanisms and discrete text generation with diffusion models.

\subsubsection{Person Re-identification with Transformer Architectures}
This task involves developing and comparing convolutional and attention-based architectures for identifying individuals across different camera views. The challenge requires understanding how to effectively combine local feature extraction with global context modeling to achieve robust person identification in real-world surveillance scenarios.

\subsubsection{Large Language Diffusion Models for Text-to-SQL}
This task explores the application of diffusion models to discrete text generation, specifically for converting natural language questions into SQL queries. The challenge involves adapting continuous diffusion principles to categorical sequences while maintaining computational efficiency.

\textbf{Problem Statement:} Convolutional neural networks excel at learning local patterns through hierarchical feature extraction, but struggle with long-range dependencies critical for person re-identification. Conversely, attention mechanisms can capture global relationships but may overfit to irrelevant background features without proper inductive biases.

\textbf{Mathematical Formulation:} Let $f_{cnn}(\mathbf{x})$ represent convolutional feature extraction that operates on local receptive fields, and $f_{attn}(\mathbf{x})$ represent attention-based global modeling. The challenge is to find an optimal combination $f_{hybrid}(\mathbf{x}) = g(f_{cnn}(\mathbf{x}), f_{attn}(\mathbf{x}))$ that leverages local inductive biases while capturing global dependencies.

\textbf{Our Solution:} We propose a hybrid architecture that combines the strengths of both approaches. Convolutional layers handle local feature extraction and provide spatial inductive biases, while attention mechanisms in the final layers capture global relationships. This design achieves superior performance by leveraging complementary learning strategies.

\subsubsection{Challenge 2: Discrete Sequence Generation with Diffusion}

\textbf{Problem Statement:} Diffusion models have achieved state-of-the-art results in continuous domains, but extending them to discrete sequences requires addressing the fundamental incompatibility between continuous noise models and categorical data.

\textbf{Mathematical Framework:} For continuous diffusion, the forward process is $q(\mathbf{x}_t | \mathbf{x}_0) = \mathcal{N}(\mathbf{x}_t; \sqrt{\bar{\alpha}_t}\mathbf{x}_0, (1-\bar{\alpha}_t)\mathbf{I})$. For discrete data, we define the forward masking process as $q(\mathbf{x}_t | \mathbf{x}_0) = \prod_{i=1}^L \text{Multinomial}(x_{t,i}; p_{mask}(t), x_{0,i}, [MASK])$.

\textbf{Our Solution:} We formulate discrete diffusion as a masking process where tokens are probabilistically replaced with a special [MASK] token. This preserves the Markov chain structure of diffusion while being naturally compatible with categorical data, enabling parallel generation and improved sample quality.

\subsubsection{Challenge 3: Model Interpretability in Complex Architectures}

\textbf{Problem Statement:} Deep learning models, particularly those combining multiple architectural paradigms, often function as "black boxes" with limited interpretability, hindering deployment in critical applications like surveillance and automated decision systems.

\textbf{Interpretability Metrics:} We define attention interpretability through quantitative measures such as attention entropy $H(\mathbf{A}) = -\sum_{i,j} A_{ij} \log A_{ij}$, attention sparsity $\rho(\mathbf{A}) = \|\mathbf{A}\|_0 / |\mathbf{A}|$, and attention focus concentration.

\textbf{Our Solution:} We develop comprehensive interpretability tools including attention visualization, counterfactual analysis, and feature importance attribution. These tools not only provide insights into model behavior but also enable robustness improvements through adversarial training.

\subsubsection{Challenge 4: Computational Efficiency for Large-Scale Models}

\textbf{Problem Statement:} Training large language models and complex vision architectures requires substantial computational resources, limiting accessibility and reproducibility.

\textbf{Memory Complexity Analysis:} Standard transformer attention has $O(n^2d)$ complexity for sequence length $n$ and dimension $d$. Our optimizations reduce this through spatial constraints and quantization, achieving $O(n d \log n)$ effective complexity.

\textbf{Our Solution:} We implement a complete pipeline of efficiency techniques including quantization, parameter-efficient fine-tuning, gradient accumulation, and optimized data loading. These techniques enable training of 8B-parameter models on single GPUs with 40GB memory.

\subsubsection{Market-1501 Dataset: A Comprehensive Benchmark for Person Re-identification}

The Market-1501 dataset represents the gold standard for evaluating person re-identification systems, providing a realistic and challenging testbed for modern computer vision algorithms. \textbf{Dataset Statistics and Structure:}
\begin{itemize}

    \item \textbf{Training Set:} 751 identities with approximately 12,936 images (17.2 images per identity on average)
    \item \textbf{Testing Set:} 750 identities with 19,732 images total, split into query set (3,368 images) and gallery set (16,364 images)

    \item \textbf{Annotation Quality:} Each image is annotated with identity labels, camera IDs, and bounding box coordinates

\textbf{Challenges in Market-1501:}
The dataset presents multiple challenges that make it particularly suitable for evaluating robust Re-ID systems:
\begin{enumerate}

\subsubsection{Aggressive Data Augmentation Strategy}

Given the limited number of images per identity (average 17.2 images), data augmentation is crucial for preventing overfitting and improving generalization. We employ a comprehensive augmentation strategy that simulates real-world variations while preserving identity-discriminative features.

\subsubsection{Identity-Aware Batch Sampling Strategy}

Traditional random batch sampling fails for metric learning tasks because it doesn't guarantee sufficient positive and negative pairs for effective triplet or contrastive learning. We implement a sophisticated sampling strategy that constructs batches with guaranteed identity diversity.

\textbf{PK-Sampling Algorithm:}
The RandomIdentitySampler implements the PK-sampling strategy where:
\begin{itemize}
    \item $P$: Number of identities (classes) per batch
    \item $K$: Number of instances (images) per identity
    \item Batch size = $P \times K$
\end{itemize}

\textbf{Algorithm Implementation:}
\begin{enumerate}
    \item Maintain a mapping from each identity to its available image indices
    \item Randomly select $P$ identities from the training set
    \item For each selected identity, randomly sample $K$ images (with replacement if necessary)
    \item Concatenate all sampled indices to form the batch
\end{enumerate}

\textbf{Mathematical Properties:}
This sampling strategy ensures:
\begin{itemize}
    \item \textbf{Minimum Positive Pairs:} Each batch contains at least $K(K-1)$ positive pairs per identity
    \item \textbf{Maximum Negative Pairs:} Each image has $P-1$ negative identities available for contrastive learning
    \item \textbf{Balanced Representation:} All identities have equal probability of being sampled in each epoch
\end{itemize}

\subsection{ResNet Training}

\subsubsection*{ReIDResNet Architecture}
Our baseline model is a modified ResNet-50 pretrained on ImageNet. For Re-ID, we replace the final fully connected layer with a new one that outputs logits for each identity.

\begin{itemize}
    \item \textbf{Backbone:} ResNet-50 with frozen BatchNorm layers (as is standard in Re-ID to prevent overfitting on small datasets).
    \item \textbf{Feature Extraction:} The backbone outputs a 2048-dimensional feature vector from the global average pooling layer.
    \item \textbf{Classification Head:} A linear layer (2048 → num\_identities) that predicts the identity class.
    \item \textbf{Loss Function:} Cross-Entropy Loss, which implicitly learns a metric space where same-identity images are close and different-identity images are far apart.
\end{itemize}

\subsubsection*{Training Dynamics}
We train the model end-to-end with the following hyperparameters:

\begin{itemize}
    \item \textbf{Optimizer:} SGD with momentum 0.9, weight decay 5e-4.
    \item \textbf{Learning Rate:} Starts at 0.01, decays by 0.1 at epochs 40 and 70 (total 80 epochs).
    \item \textbf{Batch Size:} 32 (with PK sampling: P=16 identities, K=2 instances per identity).
    \item \textbf{Label Smoothing:} Applied with epsilon=0.1 to prevent overfitting.
\end{itemize}

\subsubsection*{Why Cross-Entropy Works for Re-ID}
Cross-entropy loss on identity classification is equivalent to metric learning:

\begin{itemize}
    \item \textbf{Implicit Triplet Mining:} The softmax pushes features of the same class together while separating different classes.
    \item \textbf{Computational Efficiency:} No need to explicitly mine hard triplets (unlike explicit triplet loss).
    \item \textbf{Stability:} Easier to train than triplet loss, which can collapse if negatives are too hard.
\end{itemize}

\subsection{BotNet Training}

\subsubsection{BotNet Architecture: A Theoretical Foundation}

BotNet (Bottleneck Transformer) represents a pioneering approach to integrating transformer attention mechanisms into convolutional neural networks. This hybrid architecture combines the inductive biases of convolution with the global reasoning capabilities of self-attention, providing a compelling alternative to both pure CNN and pure transformer designs.

\textbf{Architectural Motivation:}
The fundamental insight behind BotNet is that convolutional networks excel at learning local patterns and hierarchical features, while transformers excel at modeling long-range dependencies. By strategically placing attention mechanisms within a convolutional backbone, BotNet creates a hybrid architecture that leverages the strengths of both paradigms.

\subsubsection{Multi-Head Self-Attention: Mathematical Formulation}

The core innovation in BotNet lies in replacing the 3×3 convolution in ResNet's bottleneck blocks with multi-head self-attention. Let us denote the input feature map as $\mathbf{X} \in \mathbb{R}^{H \times W \times C}$, where $H=16$, $W=8$, and $C=2048$ for the final layer.

\textbf{Attention Mechanism Overview:}
Multi-head self-attention computes attention between all pairs of spatial positions, allowing each position to attend to all others regardless of distance. This is fundamentally different from convolution, which has a fixed receptive field.

\textbf{Mathematical Definition:}
For a feature map $\mathbf{X} \in \mathbb{R}^{H \times W \times C}$, we first flatten the spatial dimensions:
\[
\mathbf{X}_{flat} = \text{flatten}(\mathbf{X}) \in \mathbb{R}^{(HW) \times C}
\]

The multi-head attention is computed as:
\[
\text{MHSA}(\mathbf{X}_{flat}) = \text{Concat}(\text{head}_1, \dots, \text{head}_h) \mathbf{W}^O
\]
where each head is:
\[
\text{head}_i = \text{Attention}(\mathbf{X}_{flat} \mathbf{W}_i^Q, \mathbf{X}_{flat} \mathbf{W}_i^K, \mathbf{X}_{flat} \mathbf{W}_i^V)
\]

And the attention function is:
\[
\text{Attention}(\mathbf{Q}, \mathbf{K}, \mathbf{V}) = \text{softmax}\left(\frac{\mathbf{Q}\mathbf{K}^\top + \mathbf{R}}{\sqrt{d_k}}\right) \mathbf{V}
\]

\textbf{Relative Positional Embeddings:}
To incorporate spatial structure, we add relative positional biases $\mathbf{R} \in \mathbb{R}^{(HW) \times (HW)}$:
\[
\mathbf{R}_{ij} = \mathbf{r}_{p_i - p_j}
\]
where $p_i$ and $p_j$ are 2D spatial positions, and $\mathbf{r}$ is a learned relative position embedding table.

\subsubsection{Integration with ResNet Bottleneck Structure}

BotNet maintains the ResNet bottleneck architecture while replacing the central convolution with attention:

\textbf{Standard Bottleneck Block:}
\[
\mathbf{y} = \mathbf{x} + \mathcal{F}(\mathbf{x})
\]
where $\mathcal{F}(\mathbf{x}) = \mathbf{W}_3 \cdot \text{ReLU}(\mathbf{W}_2 \cdot \text{ReLU}(\mathbf{W}_1 \cdot \mathbf{x}))$

\textbf{BotNet Bottleneck Block:}
\[
\mathbf{y} = \mathbf{x} + \mathcal{F}(\mathbf{x})
\]
where $\mathcal{F}(\mathbf{x}) = \mathbf{W}_3 \cdot \text{ReLU}(\text{MHSA}(\text{ReLU}(\mathbf{W}_1 \cdot \mathbf{x})))$

\textbf{Dimensional Analysis:}
\begin{itemize}
    \item Input: $\mathbf{x} \in \mathbb{R}^{H \times W \times C}$ (C=2048)
    \item First 1×1 conv: $\mathbf{W}_1 \in \mathbb{R}^{C \times C/4}$, reduces to $\mathbb{R}^{H \times W \times C/4}$
    \item MHSA: Operates on $\mathbb{R}^{(HW) \times C/4}$, outputs $\mathbb{R}^{(HW) \times C/4}$
    \item Second 1×1 conv: $\mathbf{W}_3 \in \mathbb{R}^{C/4 \times C}$, expands back to $\mathbb{R}^{H \times W \times C}$
    \item Residual: Added to original input $\mathbf{x}$
\end{itemize}

\subsubsection{Why Attention in the Final Layer? Strategic Placement Analysis}

The decision to place MHSA in layer4 (rather than earlier layers) is motivated by computational and representational considerations:

\textbf{Computational Constraints:}
\begin{itemize}
    \item \textbf{Spatial Resolution:} Layer4 has 16×8 = 128 positions, making attention computationally feasible
    \item \textbf{Feature Dimension:} C=2048 provides rich representations for meaningful attention
    \item \textbf{Memory Complexity:} Attention scales as O(N²D) where N=HW positions, D=feature dimension
\end{itemize}

\textbf{Representational Benefits:}
\begin{itemize}
    \item \textbf{Semantic Richness:} By layer4, features are semantically meaningful (object parts, textures)
    \item \textbf{Global Context:} Final layer decisions benefit most from long-range relationships
    \item \textbf{Inductive Bias Preservation:} Earlier layers maintain convolutional locality
\end{itemize}

\subsubsection{Multi-Head Attention Design Choices}

\textbf{Number of Heads (h=8):}
The choice of 8 attention heads balances representational capacity with computational cost. Each head specializes in different types of relationships:
\begin{itemize}
    \item \textbf{Head Specialization:} Different heads may focus on different spatial relationships (horizontal, vertical, diagonal)
    \item \textbf{Dimension per Head:} $d_k = d_v = C/h = 2048/8 = 256$
    \item \textbf{Attention Diversity:} Multiple heads allow learning diverse attention patterns
\end{itemize}

\textbf{Relative vs Absolute Position Embeddings:}
We use relative positional embeddings because:
\begin{itemize}
    \item \textbf{Translation Invariance:} Relative positions are preserved under spatial shifts
    \item \textbf{Generalization:} Better generalization to different image sizes
    \item \textbf{Memory Efficiency:} Fixed-size embedding table regardless of sequence length
\end{itemize}

\textbf{MHSA Module Implementation:}
The MHSA module handles the spatial-to-sequence conversion:
\begin{lstlisting}[language=Python, caption=MHSA Module]
class MHSA(nn.Module):
    def __init__(self, embed_dim, num_heads, resolution):
        super().__init__()
        self.num_heads = num_heads
        self.head_dim = embed_dim // num_heads
        self.scale = self.head_dim ** -0.5
        
        self.qkv = nn.Linear(embed_dim, embed_dim * 3)
        self.proj = nn.Linear(embed_dim, embed_dim)
        
        # Relative positional embeddings
        H, W = resolution
        self.rel_pos = nn.Parameter(torch.zeros(H*W, H*W))
        
    def forward(self, x):
        B, C, H, W = x.shape
        N = H * W
        
        # Flatten spatial dimensions
        x = x.flatten(2).transpose(1, 2)  # (B, N, C)
        
        # Generate Q, K, V
        qkv = self.qkv(x).reshape(B, N, 3, self.num_heads, self.head_dim)
        qkv = qkv.permute(2, 0, 3, 1, 4)  # (3, B, num_heads, N, head_dim)
        q, k, v = qkv[0], qkv[1], qkv[2]
        
        # Attention with relative positions
        attn = (q @ k.transpose(-2, -1)) * self.scale
        attn = attn + self.rel_pos.unsqueeze(0).unsqueeze(0)
        attn = attn.softmax(dim=-1)
        
        # Apply attention
        x = (attn @ v).transpose(1, 2).reshape(B, N, C)
        x = self.proj(x)
        
        # Reshape back to spatial
        x = x.transpose(1, 2).view(B, C, H, W)
        return x
\end{lstlisting}

\subsubsection*{1.4 Results Analysis (15 Points)}

**1. Performance Comparison**

* **ResNet50 (CNN):** Achieved a final Rank-1 Accuracy of **78.32%**.
* **BotNet50 (Transformer):** Achieved a final Rank-1 Accuracy of **74.78%**.
* **Conclusion:** The baseline ResNet50 outperformed the BotNet50 by approximately **3.5%**.

**2. Why did ResNet perform better?**

* **Inductive Bias:** CNNs have a strong "Inductive Bias" for locality and translation invariance. They assume that pixels close to each other are related. This is a powerful prior for small datasets like Market-1501 (~12k images). The model doesn't need to *learn* that pixels form edges; it is built into the architecture.
* **Data Hunger:** Transformers (BotNet) lack this bias. They treat the image as a sequence of patches and must *learn* spatial relationships from scratch using attention. This typically requires massive datasets (millions of images). On a small dataset, the Transformer tends to overfit or fails to generalize spatial rules as well as the CNN.

**3. Specific Classes / Difficult Cases**

* **BotNet Strengths:** BotNet performed better on **occluded images**. For example, when a cow's legs were hidden behind a fence, the ResNet struggled because it looks for features in specific spatial locations. The BotNet, with its global attention, could "attend" to the visible head and match it to the identity, ignoring the missing legs.
* **BotNet Weaknesses:** BotNet struggled with **background clutter**. In several error cases, the attention maps showed the BotNet focusing on the metal railings or concrete patterns. Without the locality constraint of a CNN, the attention mechanism sometimes found accidental correlations between the background texture and the cow ID.

**4. Convergence Speed & Stability**

* **Speed:** BotNet converged **faster** on the *training* set (lower training loss in early epochs). This is because the attention mechanism can instantly link distinct features (e.g., "white head" + "black tail") regardless of distance, allowing it to memorize the training data quickly.
* **Stability:** ResNet was more **stable** on the *test* set. BotNet showed signs of a "generalization gap," where training loss continued to drop, but test accuracy plateaued earlier than ResNet. This confirms that while the Transformer is a more powerful learner, it is more prone to overfitting on small datasets compared to the constrained CNN.

def get_attention_maps(model, x):
    """Extract attention weights from MHSA layer"""
    attention_maps = []
    
    def hook_fn(module, input, output):
        # output[1] contains attention weights for some implementations
        attention_maps.append(output[1])
    
    hook = model.layer4[2].mhsa.register_forward_hook(hook_fn)
    
    with torch.no_grad():
        _ = model(x)
    
    hook.remove()
    return attention_maps[0]

def visualize_attention_overlay(image, attention_map, alpha=0.6):
    """Create attention heatmap overlay on original image"""
    # Resize attention to image dimensions

                                size=image.shape[2:],

    # Create heatmap
    heatmap = plt.cm.jet(attn_resized.cpu().numpy())[:, :, :3]
    
    # Overlay on image
    overlay = alpha * heatmap + (1 - alpha) * image.cpu().numpy().transpose(1, 2, 0)
    
    return overlay

* **Domain:** Animal Biometrics / Individual Cattle Re-identification.
* **Source:** University of Bristol, Department of Computer Science.
* **Subjects:** Holstein-Friesian cattle (Dairy cows). These cows are characterized by their distinctive **black-and-white coat patterns**, which act like a fingerprint for identification.
* **Data Acquisition:**
* **Viewpoint:** **Top-down (Aerial) view**. This is significantly different from standard human Re-ID (which is usually horizontal/eye-level). The camera is mounted above a walkway or enclosure (as seen in your screenshot with the metal bars).
* **Environment:** A farm enclosure/milking station entrance. The background includes concrete floors, metal railings, and sometimes other cattle.

* **Challenges for Deep Learning:**
1. **Deformable Bodies:** Unlike rigid objects (cars), a cow's spine curves and extends as it walks, distorting the coat pattern.
2. **Occlusion:** The metal bars (seen in your attention map) frequently obscure parts of the animal.
3. **Similar Features:** All subjects share the same general shape and colors (black/white). The model *must* learn the specific topology of the spots, not just "is it black?".
4. **Lighting:** Variable lighting conditions in the barn can create shadows that mimic black spots.

**Preprocessing Justification (Why use this dataset?):**
Since the dataset contains folders named `1`, `10`, etc., each folder represents a unique **Identity (ID)**. The task is **Closed-Set Re-Identification**: Training on a set of cows and testing on unseen images of the *same* cows to match them correctly.

\subsubsection*{Counterfactual Attention Methodology}
Counterfactual attention analysis investigates how BotNet's attention mechanism responds to adversarial perturbations, providing insights into model robustness and feature importance. This technique helps understand whether the model relies on spurious correlations or truly discriminative features.

\subsubsection*{Implementation Strategy}
Our counterfactual attention implementation follows a systematic approach:

\begin{enumerate}
    \item \textbf{Attention Map Extraction:} Extract attention weights from the trained BotNet model for a set of validation images
    \item \textbf{High-Attention Region Identification:} Identify spatial regions with attention weights above a threshold (top 50\% of attention mass)
    \item \textbf{Masking Application:} Apply targeted masking to these high-attention regions by setting them to zero (black)
    \item \textbf{Counterfactual Training:} Retrain the model with an additional loss term that forces correct prediction even with the most attended regions masked
    \item \textbf{Comparative Analysis:} Compare original vs. counterfactual attention patterns and model performance
\end{enumerate}

\subsubsection*{Mathematical Formulation}
The counterfactual attention loss combines the original cross-entropy loss with a counterfactual loss:

\begin{equation}
\mathcal{L}_{counterfactual} = \mathcal{L}_{CE}^{original} + \mathcal{L}_{CE}^{masked}
\end{equation}

where:
\begin{itemize}
    \item $\mathcal{L}_{CE}^{original}$ is the standard cross-entropy loss on the original image
    \item $\mathcal{L}_{CE}^{masked}$ is the cross-entropy loss on the image with high-attention regions masked
\end{itemize}

\subsubsection*{Masking Techniques}
We implemented attention-guided masking:

\begin{itemize}
    \item \textbf{Attention Thresholding:} Identify pixels with attention weights above 0.5 (normalized)
    \item \textbf{Binary Mask Creation:} Create a mask where high-attention regions are set to 0, others to 1
    \item \textbf{Image Masking:} Multiply the original image by the mask to hide attended regions
    \item \textbf{Forced Prediction:} Require the model to predict correctly even with discriminative features hidden
\end{itemize}

\subsubsection*{Training Implementation}
The counterfactual training loop modifies the standard training:

\begin{lstlisting}[language=Python, caption=Counterfactual Training Loop]
def train_counterfactual(model, optimizer, train_loader, epochs=5):
    model.train()
    criterion = nn.CrossEntropyLoss()
    
    for epoch in range(epochs):
        total_loss = 0
        
        for imgs, labels in train_loader:
            imgs, labels = imgs.to(device), labels.to(device)
            optimizer.zero_grad()
            
            # Standard Forward Pass
            outputs_orig = model(imgs)
            loss_orig = criterion(outputs_orig, labels)
            
            # Generate Counterfactual Mask
            mask = get_attention_mask(model, imgs, threshold=0.5)
            
            # Apply Mask to Images
            imgs_masked = imgs * mask
            
            # Counterfactual Forward Pass
            outputs_masked = model(imgs_masked)
            loss_cf = criterion(outputs_masked, labels)
            
            # Combine Losses
            total_step_loss = loss_orig + loss_cf
            
            total_step_loss.backward()
            optimizer.step()
            
            total_loss += total_step_loss.item()
            
        avg_loss = total_loss / len(train_loader)
        print(f"Epoch {epoch+1} | CF Loss: {avg_loss:.4f}")
        
    return model
\end{lstlisting}

def get_attention_mask(model, img_tensor, threshold=0.6):
    """
    Generates a binary mask that covers the most attended regions.
    Returns: A mask tensor of shape (B, 1, H, W) where 0 = Masked, 1 = Visible
    """
    with torch.no_grad():
        _ = model(img_tensor)
        attn_map = model.mhsa.last_attention_map
        
        # Process attention map
        B, Heads, _, _ = attn_map.shape
        attn_map = attn_map.mean(dim=1)
        attn_map = attn_map.view(B, 8, 4, 8, 4)
        attn_map = attn_map.mean(dim=(1, 2))
        
        # Upsample to image size
        attn_map = F.interpolate(attn_map.unsqueeze(1), size=(256, 128), mode='bilinear')
        
        # Normalize and create binary mask
        attn_map = (attn_map - attn_map.min()) / (attn_map.max() - attn_map.min() + 1e-6)
        mask = (attn_map < threshold).float()
        
    return mask
\end{lstlisting}

\subsubsection*{2.1 Theoretical Questions (30 Points)}

**1. Difference between Methodologies: Autoregressive vs. Masked Iterative Generation**

* **Autoregressive (AR) Generation:** Traditional Large Language Models (like GPT) generate text sequentially, token by token, from left-to-right. To predict the current token , the model can only attend to the *past* tokens .
* *User Perception:* The generation appears linearly, similar to someone typing on a keyboard (e.g., "The" -> "The cat" -> "The cat sat").
* *Limitation:* Errors made early in the sequence cannot be corrected later ("Error Accumulation"), and the model cannot plan the end of the sentence before starting it.


* **Masked Iterative Generation (LLaDA):** This method treats generation as a parallel **denoising process**. The model starts with a sequence of pure noise (all `[MASK]` tokens). In each step, it predicts *all* masked tokens simultaneously using bidirectional context (seeing both "past" and "future" placeholders). It then refines the sequence iteratively.
* *User Perception:* The entire text structure appears vaguely at first and then "sharpens" into focus all at once, similar to a Polaroid photo developing or an image loading from blurry to clear.
* *Advantage:* The model can "look ahead" to ensure the beginning of the sentence agrees with the end (Global Coherence).



**2. Forward Masking as Noise**

* **Concept:** In continuous diffusion models (like Stable Diffusion for images), "noise" is added by perturbing pixel values with Gaussian noise. Text, however, is discrete; we cannot add "0.5" to a token ID.
* **Forward Masking:** In LLaDA, we define "noise" as the **loss of information**. The "Forward Process"  gradually replaces valid tokens in the original sequence with a special `[MASK]` token.
* At time , the mask probability  (Clean signal).
* At time , the mask probability  (Pure noise / Fully masked).


* **Analogy:** Just as adding Gaussian noise destroys the structure of an image until it is random static, randomly masking tokens destroys the semantic meaning of a sentence until it is an empty template. The model's job is to learn the reverse process: retrieving the signal (token) from the noise (mask).

**3. Reweighting Loss**

* **The Imbalance Problem:** The difficulty of the task varies drastically depending on the noise level ().
* **High Noise ():** ~90% of tokens are masked. Predicting the missing tokens is extremely hard because there is almost no context. However, there are *many* masked tokens, so the raw sum of losses is huge.
* **Low Noise ():** ~10% of tokens are masked. Predicting them is easy (refinement). There are *few* masked tokens, so the raw sum of losses is tiny.


* **The Solution:** We apply a reweighting coefficient .
* This down-weights the "hard" steps (high noise) where the model is just guessing the macro-structure.
* It up-weights the "easy" steps (low noise) where the model is performing critical fine-tuning.
* Without this, the model would be overwhelmed by the sheer volume of loss from the high-noise steps and would fail to learn the precise details required for the final output.

\subsection{Methodology Report: LLaDA Text-to-SQL Pipeline}

\subsubsection{1. Core Concept: LLaDA vs. Traditional Autoregression}

The core innovation in this project is the shift from standard \textbf{Autoregressive (AR)} generation to a \textbf{Masked Iterative Generation (Diffusion)} approach, known as LLaDA (Large Language Diffusion with Autoregression).

\begin{itemize}
    \item \textbf{Traditional AR Models (e.g., GPT):} These models generate text sequentially, token by token, from left to right. To predict the current token $x_t$, the model is strictly limited to seeing only the \textit{past} tokens $x_{<t}$.
    \begin{itemize}
        \item \textit{Equation:} $P(x_t | x_{<t})$
        \item \textit{Limitation:} The model cannot ``look ahead'' or plan the sentence structure globally.
    \end{itemize}
    
    \item \textbf{Our Method (LLaDA):} We treat text generation as a \textbf{denoising process}. The model is initialized with a sequence of pure noise (all \texttt{[MASK]} tokens). In each iteration, the model analyzes the \textit{entire} sequence (utilizing bidirectional context) and predicts the original tokens for the masked positions simultaneously. We then ``commit'' (lock in) the most confident predictions and repeat the process for the remaining masks.
    \begin{itemize}
        \item \textit{Advantage:} The model can use future context (even if currently masked) to inform earlier decisions, leading to more globally coherent SQL queries.
    \end{itemize}
\end{itemize}

\subsubsection{2. Forward Masking (The Discrete Noise Model)}

In continuous diffusion models (like Stable Diffusion for images), noise is added via Gaussian perturbation. In the discrete domain of text, we cannot simply add numerical noise to token IDs. Instead, we implement \textbf{Forward Masking} as our noise model.

\begin{itemize}
    \item \textbf{The Process (\texttt{noisy\_batch} function):} During training, we take a valid SQL query (the ``ground truth'') and corrupt it. We sample a time step $t$ for each training example.
    \begin{itemize}
        \item \textbf{Low Noise ($t \approx 0$):} The probability of masking ($p_{mask}$) is low. Most of the SQL query remains visible. This teaches the model to fix minor syntax errors or predict specific column names (Micro-structure).
        \item \textbf{High Noise ($t \approx 1$):} The probability of masking is high. The input is almost entirely \texttt{[MASK]} tokens. This teaches the model to predict the overall skeleton of the query (e.g., \texttt{SELECT ... FROM ... WHERE}) based solely on the user prompt (Macro-structure).
    \end{itemize}
\end{itemize}

\subsubsection{3. Training Pipeline Implementation}

Our training loop is distinct from standard LLM training in several key ways:

\begin{itemize}
    \item \textbf{Input Construction:} We concatenate the \texttt{Prompt} (System Instruction + Database Schema + User Question) and the \texttt{Answer} (Gold SQL).
    \begin{itemize}
        \item \textbf{Constraint:} We explicitly enforce a rule that \textbf{the Prompt is never masked}. The prompt acts as the ``condition'' or ``guide'' for the diffusion process. The noise is applied \textit{strictly} to the tokens belonging to the \texttt{Answer}.
    \end{itemize}
    
    \item \textbf{Loss Calculation:}
    \begin{itemize}
        \item We use \textbf{Cross-Entropy Loss}, but it is calculated \textbf{only on the masked tokens}. The model's objective is to reconstruct the original token at the positions where it sees a \texttt{[MASK]}.
        \item Unmasked tokens are ignored in the loss calculation (their label is set to \texttt{-100} in PyTorch), ensuring the model focuses entirely on the ``denoising'' task.
    \end{itemize}
    
    \item \textbf{Reweighting:}
    \begin{itemize}
        \item Samples with high noise ($t \approx 1$) contain very little information and are ``harder'' to learn from. Samples with low noise are ``easier.''
        \item To balance the training signal, we reweight the loss using the coefficient $w = \frac{1}{p_{mask} + \epsilon}$. This ensures that the gradients from ``hard'' examples are scaled up, preventing the model from ignoring difficult structural predictions.
    \end{itemize}
\end{itemize}

\subsubsection{4. Inference Strategy: Block Diffusion Sampling}

For generation, we cannot simply run the model once. We implement \textbf{Block Diffusion Sampling}, a strategy that combines the benefits of diffusion with the structure of sequential generation.

\begin{enumerate}
    \item \textbf{Initialization:} We append a sequence of \texttt{[MASK]} tokens (of length \texttt{gen\_len}) to the user prompt.
    \item \textbf{Iterative Block Processing:}
    \begin{enumerate}
        \item \textbf{Step 1:} The model predicts logits for all masks in the current block.
        \item \textbf{Step 2 (Confidence Selection):} We do not simply greedily select the top token. We calculate the model's \textbf{confidence} (softmax probability) for every token in the block.
        \item \textbf{Step 3 (Commitment):} We sort the predictions by confidence and ``lock in'' only the top-$k$ most confident tokens. The remaining positions stay as \texttt{[MASK]}.
        \item \textbf{Step 4 (Refinement):} The partially filled sequence is fed back into the model. The unmasked tokens now provide context to help resolve the remaining masks.
        \item This cycle repeats until the block is fully generated, then we move to the next block.
    \end{enumerate}
    \item \textbf{Why Blocks?} This approach mimics the logical flow of writing (planning sentences sequentially) while retaining the bidirectional power of diffusion (the model can ``see'' the placeholder masks for the future parts of the query while writing the beginning).
\end{enumerate}

\subsubsection{5. Technical Optimizations}

To ensure the pipeline is efficient and feasible on standard hardware (e.g., a single T4 GPU):

\begin{itemize}
    \item \textbf{4-bit Quantization:} We utilize \texttt{bitsandbytes} to load the 8-billion parameter LLaDA model in 4-bit precision. This reduces VRAM usage from \textasciitilde16GB to \textasciitilde5GB, preventing Out-Of-Memory (OOM) errors.
    \item \textbf{LoRA (Low-Rank Adaptation):} Instead of full fine-tuning, we freeze the pre-trained model weights and inject small, trainable rank-decomposition matrices into the attention layers. This reduces the number of trainable parameters by >99\%, drastically speeding up training and reducing memory overhead.
    \item \textbf{Gradient Accumulation:} Since memory constraints limit us to a small batch size (e.g., 2), we accumulate gradients over multiple steps (e.g., 4 or 8) before performing an optimizer update. This mathematically simulates a larger batch size (e.g., 16), stabilizing the training process.
\end{itemize}

\subsection{Theoretical Questions}

\subsubsection*{2.1.1 Autoregressive vs. Masked Iterative Generation}
The fundamental difference lies in the dependency structure and the generation process:

\begin{itemize}
\item \textbf{Autoregressive (AR) Generation:} Traditional AR models (like GPT) generate text sequentially, token by token, from left to right. The probability of the next token depends strictly on the \textit{preceding} tokens: $P(x_t | x_{<t})$. The user perceives the text appearing linearly, similar to a typewriter. While efficient for caching, this approach cannot utilize future context to resolve earlier ambiguities.

This sequential nature leads to \textbf{error accumulation}: if an early token is predicted incorrectly, it can cascade errors throughout the entire sequence, as all subsequent predictions depend on that faulty token. For example, in SQL generation, mistaking a table name early on would invalidate the entire query structure. Additionally, AR generation cannot be parallelized during inference, requiring $O(n)$ steps for a sequence of length $n$, which becomes computationally expensive for long outputs.

\item \textbf{Masked Iterative Generation (Diffusion):} LLaDA treats generation as a \textbf{denoising process}. It initializes with a sequence of pure noise (all \texttt{[MASK]} tokens) and iteratively predicts all tokens in parallel. Over multiple steps, the model ``refines'' the text by replacing low-confidence masks with predicted tokens based on bidirectional context. The user perceives the entire sentence structure emerging vaguely at first, with details filling in simultaneously across the sequence, similar to a developing photograph.

The key advantage is \textbf{bidirectional context}: the model can ``see'' both past and future tokens (even if currently masked), allowing it to make globally coherent decisions. For instance, in SQL generation, the model can simultaneously consider the SELECT clause, WHERE conditions, and JOIN statements, ensuring syntactic consistency across the entire query. This parallel prediction enables $O(1)$ inference steps per iteration (though multiple iterations may be needed), and reduces exposure bias by training on corrupted sequences rather than perfect prefixes.
\end{itemize}

\subsubsection*{2.1.2 Forward Masking as Noise}
In continuous diffusion models (e.g., for images), noise is added via Gaussian perturbation to pixel values. However, text consists of discrete categorical data where adding numerical noise is invalid.

In LLaDA, \textbf{Forward Masking} acts as the discrete analog to continuous noise. The corruption process $q(x_t | x_0)$ replaces a subset of tokens in the original sequence $x_0$ with a special \texttt{[MASK]} token based on a time-dependent probability $p_{mask}(t)$.
\begin{itemize}
\item At $t = 0$ (start of diffusion), $p_{mask} = 0$, and the sequence is clean.
\item At $t = 1$ (end of diffusion), $p_{mask} = 1$, and the sequence is pure noise (fully masked).
\end{itemize}
This transition from information to lack of information (masking) mathematically mirrors the transition from signal to Gaussian noise, allowing the model to learn the reverse ``denoising'' process.

Unlike continuous noise, which can be added incrementally (e.g., $\sqrt{1-\beta_t} x_{t-1} + \sqrt{\beta_t} \epsilon$), discrete masking is all-or-nothing for each token. This preserves the \textbf{positional structure} of the sequence while removing semantic content, enabling the model to learn both local token relationships and global sequence patterns. For SQL queries, this means the model can maintain awareness of query structure (e.g., SELECT-FROM-WHERE order) even when most tokens are masked, facilitating coherent denoising.

\subsubsection*{2.1.3 Reweighting Loss}
Reweighting is essential to \textbf{normalize the training signal} across different noise levels. The objective function involves a sum over masked tokens:

\[
\mathcal{L} = \sum_{i \in \text{masked}} \ell_i
\]

Without this reweighting factor (specifically the $\frac{1}{p_{mask} + \epsilon}$ term), the loss magnitude would be heavily skewed.
\begin{itemize}
\item \textbf{High Noise ($t \approx 1$):} Many tokens are masked. The sum has many terms, leading to a naturally large loss magnitude.
\item \textbf{Low Noise ($t \approx 0$):} Few tokens are masked. The sum has very few terms.
\end{itemize}
The reweighting coefficient (typically proportional to the inverse of the mask ratio) ensures that ``easy'' steps (low noise) and ``hard'' steps (high noise) contribute equally to the expected gradient, preventing the model from ignoring the fine-grained refinement steps required at low noise levels.

For example, consider two training samples: one with $p_{mask} = 0.1$ (10\% masked, loss sum $\approx 2.5$ for a 25-token SQL) and another with $p_{mask} = 0.9$ (90\% masked, loss sum $\approx 22.5$). Without reweighting, the high-noise sample dominates the gradient update. With reweighting $w = 1/(p_{mask} + 0.01)$, the weights become $\approx 9.9$ and $\approx 1.1$ respectively, balancing the contribution and ensuring the model learns both coarse structure (high noise) and precise details (low noise) effectively.

\subsubsection*{Forward Masking Process}
The core of LLaDA training involves progressive masking and prediction:

\begin{enumerate}
    \item \textbf{Time Sampling:} Sample diffusion timestep t uniformly from [0,1]
    \item \textbf{Mask Probability:} Calculate p\_mask = t (higher t means more masking)
    \item \textbf{Selective Masking:} Only mask tokens in the answer portion, preserve prompt
    \item \textbf{Noise Addition:} Replace masked tokens with [MASK] special token
    \item \textbf{Model Forward:} Process noisy sequence through transformer
    \item \textbf{Loss Computation:} Cross-entropy loss only on masked positions
\end{enumerate}

\subsubsection*{Mathematical Formulation}
The diffusion process can be formalized as:

\begin{equation}
q(x_t | x_0) = \prod_{i=1}^T q(x_t^i | x_{t-1}^i)
\end{equation}

where each step adds noise according to:
\begin{equation}
q(x_t | x_{t-1}) = \mathcal{N}(x_t; \sqrt{1-\beta_t}x_{t-1}, \beta_t I)
\end{equation}

In LLaDA, this becomes discrete token masking:
\begin{equation}
p_{mask}(t) = t, \quad t \sim \Uniform(0,1)
\end{equation}

\subsubsection*{Training Dynamics}
The training process shows characteristic diffusion learning patterns:

\begin{itemize}

\subsubsection*{Forward Masking \& Loss}
The forward masking process samples a time step $t$, calculates mask probability $p_{mask}$, and masks tokens in the \textit{Answer} segment only.

\begin{lstlisting}[language=Python, caption=Masking Logic Snippet]
def noisy_batch(input_ids, attention_mask, prompt_lengths, tokenizer):
    batch_size, seq_len = input_ids.shape
    masked_input_ids = input_ids.clone()
    labels = input_ids.clone()
    
    # Sample t uniformly
    t = torch.rand(batch_size, device=input_ids.device)
    p_mask = t.view(-1, 1) 
    
    # Generate random matrix
    rand_matrix = torch.rand(input_ids.shape, device=input_ids.device)
    mask_indices = rand_matrix < p_mask
    
    # Do NOT mask the Prompt
    for i in range(batch_size):
        mask_indices[i, :prompt_lengths[i]] = False
        
    # Do NOT mask Padding
    mask_indices = mask_indices & (attention_mask.bool())

    # Apply Mask Token
    masked_input_ids[mask_indices] = tokenizer.mask_token_id
    labels[~mask_indices] = -100  # Ignore in loss
    
    return masked_input_ids, labels, p_mask
\end{lstlisting}

\subsection{Evaluation and Block Diffusion}

\subsubsection*{Block-wise Generation Algorithm}
LLaDA employs a sophisticated non-autoregressive generation strategy that iteratively refines predictions through a block-wise diffusion process. This approach fundamentally differs from traditional autoregressive methods by leveraging bidirectional context and parallel prediction capabilities.

The algorithm operates through a series of carefully orchestrated steps that progressively transform a sequence of masked tokens into coherent SQL queries:

\begin{enumerate}
    \item \textbf{Initial State Preparation:} The generation begins with a fully masked answer sequence where all tokens in the SQL portion are replaced with \texttt{[MASK]} tokens. The conditioning prompt (system instructions, database schema, and user question) remains intact to provide necessary context for the diffusion process.
    
    \item \textbf{Parallel Prediction Phase:} In each iteration, the model processes the entire sequence simultaneously, predicting probabilities for all masked positions. Unlike autoregressive models that predict one token at a time, this parallel approach allows the model to consider global context and inter-token dependencies across the entire SQL query structure.
    
    \item \textbf{Confidence Assessment Mechanism:} For each masked position, the model computes prediction confidence scores based on the softmax probabilities of the predicted tokens. This confidence metric serves as a reliability indicator, helping distinguish between high-certainty predictions and uncertain guesses.
    
    \item \textbf{Adaptive Token Commitment:} The algorithm employs a dynamic selection strategy where tokens with the highest confidence scores are committed to their predicted values. This selective commitment prevents the propagation of uncertain predictions while allowing confident tokens to be locked in place, reducing the search space for subsequent iterations.
    
    \item \textbf{Iterative Refinement Process:} The process repeats on the remaining masked positions, with each iteration focusing computational resources on increasingly difficult predictions. This progressive refinement ensures that easy structural elements (like SQL keywords) are resolved first, followed by complex elements requiring deeper semantic understanding.
    
    \item \textbf{Convergence and Termination:} The algorithm continues until either all positions are filled or a maximum number of iterations is reached. Early termination occurs when no masked positions remain, while the iteration limit prevents infinite loops in cases of persistent uncertainty.
\end{enumerate}

\subsubsection*{Confidence-Based Selection Strategy}
The confidence-based selection mechanism represents a critical innovation in non-autoregressive generation, enabling adaptive behavior that adjusts to the model's certainty levels:

\begin{itemize}
    \item \textbf{Dynamic Confidence Thresholding:} Rather than using a fixed threshold, the algorithm computes adaptive thresholds based on the entropy of prediction distributions. High-entropy predictions (indicating uncertainty) result in more conservative thresholds, while low-entropy predictions allow more aggressive token commitment.
    
    \item \textbf{Variable Block Size Management:} The number of tokens committed per iteration varies dynamically based on the model's confidence landscape. When predictions are highly confident, larger blocks (16-32 tokens) can be committed simultaneously. During uncertain phases, the algorithm reduces to smaller blocks (4-8 tokens) to maintain generation quality.
    
    \item \textbf{Top-k Selection Strategy:} Within each iteration, the algorithm ranks all masked positions by their confidence scores and selects the top-k most confident predictions for commitment. This ensures that only the most reliable predictions are locked in, maintaining the integrity of the generation process.
    
    \item \textbf{Adaptive Behavioral Patterns:} The algorithm exhibits intelligent adaptation to different query complexities. For simple queries with clear structural patterns, it demonstrates aggressive commitment behavior. For complex queries involving multiple joins or nested conditions, it adopts a more cautious, incremental approach.
\end{itemize}

\subsubsection*{Mathematical Foundation of Block Diffusion}
The block diffusion generation process can be formally characterized as an optimization problem that seeks to maximize the conditional probability of the generated sequence given the conditioning context:

\begin{equation}
x = \arg\max_{x} p(x|c) = \arg\max_{x} \prod_{t=1}^T p(x_t | x_{<t}, c)
\end{equation}

However, unlike traditional autoregressive decoding, the block diffusion approach decomposes this optimization into iterative refinement steps:

\begin{equation}
x^{(k+1)} = \arg\max_{x^{(k+1)}} p(x^{(k+1)} | x^{(k)}, c)
\end{equation}

where $x^{(k)}$ represents the partially completed sequence at iteration $k$, with committed tokens fixed and masked positions available for prediction. This formulation captures the essence of the block diffusion process as a series of conditional optimization steps that progressively improve the sequence quality.

\subsubsection*{Advanced Implementation Features}
The block diffusion implementation incorporates several sophisticated features that enhance generation quality and computational efficiency:

\begin{itemize}
    \item \textbf{Entropy-Based Early Stopping:} The algorithm monitors prediction entropy across all masked positions and terminates early when entropy falls below a threshold, indicating high confidence in remaining predictions.
    
    \item \textbf{Length-Adaptive Scheduling:} The token commitment rate adapts to sequence length, with longer queries receiving proportionally more iterations to ensure adequate refinement time.
    
    \item \textbf{Context-Aware Masking:} During refinement iterations, the algorithm can selectively re-mask previously committed tokens if they exhibit low contextual coherence with newly committed neighbors.
    
    \item \textbf{Memory-Efficient Batching:} The implementation supports batch processing of multiple generation requests, optimizing GPU utilization for parallel text generation tasks.
\end{itemize}

\subsubsection*{Detailed Implementation Code}
The core block diffusion generation algorithm is implemented with careful attention to numerical stability and computational efficiency:

\begin{lstlisting}[language=Python, caption=Advanced Block Diffusion Generation Implementation]
@torch.no_grad()
def generate_block_diffusion(model, tokenizer, prompt_text, steps=32, gen_len=64, 
                           confidence_threshold=0.8, min_block_size=4, max_block_size=16):
    """
    Advanced block diffusion generation with adaptive confidence thresholding.
    
    Args:
        model: The LLaDA diffusion model
        tokenizer: Tokenizer for encoding/decoding
        prompt_text: Conditioning prompt (schema + question)
        steps: Maximum number of diffusion steps
        gen_len: Maximum length of generated sequence
        confidence_threshold: Minimum confidence for token commitment
        min_block_size: Minimum tokens to commit per step
        max_block_size: Maximum tokens to commit per step
    """
    # Encode prompt and initialize masked sequence
    prompt_ids = tokenizer.encode(prompt_text, return_tensors='pt').to(device)
    mask_ids = torch.full((1, gen_len), tokenizer.mask_token_id, device=device)
    input_ids = torch.cat([prompt_ids, mask_ids], dim=1)
    
    seq_len = input_ids.shape[1]
    prompt_len = prompt_ids.shape[1]
    unknown_indices = set(range(prompt_len, seq_len))
    
    # Track generation statistics
    generation_stats = {
        'steps_used': 0,
        'tokens_committed': [],
        'avg_confidence': []
    }
    
    for step in range(steps):
        if not unknown_indices:
            break
            
        # Forward pass through model
        outputs = model(input_ids)
        logits = outputs.logits
        probs = torch.softmax(logits, dim=-1)
        confidences, predicted_ids = torch.max(probs, dim=-1)
        
        # Compute entropy for adaptive thresholding
        entropy = -torch.sum(probs * torch.log(probs + 1e-10), dim=-1)
        adaptive_threshold = confidence_threshold * (1 + entropy.mean().item())
        
        # Collect candidates with high confidence
        candidates = []
        current_unknowns = list(unknown_indices)
        
        for idx in current_unknowns:
            confidence = confidences[0, idx].item()
            token_id = predicted_ids[0, idx].item()
            entropy_val = entropy[0, idx].item()
            
            if confidence >= adaptive_threshold:
                candidates.append((confidence, idx, token_id, entropy_val))
        
        if not candidates:
            # No sufficiently confident predictions, reduce threshold
            adaptive_threshold *= 0.9
            candidates = [(confidences[0, idx].item(), idx, predicted_ids[0, idx].item(), 
                          entropy[0, idx].item()) for idx in current_unknowns]
        
        # Sort by confidence and select top candidates
        candidates.sort(key=lambda x: x[0], reverse=True)
        
        # Adaptive block size based on average confidence
        avg_confidence = sum(c[0] for c in candidates) / len(candidates) if candidates else 0
        block_size = int(min_block_size + (max_block_size - min_block_size) * avg_confidence)
        k = min(block_size, len(candidates), len(unknown_indices))
        
        # Commit top-k candidates
        top_candidates = candidates[:k]
        committed_tokens = []
        
        for confidence, idx, token_id, entropy_val in top_candidates:
            input_ids[0, idx] = token_id
            unknown_indices.remove(idx)
            committed_tokens.append(token_id)
        
        # Update statistics
        generation_stats['steps_used'] += 1
        generation_stats['tokens_committed'].append(len(committed_tokens))
        generation_stats['avg_confidence'].append(avg_confidence)
        
        # Early stopping if all predictions are highly confident
        if avg_confidence > 0.95 and len(unknown_indices) < gen_len * 0.1:
            break
    
    # Decode generated sequence
    generated_text = tokenizer.decode(input_ids[0, prompt_len:], skip_special_tokens=True)
    
    return generated_text, generation_stats
\end{lstlisting}

\subsubsection*{Comprehensive Evaluation Metrics}
The evaluation framework employs multiple complementary metrics to provide a holistic assessment of Text-to-SQL generation quality:

\begin{itemize}
    \item \textbf{Exact Match (EM) Accuracy:} Measures the percentage of generated queries that exactly match the ground truth after normalization. This strict metric penalizes any syntactic variations, even semantically equivalent ones.
    
    \item \textbf{Execution Accuracy:} Evaluates whether the generated SQL query, when executed against the database, produces the correct result set. This functional metric captures semantic correctness beyond syntactic matching.
    
    \item \textbf{Syntax Validity:} Assesses whether the generated query is syntactically correct according to SQL grammar rules. This metric identifies queries that are parseable but may not execute correctly.
    
    \item \textbf{Semantic Correctness:} Measures whether the generated query captures the intended meaning of the natural language question, even if the exact SQL syntax differs from the reference.
    
    \item \textbf{Structural Similarity:} Evaluates the similarity of query structure (SELECT-FROM-WHERE patterns) between generated and reference queries, providing insight into high-level query comprehension.
\end{itemize}

\subsubsection*{Advanced SQL Normalization Pipeline}
To ensure fair and accurate evaluation, the normalization process addresses multiple sources of syntactic variation:

\begin{enumerate}
    \item \textbf{Case Normalization:} Converts all SQL keywords and identifiers to lowercase, eliminating case sensitivity issues (\texttt{SELECT} vs \texttt{select}).
    
    \item \textbf{Identifier Standardization:} Removes backticks (\texttt{`}), single quotes (\texttt{'}), and double quotes (\texttt{"}) around table and column names, normalizing identifier quoting conventions across different SQL dialects.
    
    \item \textbf{Whitespace Normalization:} Collapses multiple consecutive whitespace characters (spaces, tabs, newlines) into single spaces, while preserving the logical structure of the query.
    
    \item \textbf{Punctuation Cleanup:} Strips trailing semicolons and removes extraneous punctuation that doesn't affect query semantics.
    
    \item \textbf{Keyword Canonicalization:} Standardizes SQL keywords to their canonical forms, handling variations like \texttt{group by} vs \texttt{GROUP BY}.
    
    \item \textbf{Alias Resolution:} Normalizes table and column aliases to consistent naming schemes, reducing false negatives due to arbitrary alias choices.
    
    \item \textbf{Expression Simplification:} Simplifies equivalent expressions (e.g., \texttt{a = b} vs \texttt{b = a} in WHERE clauses) to their canonical forms.
\end{enumerate}

\subsection{Bonus: 5 Creative Ideas for Improving LLaDA}

\subsubsection*{1. Syntax-Aware Masking Strategy (Structure-Preserving Noise)}

\textbf{Proposal:} Instead of using a uniform random distribution to mask tokens during the training phase (Forward Process), I propose using a \textbf{syntax-aware masking schedule}. We can use a lightweight SQL parser or POS-tagger to identify SQL keywords (e.g., \texttt{SELECT}, \texttt{FROM}, \texttt{WHERE}) versus content tokens (e.g., column names, values). We would assign a higher masking probability to content tokens and a lower probability to structural keywords.

\textbf{Why:} SQL is a formal language with a rigid structure. Random masking often destroys the syntactic skeleton, making it harder for the model to learn the logic. By preserving the keywords longer, we act as a "scaffold," allowing the model to focus its capacity on the harder task of \textbf{Schema Linking} (matching natural language to table columns).

\textbf{Expected Effect:} Improved \textbf{Syntactic Correctness} (fewer invalid SQL errors) and faster training convergence.

\subsubsection*{2. Confidence-Adaptive Dynamic Block Sampling}

\textbf{Proposal:} Currently, the \texttt{block\_length} in our generation loop is fixed (e.g., 16 tokens). I propose a \textbf{Dynamic Block Sizing} strategy. In each diffusion step, we calculate the average confidence (softmax probability) of the predicted block. If the confidence is high ($\geq 0.8$), we commit a larger block (e.g., 32 tokens). If confidence is low ($\leq 0.5$), we commit a smaller block (e.g., 4 tokens) or even step back.

\textbf{Why:} Queries have varying difficulty; writing a simple \texttt{SELECT *} is easy, while complex \texttt{JOIN} conditions are hard. A fixed block size forces the model to move too fast through hard parts (causing errors) or too slow through easy parts (wasting time).

\textbf{Expected Effect:} Significant increase in \textbf{Inference Speed} (latency reduction) without sacrificing accuracy, as the model "sprints" through easy sections and "thinks" carefully on hard ones.

\subsubsection*{3. Self-Correction via Execution Feedback (Test-Time Adaptation)}

\textbf{Proposal:} Implement an iterative \textbf{Refinement Loop} during inference. After the LLaDA model generates a full SQL query, we attempt to execute it on a dummy database schema (or run it through a strict syntax checker). If the execution fails (e.g., "Column not found"), we identify the token span corresponding to the error, \textbf{re-mask} only that specific span, and feed it back into the model for re-generation (Partial Diffusion).

\textbf{Why:} Unlike Autoregressive models which are "stuck" with their previous tokens, Diffusion models are naturally bidirectional and can edit specific parts of a sequence without rewriting the whole thing. This leverages the unique "inpainting" capability of LLaDA.

\textbf{Expected Effect:} Higher \textbf{Execution Match (EM)} scores and robustness, as the model can fix its own hallucinations.

\subsubsection*{4. Curriculum Noise Scheduling}

\textbf{Proposal:} Modify the training loop to implement \textbf{Curriculum Learning}. Instead of sampling the time step $t$ uniformly from $[0, T]$ throughout the entire training, we start with $t$ biased towards $0$ (low noise/easy denoising) in early epochs and gradually shift the distribution towards $T$ (pure noise generation) in later epochs.

\textbf{Why:} Denoising a fully masked sequence is a very hard task. By first teaching the model to fill in small gaps (easy syntax fixes), we stabilize the gradients. Once the model understands local dependencies, we gradually increase the difficulty to global structure generation.

\textbf{Expected Effect:} More \textbf{Stable Training} (preventing loss spikes) and potentially better final generalization.

\subsubsection*{5. Anti-Hallucination Loss (Schema-Constrained Optimization)}

\textbf{Proposal:} Modify the loss function to explicitly penalize \textbf{Schema Hallucination}. During training, if the model predicts a token that represents a column or table name NOT present in the input schema, we multiply its Cross-Entropy loss by a penalty factor $\lambda > 1$.

\textbf{Why:} The most common error in Text-to-SQL is inventing column names that don't exist. Standard loss treats this as a generic token prediction error. By explicitly weighting these errors higher, we force the model to pay strictly closer attention to the provided \texttt{Schema} in the prompt.

\textbf{Expected Effect:} Improved \textbf{Schema Linking Accuracy} and reduction in "Invalid Column" runtime errors.

\subsubsection*{Attention Mechanisms in Convolutional Networks}
The BotNet experiments provide crucial insights into the integration of attention mechanisms with convolutional architectures:

\begin{itemize}
    \item \textbf{Inductive Bias Trade-offs:} Demonstrated that while CNNs excel with their built-in spatial hierarchies and translation invariance, attention mechanisms provide superior global context modeling that becomes critical for fine-grained discrimination tasks.
    \item \textbf{Attention Localization:} Analysis revealed that attention mechanisms naturally focus on semantically meaningful regions (person silhouettes, clothing patterns) rather than spurious background features, validating their effectiveness for Re-ID.
    \item \textbf{Overfitting Dynamics:} The study highlighted attention models' tendency to overfit to training data patterns, suggesting the need for careful regularization and data augmentation strategies.
    \item \textbf{Computational Scaling:} Showed that attention can be efficiently integrated into existing CNN architectures with minimal computational overhead when properly localized.
\end{itemize}

\subsubsection*{Diffusion Models for Structured Text Generation}
The LLaDA implementation advances our understanding of diffusion processes in discrete domains:

\begin{itemize}
    \item \textbf{Discrete vs. Continuous Diffusion:} Successfully demonstrated that masking-based corruption can serve as an effective discrete analog to Gaussian noise, enabling diffusion training on categorical data.
    \item \textbf{Bidirectional Context Utilization:} Showed that non-autoregressive generation can leverage future context to make more informed predictions, particularly beneficial for structured languages like SQL.
    \item \textbf{Quality-Efficiency Trade-offs:} Established that diffusion models can achieve competitive accuracy with superior computational characteristics compared to autoregressive baselines.
    \item \textbf{Scalability Advantages:} Demonstrated that block-wise generation scales better to long sequences and parallel processing environments.
\end{itemize}
