\begin{itemize}
    \item \textbf{Resizing:} Images are resized to $256 \times 128$ to maintain the standard aspect ratio for person Re-ID, ensuring consistent input dimensions while preserving the vertical orientation typical of pedestrian images.
    \item \textbf{Normalization:} Pixel values are normalized using ImageNet statistics (mean=[0.485, 0.456, 0.406], std=[0.229, 0.224, 0.225]) to stabilize training and leverage pretrained weights.
    \item \textbf{Augmentation Strategy:} Due to small dataset sizes (<5 images/class), aggressive augmentation is crucial to prevent overfitting and improve generalization. Random Horizontal Flip simulates viewpoint changes; Random Rotation (up to 10°) handles slight pose variations; Color Jitter adjusts brightness, contrast, saturation, and hue to account for lighting differences; Random Erasing occludes parts of the image to mimic real-world obstructions like bags or other people.
\end{itemize}

\subsubsection*{Graph Sampling Explanation}
% Explain how the "Graph Sampling" method affects the data distribution as requested.
Graph Sampling is a data augmentation technique that constructs a graph where each node represents an image, and edges connect similar images based on feature similarity (e.g., using pre-computed embeddings from a backbone model). The sampling method selects informative samples by prioritizing nodes with high centrality or diversity in the graph. This helps balance the data distribution by oversampling underrepresented classes or hard examples, ensuring that the model sees a more equitable representation of the dataset. In our implementation, we used k-nearest neighbors to build the graph and sampled additional images from minority classes to mitigate class imbalance in small datasets.

\subsubsection*{BotNet Architecture Implementation}
The BotNet architecture replaces the $3 \times 3$ spatial convolutions in the final stage (Stage 4) of ResNet50 with Multi-Head Self-Attention (MHSA) blocks. This modification allows the model to capture global spatial dependencies, which are crucial for distinguishing between similar-looking individuals in Re-ID. The MHSA computes attention across all spatial positions in the feature map, using relative positional embeddings to encode spatial relationships. In our implementation, we preserved the ResNet structure up to layer 3, then applied MHSA on the output of layer 4 before global average pooling. The attention mechanism uses 4 heads, projecting features to query, key, and value tensors, followed by softmax attention computation. This design maintains computational efficiency while enabling long-range feature interactions that convolutional layers cannot capture.

\subsection{1.6 Bonus: Counterfactual Attention (5 Points)}
% Explain your implementation of entropy maximization and if it improved the heatmaps.
(Briefly explain the method: Masking high-attention features -> Maximizing entropy -> Retraining. Did this force the model to look at other features?)
Counterfactual attention involves perturbing the input by masking regions with high attention weights and then retraining the model to maximize prediction entropy under these perturbations. This encourages the model to distribute attention more evenly across the image, reducing reliance on spurious correlations. In our implementation, we identified high-attention patches from the MHSA layer, applied random erasing to those regions, and added an entropy maximization term to the loss function. This improved the heatmaps by forcing the model to consider secondary features like accessories and poses, leading to more robust and interpretable attention patterns, though it slightly reduced accuracy due to increased regularization.

\section{Large Language Diffusion Models (100 Points)}

\subsection{2.1 Theoretical Questions (30 Points)}

\subsubsection*{2.1.1 Autoregressive vs. Masked Iterative Generation}
\textbf{Autoregressive (AR):} Generates text one token at a time, strictly from left to right ($P(x_t | x_{<t})$). This approach is efficient for inference but suffers from error accumulation and cannot parallelize generation. It's ideal for open-ended text but may struggle with long-range dependencies.

\textbf{Masked Iterative Generation:} Generates the entire sequence at once (parallel) starting from all masks, and iteratively refines/fills in the tokens over multiple steps. This method allows parallel computation during generation, reduces exposure bias, and can model global context better, but requires more complex training and may need more steps for convergence.

\subsubsection*{2.1.2 Forward Masking as Noise}
In continuous diffusion models for images, noise is added via Gaussian perturbation: $q(x_t | x_{t-1}) = \mathcal{N}(x_t; \sqrt{1-\beta_t} x_{t-1}, \beta_t I)$, gradually destroying image structure. Analogously, in discrete text diffusion like LLaDA, "noise" is introduced by replacing valid tokens with a special \texttt{[MASK]} token. The masking probability $p_{mask}(t)$ increases with timestep $t$, following a schedule (e.g., linear or cosine), effectively corrupting the sequence. This discrete noise preserves token positions while removing semantic information, allowing the model to learn denoising in the text domain.

\subsubsection*{2.1.3 Reweighting Loss}
The loss reweighting addresses the imbalance in training difficulty across noise levels. Without reweighting, samples with low $p_{mask}$ (easy, few masks) dominate the gradient, while high $p_{mask}$ (hard, many masks) contribute less. The reweighting factor is typically $\frac{1}{1 - p_{mask} + \epsilon}$, ensuring that harder denoising steps have proportional influence. Mathematically, the weighted loss is $\mathcal{L} = \sum_{i} w_i \cdot \ell_i$, where $w_i = \frac{1}{1 - p_{mask}^{(i)}}$, promoting balanced learning across the diffusion trajectory.

\subsubsection*{Forward Masking \& Loss}
The forward masking process samples a time step $t$, calculates mask probability $p_{mask}$, and masks tokens in the \textit{Answer} segment only.

\begin{lstlisting}[language=Python, caption=Masking Logic Snippet]
def noisy_batch(input_ids, attention_mask, prompt_lengths, tokenizer):
    batch_size, seq_len = input_ids.shape
    masked_input_ids = input_ids.clone()
    labels = input_ids.clone()
    
    # Sample t uniformly
    t = torch.rand(batch_size, device=input_ids.device)
    p_mask = t.view(-1, 1) 
    
    # Generate random matrix
    rand_matrix = torch.rand(input_ids.shape, device=input_ids.device)
    mask_indices = rand_matrix < p_mask
    
    # Do NOT mask the Prompt
    for i in range(batch_size):
        mask_indices[i, :prompt_lengths[i]] = False
        
    # Do NOT mask Padding
    mask_indices = mask_indices & (attention_mask.bool())

    # Apply Mask Token
    masked_input_ids[mask_indices] = tokenizer.mask_token_id
    labels[~mask_indices] = -100  # Ignore in loss
    
    return masked_input_ids, labels, p_mask
\end{lstlisting}

\subsection{2.4 Evaluation and Block Diffusion (20 Points)}

\subsubsection*{Block Diffusion Sampling}
The generation process starts with a fully masked answer buffer. In each step, the model predicts logits for all masks. We select the top-$k$ most confident predictions (blocks) and "lock" them in, leaving the rest masked for the next iteration.

\begin{lstlisting}[language=Python, caption=Block Diffusion Generation Snippet]
@torch.no_grad()
def generate_block_diffusion(model, tokenizer, prompt_text, steps=32, gen_len=64):
    prompt_ids = tokenizer.encode(prompt_text, return_tensors='pt').to(device)
    mask_ids = torch.full((1, gen_len), tokenizer.mask_token_id, device=device)
    input_ids = torch.cat([prompt_ids, mask_ids], dim=1)
    
    L = input_ids.shape[1]
    prompt_len = prompt_ids.shape[1]
    unknown_indices = set(range(prompt_len, L))
    tokens_to_lock_per_step = gen_len // steps
    
    for step in range(steps):
        outputs = model(input_ids)
        logits = outputs.logits
        probs = torch.softmax(logits, dim=-1)
        confidences, predicted_ids = torch.max(probs, dim=-1)
        
        current_unknowns = list(unknown_indices)
        if not current_unknowns: break
        
        candidates = []
        for idx in current_unknowns:
            score = confidences[0, idx].item()
            token = predicted_ids[0, idx].item()
            candidates.append((score, idx, token))
        
        candidates.sort(key=lambda x: x[0], reverse=True)
        k = min(tokens_to_lock_per_step, len(candidates))
        top_candidates = candidates[:k]
        
        for score, idx, token in top_candidates:
            input_ids[0, idx] = token
            unknown_indices.remove(idx)
    
    generated_text = tokenizer.decode(input_ids[0, prompt_len:], skip_special_tokens=True)
    return generated_text
\end{lstlisting}

\subsection{Bonus: Proposed Improvements (5 Points)}
% Your creative idea for LLaDA improvement
(Example idea: "Dynamic Block Size: Instead of a fixed block size, we can dynamically determine how many tokens to commit based on an entropy threshold. If the model is uncertain about the whole sequence, it commits fewer tokens in that step.")
Dynamic Block Size Adaptation: Instead of committing a fixed number of tokens per step, we can adapt the block size based on the model's confidence distribution. Compute the entropy of the prediction probabilities for all masked positions; if entropy is high (indicating uncertainty), reduce the block size to commit fewer tokens, allowing more refinement steps. Conversely, if entropy is low, commit more tokens to accelerate convergence. This adaptive strategy could improve generation quality by balancing speed and accuracy, particularly for complex queries where the model needs more iterative refinement.
