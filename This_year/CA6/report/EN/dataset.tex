\subsection{Datasets}
This report uses two standard vision datasets selected to match the two tasks:
(i) likelihood-based generative modeling and latent analysis (Dynamic MNIST), and
(ii) conditional generation for augmentation with limited labeled data (FashionMNIST).

\subsubsection{Dynamic MNIST}
Dynamic MNIST is derived from the MNIST handwritten digits dataset (28$\times$28 grayscale). Instead of using a single fixed binarization, each image is binarized \emph{stochastically} at each presentation using the pixel intensity as a Bernoulli parameter:
\[
x_i \sim \mathrm{Bernoulli}(x^{\mathrm{gray}}_i),\quad i=1,\dots,D.
\]
This yields a distribution over binary images that more faithfully reflects uncertainty in pixel values and is widely used in likelihood-based generative modeling studies. The dataset is used to evaluate:
\begin{itemize}
  \item baseline VAE vs proposed VAE objective/architecture,
  \item low-dimensional vs high-dimensional latent settings,
  \item posterior behavior, collapse indicators, and likelihood estimates.
\end{itemize}

\subsubsection{FashionMNIST}
FashionMNIST contains 28$\times$28 grayscale images across 10 clothing categories (e.g., T-shirt/top, trouser, pullover). It is used for conditional image generation and augmentation. Images are normalized to $[-1,1]$ using:
\[
x \leftarrow \frac{x-0.5}{0.5}.
\]
FashionMNIST supports clean class-conditional evaluation and direct measurement of augmentation effects on classifier generalization.

\subsection{Limited-data regime and non-overlapping splits (FashionMNIST)}
To simulate limited labeled data and to ensure the augmentation experiment is scientifically valid, we construct two \emph{non-overlapping} subsets of the FashionMNIST training set:
\begin{itemize}
  \item $\mathcal{D}_{\mathrm{GAN}}$: used exclusively to train the conditional WGAN-GP generator/critic.
  \item $\mathcal{D}_{\mathrm{CLS}}$: used exclusively to train the downstream classifier.
\end{itemize}
The subsets are stratified by class, and the per-class sample counts follow the assignment specification (e.g., $N$ samples per class). The index lists of both subsets are saved to disk (e.g., \texttt{data/splits/}) and reused for all runs. This prevents accidental overlap and eliminates a key confounder: if $\mathcal{D}_{\mathrm{GAN}} \cap \mathcal{D}_{\mathrm{CLS}} \neq \emptyset$, the generator can effectively memorize classifier training examples, and ``augmentation'' would not be an independent distributional expansion.

\subsection{Train/Validation/Test protocol}
\paragraph{VAE (Dynamic MNIST).}
Models are trained on the training split. Evaluation uses a held-out test split for:
(i) likelihood estimation (importance-weighted estimator),
(ii) latent diagnostics (posterior statistics and PCA/traversals),
(iii) qualitative sample generation. If a validation set is used for hyperparameter selection (e.g., learning rates, architecture depth), it is formed only from the training split to preserve test integrity.

\paragraph{GAN augmentation (FashionMNIST).}
\begin{itemize}
  \item The GAN is trained only on $\mathcal{D}_{\mathrm{GAN}}$.
  \item The classifier is trained only on $\mathcal{D}_{\mathrm{CLS}}$ (real-only baseline) or on $\mathcal{D}_{\mathrm{CLS}}$ plus synthetic samples generated by the trained GAN (augmented condition).
  \item Final evaluation is performed on the untouched FashionMNIST test set, which contains only real samples.
\end{itemize}

\subsection{Ground truth and evaluation endpoints}
Both tasks use standard, unambiguous evaluation endpoints:
\begin{itemize}
  \item \textbf{VAE:} ELBO decomposition, importance-sampled log-likelihood estimates, posterior/latent diagnostics, and qualitative sampling.
  \item \textbf{GAN augmentation:} classifier test accuracy and class-wise performance on real test data, plus training diagnostics (Wasserstein estimate, GP, drift, embedding regularization) and fixed-noise sample grids at specified checkpoints.
\end{itemize}

\subsection{Dataset integrity checks}
Before training, we perform the following checks and log them:
\begin{itemize}
  \item class balance in $\mathcal{D}_{\mathrm{GAN}}$ and $\mathcal{D}_{\mathrm{CLS}}$,
  \item confirmation of zero overlap between splits,
  \item normalization range verification (min/max and histogram sanity checks),
  \item sample visualizations after preprocessing (to detect transform mistakes).
\end{itemize}
These checks prevent common implementation errors that can invalidate generative modeling comparisons or augmentation conclusions.
