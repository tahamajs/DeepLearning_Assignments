\section{Implementation Details and Codebase Walkthrough}
This section documents the code modules that implement the datasets, metrics, reproducibility utilities, and model architectures. The goal is to ensure that every reported experimental claim can be traced to a specific implementation component.

\subsection{\texttt{deepgen/data.py}: Datasets, transforms, and loaders}
\paragraph{Purpose.}
This module defines the preprocessing transforms and PyTorch \texttt{DataLoader} objects used throughout training and evaluation.

\paragraph{Transform definition: \texttt{mnist\_transforms}.}
The function \texttt{mnist\_transforms(scale\_to\_minus1\_1)} composes:
\begin{itemize}
  \item \texttt{ToTensor}: converts PIL images to float tensors in $[0,1]$,
  \item optional \texttt{Normalize(mean=0.5,std=0.5)}: maps $[0,1]\rightarrow[-1,1]$ using $x\mapsto (x-0.5)/0.5$.
\end{itemize}
This range convention is essential because the GAN generator outputs $\tanh(\cdot)\in[-1,1]$, and the VAE encoder in this project is written assuming inputs in $[-1,1]$. When the VAE reconstruction uses BCE against sigmoid outputs, targets are converted back to $[0,1]$ as $(x+1)/2$ inside the loss.

\paragraph{Loader construction: \texttt{get\_mnist\_loaders}.}
\texttt{get\_mnist\_loaders} downloads MNIST via \texttt{torchvision.datasets.MNIST} and returns two loaders (train/test). Key scientific/engineering choices:
\begin{itemize}
  \item \textbf{Shuffling:} training data is shuffled to reduce gradient bias.
  \item \textbf{drop\_last=True (train):} ensures consistent batch size; this is often important for stable adversarial training and for batchnorm behavior.
  \item \textbf{pin\_memory:} enabled only when CUDA is available to speed host-to-device transfers.
  \item \textbf{train\_subset:} allows controlled small-data experiments by restricting training indices to \texttt{range(train\_subset)}; this must be logged to preserve interpretability of limited-regime results.
\end{itemize}

\subsection{\texttt{deepgen/metrics.py}: Feature extraction and FID-like distance}
\paragraph{Purpose.}
This module computes a Fréchet-distance-style metric in a learned feature space, analogous to FID, but using a project-specific feature extractor rather than Inception.

\paragraph{\texttt{extract\_features}.}
Given a \texttt{feature\_model} and a \texttt{DataLoader}, this function:
\begin{itemize}
  \item switches to eval mode and disables gradients,
  \item forwards batches through the model with \texttt{return\_features=True},
  \item aggregates features into a NumPy array of shape $(N,D)$.
\end{itemize}
This yields a deterministic feature matrix when seeds and threading are controlled.

\paragraph{Covariance and matrix square root.}
The helper \texttt{\_covariance} computes empirical mean and covariance with Bessel correction. The function \texttt{\_sqrtm\_psd} computes the symmetric PSD square root using eigen-decomposition with eigenvalue clipping for numerical stability.

\paragraph{\texttt{fid\_like}.}
Given real features and fake features, the metric is:
\[
\|\mu_r-\mu_f\|_2^2 + \mathrm{Tr}\Big(\Sigma_r+\Sigma_f-2(\Sigma_r^{1/2}\Sigma_f\Sigma_r^{1/2})^{1/2}\Big),
\]
with diagonal jitter $\epsilon I$ added to covariances. This is a standard Fréchet distance formula; in this project it should be interpreted as a \emph{FID-like proxy} dependent on the chosen feature model (e.g., LeNet penultimate features), and must be reported with that caveat.

\subsection{\texttt{deepgen/utils.py}: Reproducibility utilities and checkpointing}
\paragraph{Determinism controls.}
\texttt{set\_seed(seed)} sets Python, NumPy, and Torch seeds, and forces CuDNN determinism (at possible speed cost). This is required for scientifically defensible comparisons of GAN/VAE runs, since nondeterminism can otherwise dominate observed variance.

\paragraph{Device selection.}
\texttt{get\_device("auto")} chooses CUDA when available, otherwise CPU, ensuring a single codepath with logged hardware dependence.

\paragraph{Atomic checkpoint saving.}
\texttt{\_atomic\_torch\_save} writes checkpoints to a temporary file and then atomically renames it, preventing partial/corrupted checkpoints if the process crashes mid-write.

\paragraph{RNG state capture/restore.}
\texttt{capture\_rng\_state} and \texttt{restore\_rng\_state} store/restore Python/NumPy/Torch RNG states (and CUDA RNG if available). This enables exact continuation of training trajectories from checkpoints.

\paragraph{Checkpoint schema.}
\texttt{save\_checkpoint} stores:
\begin{itemize}
  \item model state dict,
  \item optimizer state dict (optional),
  \item extra metadata (optional),
  \item RNG state,
  \item torch version string.
\end{itemize}
This schema is sufficient for scientific reproducibility and audit trails.

\paragraph{AverageMeter.}
\texttt{AverageMeter} tracks running averages for losses/metrics; it is used to report stable epoch-level summaries rather than noisy per-step values.

\subsection{\texttt{deepgen/models/blocks.py}: Reusable neural building blocks}
\paragraph{SEBlock (channel attention).}
\texttt{SEBlock} implements squeeze-and-excitation gating: global average pooling creates a channel descriptor, then a bottleneck MLP and sigmoid gate produce channel-wise weights that modulate the input. This improves representational efficiency by emphasizing informative channels.

\paragraph{ResidualBlock.}
\texttt{ResidualBlock} provides two conv-bn layers plus an optional SE module and a skip path. When \texttt{downsample=True}, stride=2 is used and the skip path becomes a $1\times 1$ strided conv. This supports deep encoders/decoders with stable gradients.

\paragraph{SelfAttention2d.}
\texttt{SelfAttention2d} computes attention across spatial positions (SAGAN-style). It builds query/key/value projections and uses a residual connection with a learnable scalar \texttt{gamma}, allowing the network to gradually introduce non-local interactions as training stabilizes.

\subsection{\texttt{deepgen/models/classifier.py}: Feature extractor and classifier (LeNet5)}
\paragraph{Purpose.}
\texttt{LeNet5} serves two roles:
(i) a baseline classifier for MNIST-like data, and
(ii) a feature extractor for \texttt{fid\_like} when called with \texttt{return\_features=True}.

\paragraph{Feature interface.}
The model exposes penultimate features (dimension 84) via \texttt{return\_features}. This is the representation used for feature-space evaluation in \texttt{deepgen/metrics.py}. Any reported FID-like score must explicitly state that features are LeNet-based.

\subsection{\texttt{deepgen/models/gan.py}: Conditional WGAN-GP with projection discriminator}
\paragraph{Generator.}
The generator embeds labels and adds them to noise, projects to a $7\times 7$ feature map, upsamples via residual-style blocks, applies self-attention, and outputs $\tanh$-bounded images in $[-1,1]$.

\paragraph{Discriminator (critic).}
The projection discriminator computes pooled features and adds an inner product with a label embedding. This is a standard conditional design that is parameter-efficient and empirically stable.

\paragraph{Gradient penalty.}
\texttt{gradient\_penalty} constructs interpolates $\hat{x}$ and enforces $\|\nabla_{\hat{x}}D(\hat{x},y)\|_2\approx 1$. This is the core WGAN-GP regularizer for Lipschitz control.

\subsection{\texttt{deepgen/models/vae.py}: VAE with VampPrior}
\paragraph{Encoder/decoder.}
The encoder outputs $(\mu,\log\sigma^2)$. The decoder outputs sigmoid pixels in $(0,1)$.

\paragraph{VampPrior pseudo-inputs.}
Pseudo-inputs are learned image-shaped parameters. Sampling selects a pseudo-input, encodes it to get $(\mu,\log\sigma^2)$, samples $z$, and decodes. The KL term is computed against the mixture prior using log-sum-exp, which is numerically stable and aligns with the VampPrior definition.
