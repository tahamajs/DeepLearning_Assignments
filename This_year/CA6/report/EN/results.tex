\subsection{Overview of Exported Artifacts and Traceability Contract}
The evaluation pipeline exports \emph{both} qualitative and quantitative artifacts to guarantee that every claim in this section can be traced to files on disk. We follow a strict ``artifact contract'': for each evaluated pair $(\mathcal{I}_T,\mathcal{I}_Q)$ we export (i) at least one overlay image, and (ii) one row in a per-sample metrics CSV. Dataset-level tables and report figures are derived \emph{only} from these raw exports.

\paragraph{Directory structure.}
Artifacts are stored under:
\begin{itemize}
  \item \textbf{Overlays:} \texttt{../results/overlays/} --- warped template rendered into the photo frame.
  \item \textbf{Metrics:} \texttt{../results/metrics/} --- per-sample and summary CSV/JSON logs.
  \item \textbf{Figures:} \texttt{../results/figures/} --- plots used in this report (histograms, curves, ablations, runtime).
  \item \textbf{Debug (optional):} \texttt{../results/matches/} --- match visualizations, inlier masks, and RANSAC diagnostics.
\end{itemize}

\paragraph{Recommended file naming convention.}
To make provenance unambiguous, filenames should include a sample identifier and key configuration parameters (or a short run hash). For example:
\begin{itemize}
  \item \texttt{overlays/\{id\}\_\{run\_hash\}\_overlay.png}
  \item \texttt{matches/\{id\}\_\{run\_hash\}\_matches.png}, \texttt{matches/\{id\}\_\{run\_hash\}\_inliers.png}
  \item \texttt{metrics/per\_sample.csv}, \texttt{metrics/summary.csv}, \texttt{metrics/config.json}
\end{itemize}
The \texttt{run\_hash} can be computed from the config JSON (e.g., SHA1 of the serialized config) to ensure that artifacts are uniquely tied to a configuration.

\paragraph{Minimum required exported metrics per sample.}
At minimum, each evaluated pair should export one row with:
\begin{itemize}
  \item identifiers: \texttt{sample\_id}, \texttt{template\_path}, \texttt{photo\_path}
  \item matching: \texttt{n\_kp\_T}, \texttt{n\_kp\_Q}, \texttt{n\_matches}, \texttt{n\_inliers}, \texttt{inlier\_ratio}
  \item geometry: \texttt{H\_status} (ok/fail), \texttt{H\_cond} (optional), \texttt{warp\_area\_ratio} (optional)
  \item accuracy (if GT exists): \texttt{MRE}, \texttt{MedRE}, (optional) \texttt{p90\_err}, \texttt{p95\_err}
  \item runtime: \texttt{t\_pre}, \texttt{t\_feat}, \texttt{t\_match}, \texttt{t\_ransac}, \texttt{t\_warp}, \texttt{t\_total} (all in ms)
\end{itemize}
If ground truth is unavailable, the evaluator must explicitly report that MRE/MedRE are not computed and the results are based on proxy metrics (e.g., inlier ratio and overlay inspection).

\subsection{Quantitative Summary (Dataset-Level Aggregates)}
A dataset-level summary is exported as \texttt{../results/metrics/summary.csv}. This table aggregates performance across all evaluated samples under a fixed configuration. To prevent misleading conclusions from heavy-tailed failures, we report robust statistics in addition to means.

\SafeCSVTable{../results/metrics/summary.csv}{Dataset-level summary metrics exported by the evaluation script.}{tab:summary_metrics}

\paragraph{Scientifically correct interpretation of the summary table.}
The summary table should contain (at minimum):
\begin{itemize}
  \item \textbf{Mean reprojection error (MRE):} average geometric error in pixels. Sensitive to failures; can be dominated by outliers.
  \item \textbf{Median reprojection error (MedRE):} robust central tendency. If $\text{MedRE} \ll \text{MRE}$, performance is bimodal or heavy-tailed.
  \item \textbf{Success rate at tolerance $\delta$:} $\Pr(\text{MRE}<\delta)$ (or $\Pr(\text{MedRE}<\delta)$ if specified). Operationally interpretable.
  \item \textbf{Runtime median and P95:} median latency reflects typical performance; P95 captures tail latency critical for deployment.
\end{itemize}

\paragraph{Confidence intervals (recommended).}
If the dataset size is not large, or if you compare multiple configurations, report uncertainty:
\begin{itemize}
  \item \textbf{Bootstrap CIs} for MRE/MedRE and success rate (e.g., 1{,}000 bootstrap resamples of per-sample metrics),
  \item and/or \textbf{multi-seed runs} (if any randomized steps exist) reporting mean$\pm$std across runs.
\end{itemize}
This prevents overclaiming based on a single dataset realization.

\subsection{Qualitative Results: Overlay Inspection Protocol}
Qualitative overlays are the primary sanity check that the estimated homography produces a visually consistent mapping.

% \ResultGraphic{../results/figures/overlay_grid.png}{0.95\linewidth}{Representative overlays: warped template projected onto query photographs. The grid should include a stratified set covering low, median, and high error cases (when GT is available).}

\paragraph{What this figure demonstrates.}
Overlays provide evidence that the mapping is correct in the \emph{image plane}:
\begin{itemize}
  \item \textbf{Correct alignment:} template contours (edges, holes, fiducials) coincide with the photographed part geometry.
  \item \textbf{Local drift:} misalignment increasing toward image corners often indicates insufficient inlier support, poor conditioning of $\mathbf{H}$, or planarity violation.
  \item \textbf{Systematic offset:} consistent displacement across samples strongly suggests a deterministic preprocessing mismatch (scale convention, cropping origin, or inconsistent template normalization).
\end{itemize}

\paragraph{Selection policy for overlays (to avoid cherry-picking).}
To make qualitative reporting scientifically defensible, include at least:
\begin{itemize}
  \item a random subset of samples (fixed random seed),
  \item and the worst-$k$ samples by error (or by lowest inlier ratio if no GT exists),
  \item plus a small set of ``typical'' (median) cases.
\end{itemize}
This ensures that failure modes are visible and not hidden by selection.

\subsection{Alignment Error Distribution and Success Curves}
Distributional reporting is essential because feature-based pipelines typically show heavy-tailed failures.

% \ResultGraphic{../results/figures/reproj_error_hist.png}{0.85\linewidth}{Distribution of per-sample mean reprojection error (pixels). Report median, P90, and P95 in the caption when available.}

\paragraph{What the error histogram demonstrates.}
\begin{itemize}
  \item \textbf{Tight unimodal near zero:} stable, repeatable estimation.
  \item \textbf{Heavy tail:} rare catastrophic misalignments; motivates reporting success rates and worst-case diagnostics.
  \item \textbf{Bimodality:} two regimes (success vs failure), often caused by lighting/clutter/occlusion thresholds or repetitive patterns.
\end{itemize}

\paragraph{Success-vs-tolerance curve (recommended).}
In addition to a single tolerance $\delta$, export a success curve:
\[
S(\delta)=\Pr(\mathrm{MRE}<\delta), \quad \delta\in\{\delta_1,\dots,\delta_m\}.
\]
Plotting $S(\delta)$ reveals whether improvements are meaningful at strict tolerances (precision) or only at loose tolerances (coarse alignment). Export as:
\texttt{../results/figures/success\_curve.png} and \texttt{../results/metrics/success\_curve.csv}.

\subsection{Matching and Geometry Diagnostics (Beyond Error Alone)}
Quantitative alignment error does not fully explain failures. We therefore report match/geometry diagnostics that correlate with success.

\paragraph{Inlier ratio and inlier count.}
Given RANSAC inliers $\mathcal{M}_{\text{in}}$ and matches $\mathcal{M}$, define:
\[
r_{\text{in}}=\frac{|\mathcal{M}_{\text{in}}|}{|\mathcal{M}|}.
\]
Low $|\mathcal{M}_{\text{in}}|$ or low $r_{\text{in}}$ often predicts instability in $\mathbf{H}$.

\paragraph{Homography sanity checks (recommended and loggable).}
Even if RANSAC returns a matrix, it can be numerically or geometrically implausible. Log and optionally threshold:
\begin{itemize}
  \item \textbf{Condition indicator:} a proxy such as $\kappa(\mathbf{H})$ or $\kappa(\mathbf{A})$ from DLT, if available.
  \item \textbf{Warped-corner validity:} warp the template corners and check that a reasonable fraction lie within the photo bounds.
  \item \textbf{Area ratio:} compare area of warped template quadrilateral to original; extreme ratios indicate degenerate solutions.
\end{itemize}
If a sample fails sanity checks, label \texttt{H\_status=fail} and exclude from numeric error summaries (or report separately), while still saving overlays for diagnosis.

\subsection{Runtime and Stage-Wise Profiling}
Runtime must be reported with a clear measurement protocol to avoid misleading numbers.

% \ResultGraphic{../results/figures/runtime_breakdown.png}{0.90\linewidth}{Stage-wise runtime breakdown (ms): preprocessing, feature extraction, matching, RANSAC, warp/overlay. Report median and P95 per stage.}

\paragraph{Measurement protocol (must be stated).}
To produce credible runtime claims:
\begin{itemize}
  \item report hardware and software versions (CPU/GPU, OpenCV build),
  \item use a warm-up phase (discard first $n$ samples) to avoid cold-start bias,
  \item measure per-image latency with consistent resolution policy ($M$ fixed),
  \item report \textbf{median and P95}, not only mean.
\end{itemize}

\paragraph{Interpreting bottlenecks.}
\begin{itemize}
  \item \textbf{Feature extraction dominated:} reduce $M$ or ORB \texttt{nfeatures} / pyramid depth.
  \item \textbf{Matching dominated:} use stricter prefilters (distance percentile), cross-check, or reduce descriptors.
  \item \textbf{RANSAC dominated:} indicates low inlier ratio; improve match quality or ROI-gate to suppress background.
\end{itemize}

\subsection{Ablation Study: Parameter Sensitivity and Stability Regions}
A scientifically defensible system is not only accurate at one setting; it is stable over a neighborhood of parameters.

% \ResultGraphic{../results/figures/ablation_plot.png}{0.90\linewidth}{Ablation results: accuracy (MRE/MedRE or proxy) and success rate vs key parameters. Prefer reporting a stability region rather than a single best point.}

\paragraph{Ablation design (recommended).}
At minimum, sweep:
\begin{itemize}
  \item ORB \texttt{nfeatures} (e.g., $\{500,1000,2000\}$),
  \item RANSAC threshold $\tau$ (pixels) (e.g., $\{2,3,5,8\}$),
  \item match filtering (cross-check on/off; distance percentile).
\end{itemize}
For each setting, report: MedRE, success rate at $\delta$, and runtime median/P95.

\paragraph{Interpreting stability.}
A robust operating regime is characterized by:
\begin{itemize}
  \item a \textbf{plateau} in success rate (insensitive to small perturbations),
  \item low MedRE without extreme $\tau$,
  \item acceptable runtime across the plateau.
\end{itemize}
The scientific goal is to select a configuration from the stability region, not an isolated peak that may overfit the dataset.

\subsection{Failure-Case Analysis and Diagnostics}
We explicitly document failures, since they define the validity domain and guide mitigations.

% {failure_cases}

\paragraph{Failure taxonomy (report as counts).}
Classify failures into categories and report how many occur in the test set:
\begin{itemize}
  \item \textbf{Texture ambiguity / repetition:} geometrically consistent but incorrect homography.
  \item \textbf{Low texture / blur:} too few reliable keypoints, low inlier count.
  \item \textbf{Glare / saturation:} keypoint instability due to suppressed gradients.
  \item \textbf{Occlusion / truncation:} insufficient overlap between template and photo.
  \item \textbf{Planarity violation:} systematic drift that cannot be eliminated by tuning.
\end{itemize}

\paragraph{Evidence-driven mitigations (activate only if metrics improve).}
\begin{itemize}
  \item \textbf{ROI gating:} restrict matching to the part region to suppress background outliers (expected to increase $r_{\text{in}}$).
  \item \textbf{Stricter filtering:} cross-check + distance percentile; optionally enforce spatial dispersion of inliers to reduce local clustering.
  \item \textbf{Illumination normalization:} CLAHE in grayscale if glare/low contrast is the dominant failure driver.
  \item \textbf{Template standardization:} enforce consistent scale/contrast/line thickness to increase descriptor repeatability.
\end{itemize}
A mitigation is accepted only if it increases success rate at the chosen tolerance and reduces tail failures (e.g., lower P95 error), not merely improves the mean.

\subsection{Result Summary: What the Results Establish}
Collectively, the exported artifacts support three scientifically testable claims:

\begin{enumerate}
  \item \textbf{Geometric correctness (within the validity domain):}
  supported by low MedRE/MRE (when GT exists) and visually consistent overlays on a stratified set of samples.

  \item \textbf{Robustness characteristics:}
  supported by error distributions (tail behavior), success-vs-tolerance curves, and explicit failure-case taxonomy with counts.

  \item \textbf{Operational feasibility:}
  supported by median/P95 runtime and stage-wise bottleneck analysis under a fixed resolution policy.
\end{enumerate}
