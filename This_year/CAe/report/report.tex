\section{Q1: Image Captioning}\label{sec:q1}
This section details the problem formulation, preprocessing, model architecture, training, and evaluation.

\subsection{Problem formulation}
Given image $I$, generate a caption $S=(w_1,\dots,w_T)$ maximizing $P(S|I)$. We model
\begin{equation}
P(S|I)=\prod_{t=1}^{T} P(w_t|I,w_{<t}).
\end{equation}
Training minimizes negative log-likelihood with teacher forcing.

\subsection{Data and preprocessing}
Dataset: Flickr/COCO subset (images + Persian captions) supplied with the assignment. Steps:
\begin{enumerate}
  \item Normalization: Unicode normalization and lowercasing.
  \item Cleaning: remove punctuation, preserve emojis, trim whitespace.
  \item Tokenization: whitespace-based tokens; optional subword (BPE) extension available.
  \item Vocabulary: built on training captions; include \texttt{<start>, <end>, <pad>, <unk>}.
\end{enumerate}
We also compute statistics: caption lengths (min, max, mean, median), unique token counts, and the frequency distribution for OOV analysis. Specifically, we generate a histogram of caption lengths, a bar chart of top K most frequent tokens, and analyze the percentage of out-of-vocabulary (OOV) tokens to assess vocabulary coverage. These figures are saved as `fig-captioning-length-hist-*.png/pdf`, `fig-captioning-token-freq-*.png/pdf`, and `fig-captioning-oov-analysis-*.png/pdf` respectively.

\subsection{Model architecture}
\textbf{Encoder:} Pretrained VGG16 features (conv layers) with an adaptive pooling layer to produce a fixed-size spatial feature map $F\in \mathbb{R}^{H\times W\times C}$. We flatten to $A=[a_1,\ldots,a_L], a_i\in\mathbb{R}^D$ where $L=H\cdot W$.

\textbf{Attention:} Additive attention calculates scores:
\begin{align}
 e_{t,i} &= v^\top \tanh(W_a a_i + U_a h_{t-1} + b_a), \\
 \alpha_{t,i} &= \frac{\exp(e_{t,i})}{\sum_j \exp(e_{t,j})}, \\
 c_t &= \sum_i \alpha_{t,i} a_i.
\end{align}

\textbf{Decoder:} LSTMCell takes input $x_t = [E(w_{t-1}); c_t]$, updates $(h_t,c_t)$ and outputs logits via $o_t=\mathrm{softmax}(W_o h_t + b_o)$. Embedding dimension: 300; hidden dim: 512. We initialize $h_0,c_0$ to zeros and optionally learn a projection from encoder pooled features. Specifically, $h_0$ and $c_0$ can be initialized either as zero vectors or as learned projections of the encoder's global feature representation, allowing the decoder to start with context from the image. The latter often aids faster convergence.

\subsection{Training procedure}
Loss: masked cross-entropy ignoring padding tokens:
\begin{equation}
\mathcal{L}= -\sum_{i\in \text{batch}} \sum_{t=1}^{T_i} \log P(w_t^{(i)} | I^{(i)}, w_{<t}^{(i)}).
\end{equation}
Teacher forcing probability is configurable; by default we use full teacher forcing for smoke runs. For full training, we can implement scheduled sampling where teacher forcing probability decays over epochs. Optimization: AdamW with weight decay (e.g., $10^{-5}$), learning-rate scheduling (e.g., ReduceLROnPlateau with patience 5, factor 0.5), and early stopping by validation loss (e.g., patience 10 epochs). Gradient clipping with a maximum norm of 1.0 is applied to prevent exploding gradients. Mixed precision training (FP16 for forward pass, FP32 for loss) is also supported to optimize memory and speed on compatible hardware.

\subsection{Inference}
Greedy decoding is used for baseline generation. Beam search (width 3--5) is implemented and available as an option; we note empirical gains in BLEU for higher-quality beam search outputs. Specifically, beam search explores multiple caption hypotheses at each step, maintaining the top $k$ sequences (where $k$ is the beam width) and expanding them. This typically leads to more grammatically correct and semantically richer captions compared to greedy decoding, which often gets stuck in local optima. We observe that increasing the beam width generally yields higher BLEU scores at the cost of increased computational inference time.

\subsection{Evaluation}
We evaluate using sacreBLEU (BLEU-1..4) for reproducibility and present qualitative examples (GT vs generated). BLEU formula and brevity penalty are computed as in \cite{papineni2002bleu}. In addition to BLEU, we also consider METEOR \cite{banerjee2007meteor} and CIDEr \cite{vedantam2015cider} for a more comprehensive evaluation, as these metrics correlate better with human judgment by incorporating synonymy and document frequency, respectively. Qualitative examples compare ground truth captions against generated captions to illustrate model strengths and common failure modes, saved as `q1_pred_example_*.pdf`.

\section{CLIP-style Contrastive Learning}\label{sec:clip}
\subsection{Model}
The image encoder is a ViT from `timm` (e.g., vit\_small\_patch16\_224) with a projection head: $z_{img}=\mathrm{proj}(f_{vit}(I))$. The text encoder is a lightweight LSTM or small Transformer producing $z_{txt}=\mathrm{proj}(g_{txt}(S))$. Both outputs are L2-normalized.

\subsection{InfoNCE and Temperature}
For a batch of $N$ pairs we compute similarities $s_{ij}=z_{img,i}^\top z_{txt,j}/\tau$, where $\tau$ is a learned scalar temperature. The symmetric loss is the average cross-entropy when matching images to text and text to images \cite{radford2021learning}.

\subsection{Zero-shot and retrieval}
We evaluate retrieval (text->image and image->text) using recall@k (k=1,5,10). For small-scale tests we report recall on held-out sets; larger-scale evaluation is possible when dataset sizes permit.

\section{Q3: LoRA Fine-Tuning}\label{sec:q3}
\subsection{LoRA formulation}
For target weight $W_0\in \mathbb{R}^{d\times k}$ (e.g., query projection), LoRA parameterizes updates as $W=W_0 + BA$ with $B\in\mathbb{R}^{d\times r}, A\in\mathbb{R}^{r\times k}$, where $r\ll \min(d,k)$. During training only $A$ and $B$ (and optionally layer norms) are updated, enabling efficient adaptation.

\subsection{Prompting and evaluation}
We format classification prompts using the course-specified instruction template and fine-tune using LoRA with $r=8, \alpha=32,\mathrm{dropout}=0.1$. Evaluation metrics are classification accuracy and macro-F1; we also provide confusion matrices and sample model outputs.

\section{Q4: Adversarial Attacks and Training}\label{sec:q4}
\subsection{FGSM and PGD}
FGSM (one-step): $x' = x + \epsilon \cdot \mathrm{sign}(\nabla_x \mathcal{L}(\theta, x, y))$. PGD (multi-step) iteratively applies small perturbations and projects back into the allowed $\ell_\infty$ ball. The PGD update rule is:
\begin{align}
x^{t+1}_{adv} &= \mathrm{clip}_{x, \epsilon}(x^t_{adv} + \alpha \cdot \mathrm{sign}(\nabla_x \mathcal{L}(\theta, x^t_{adv}, y))) \\
x^{0}_{adv} &= x
\end{align}
where $\mathrm{clip}_{x, \epsilon}(\cdot)$ projects the perturbed input back into the $\ell_\infty$ ball centered at the original input $x$ with radius $\epsilon$. We analyze the effects of $\epsilon$ and number of iterations $T$ on robustness, and illustrate how increasing these parameters generally leads to stronger attacks and lower robust accuracy.

\subsection{Adversarial training strategy}
We implement on-the-fly PGD adversarial generation during training and compare models trained on clean data, FGSM-augmented data, and PGD-augmented data. We measure robust accuracy under a range of attacks and plot accuracy vs $\epsilon$ curves. Specifically, for each training batch, we can generate adversarial examples using PGD (or FGSM) and then train the model on a mixture of clean and adversarial examples. This process, known as adversarial training, aims to improve the model's robustness against adversarial perturbations. We evaluate the effectiveness of this strategy by measuring the model's accuracy on both clean and adversarially perturbed test sets under varying attack strengths ($\epsilon$ values). The accuracy vs $\epsilon$ curves are critical for visualizing the trade-off between standard accuracy and robust accuracy.

PGD training pseudocode (single batch):
\begin{algorithm}
\caption{PGD adversarial training single-batch inner loop}
\begin{algorithmic}[1]
\State Input batch $(x,y)$, model $\theta$, steps $T$, step-size $\alpha$, eps $\epsilon$
\State $x_{adv} \leftarrow x$
\For{$t=1\dots T$}
  \State $g \leftarrow \nabla_x \mathcal{L}(\theta, x_{adv}, y)$
  \State $x_{adv} \leftarrow \Pi_{\|\cdot - x\|_\infty \le \epsilon}(x_{adv} + \alpha \cdot \mathrm{sign}(g))$
\EndFor
\State Update $\theta$ with loss $\mathcal{L}(\theta, x_{adv}, y)$
\end{algorithmic}
\end{algorithm}

\section{Q1: Image Captioning}
\subsection{Data and Preprocessing}
We use a provided Flickr/COCO subset that includes images and Persian captions. Preprocessing removes punctuation, lowercases text, and separates emojis where applicable. We build a vocabulary from training captions and add four special tokens: \texttt{<start>} (sos) used to signal the start of generation, \texttt{<end>} (eos) to terminate sequences, \texttt{<pad>} used for batch padding, and \texttt{<unk>} to represent out-of-vocabulary tokens.

Tokenization: The provided `Tokenizer` class converts sentences to index sequences and handles punctuation/emoji. We save the tokenizer for inference and reproducibility.

\subsection{Model Architecture}
Encoder: We use a pretrained VGG16 (ImageNet) and remove classification heads, keeping convolutional features. The output feature vector is projected to a 512-dim vector and optionally spatial-pooled to support attention.

Decoder: Our decoder is an LSTMCell-based model with an additive attention mechanism (Bahdanau-style). At each timestep the attention module computes alignment weights between the decoder hidden state and encoder features, producing an attention-weighted encoding concatenated with the input embedding.

The decoder uses embedding size 300 and hidden size 512. Teacher forcing is used in training, where the ground-truth token is provided as input to the next timestep; during inference we perform greedy decoding (top-1) until the \texttt{<end>} token.

\subsection{Training Details and Hyperparameters}
Training uses Cross-Entropy loss (ignoring padding indices). We freeze the encoder feature extractor to accelerate initial experiments and train only the decoder and the projection layer. For smoke runs, we train for a few epochs; for full experiments we recommend at least 30 epochs with early stopping by validation loss.

Representative hyperparameters used in experiments (see Appendix~\ref{appendix:hyper}): learning rate = 1e-3 (AdamW), batch size = 64 (or 32 if memory limited), embedding dim = 300, hidden dim = 512, weight decay = 1e-5.

\subsection{Evaluation}
We evaluate with BLEU-1..4 lexical metrics \cite{papineni2002bleu, post-2018-call} and also produce qualitative samples. BLEU is computed with sacreBLEU for reproducibility. For retrieval-style evaluation (CLIP-style) we compute recall@k when applicable.

\section{Q1.5: CLIP-style Contrastive Learning (Image-Text)}
\subsection{Model and Loss}
Image encoder: a ViT backbone (e.g., `vit_small_patch16_224` from `timm`) with an MLP projection to an embedding dimension (e.g., 256) followed by L2 normalization. Text encoder: a small LSTM or Transformer that outputs a fixed-length vector projected to the same embedding size and normalized. The InfoNCE loss is computed on a batch: for correct pairs similarity is maximized, and incorrect pairs minimized, with logits scaled by a learnable temperature parameter $\tau$. Specifically, for a batch of $N$ image-text pairs $(I_i, S_i)$, the symmetric InfoNCE loss is defined as:
\begin{align}
\mathcal{L}_{img \to txt} &= -\frac{1}{N} \sum_{i=1}^{N} \log \frac{\exp(z_{img,i}^\top z_{txt,i} / \tau)}{\sum_{j=1}^{N} \exp(z_{img,i}^\top z_{txt,j} / \tau)} \\
\mathcal{L}_{txt \to img} &= -\frac{1}{N} \sum_{i=1}^{N} \log \frac{\exp(z_{txt,i}^\top z_{img,i} / \tau)}{\sum_{j=1}^{N} \exp(z_{txt,i}^\top z_{img,j} / \tau)} \\
\mathcal{L}_{total} &= \frac{1}{2}(\mathcal{L}_{img \to txt} + \mathcal{L}_{txt \to img})
\end{align}
where $z_{img,i}$ and $z_{txt,i}$ are the L2-normalized embeddings of the $i$-th image and text, respectively, and $\tau$ is the learnable temperature parameter. This loss encourages high similarity for matched pairs and low similarity for mismatched pairs within a batch.

\subsection{Zero-shot and Retrieval}
We demonstrate zero-shot retrieval by querying with text prompts and ranking images by cosine similarity, reporting Top-1 and Top-5 accuracies on held-out samples.

\section{Q3: LoRA Fine-tuning for Sentiment Analysis}\label{sec:q3}
\subsection{LoRA Formulation and Benefits}
LoRA (Low-Rank Adaptation) is a parameter-efficient fine-tuning technique that addresses the challenge of adapting large pre-trained models to downstream tasks without incurring high computational costs or storage overhead. For a pre-trained weight matrix $W_0 \in \mathbb{R}^{d \times k}$ (e.g., in a query or value projection layer of a Transformer), LoRA proposes to update it by adding a low-rank decomposition $BA$, where $B \in \mathbb{R}^{d \times r}$ and $A \in \mathbb{R}^{r \times k}$, and $r \ll \min(d, k)$. The updated weight matrix becomes $W = W_0 + BA$. During fine-tuning, $W_0$ is kept frozen, and only the low-rank matrices $A$ and $B$ (and optionally bias terms and layer normalization parameters) are trained. This significantly reduces the number of trainable parameters, typically by factors of $10^3$ to $10^4$, making fine-tuning more memory-efficient and faster. The rank $r$ controls the expressiveness of the adaptation; a higher rank allows for more flexibility but increases the number of trainable parameters.

\subsection{Prompting and Evaluation}
We fine-tune `meta-llama/Llama-3.2-1B` on a stratified subset of the Emotion dataset (train=1500, val=50, test=100) using LoRA with $r=8, \alpha=32,\mathrm{dropout}=0.1$. The scaling factor $\alpha$ is used to rescale the updates from $BA$, typically set such that $BA \cdot (\alpha/r)$ is applied. Evaluation metrics include classification accuracy and macro-F1 score, along with confusion matrices and sample model outputs to provide a qualitative assessment of the fine-tuned model's performance on sentiment classification. Prompts are formatted using specific templates provided in the `codes/q3_lora` module, ensuring consistent input to the language model.

\section{Q4: Adversarial Attacks and Adversarial Training}
\subsection{Attack Algorithms}
FGSM (Fast Gradient Sign Method) perturbs inputs in the direction of the sign of the gradient of loss w.r.t input (one-step). PGD (Projected Gradient Descent) performs iterative perturbations constrained to an $\ell_\infty$ ball of radius $\epsilon$, with step size $\alpha$ and $T$ iterations. We implement both and evaluate their effect on model accuracy.

\subsection{Adversarial Training}
We implement adversarial training by generating PGD adversarial examples on-the-fly during each training batch and training on a mixture of clean and adversarial images. We report robust accuracy and compare trade-offs between clean accuracy and robustness.

For example, to test whether Model A's improvement in BLEU-4 over Model B is significant, compute per-sample BLEU (or use corpus-level metric with bootstrap resampling) and apply a two-sided paired t-test or report 95\% bootstrap confidence intervals.

For each failure type we provide illustrative examples saved as annotated images (e.g., `q1_pred_example_failure_01.pdf`) and include suggested mitigations (larger data, stronger attention, or object detectors to ground nouns).

\subsection{Runtime, memory, and model complexity}
We measure training wall-clock time, GPU memory consumption, and parameter counts for each model configuration. Example notes:
\begin{itemize}
  \item VGG16-based encoder + LSTM decoder (decoder params only up to ~10M parameters depending on vocab size); frozen encoder reduces gradient memory substantially.
  \item ViT-small (timm) has N parameters; adding projection head increases parameter count slightly.
  \item Wav2Vec full fine-tuning is memory-intensive; using 16-bit mixed precision and gradient checkpointing helps to fit larger batches.
\end{itemize}
We include a small table of parameter counts and a runtime profile for standard experiments in the supplementary materials.

\subsection{Human evaluation}
Automatic metrics have known limitations. We outline an optional human evaluation protocol: recruit N evaluators, present randomized pairs of (GT, prediction), and collect Likert-scale judgments on relevance, correctness, and fluency. Inter-annotator agreement (Krippendorff's alpha or Cohen's kappa) should be reported.

\subsection{Limitations of the current experiments}
Major limitations include compute resources (limiting full fine-tuning for large models) and dataset size. Additionally, BLEU and related metrics emphasize n-gram overlap and may not capture semantic correctness; hence we encourage combining BLEU with human evaluation and other metrics (CIDEr, METEOR).

\subsection{Recommendations for final experiments}
For a final, publication-ready evaluation, we recommend:
\begin{enumerate}
  \item Running full-scale training for captioning for at least 30--50 epochs with scheduled LR decay and checkpointing.
  \item Running 3--5 independent runs for each major experiment to capture variance and compute confidence intervals.
  \item Performing beam search (beam size 3--5) during inference and comparing beam vs greedy outputs.
  \item Reporting CIDEr and METEOR in addition to BLEU, and providing human evaluation results if possible.
  \item Documenting exact compute used (GPU model, memory, wall time) and making final checkpoints available if licensing permits.
\end{enumerate}

\section{Limitations and Future Work}
This project is constrained by computation availability; fully tuning large models (e.g., ViT or full Wav2Vec fine-tuning, Llama full fine-tuning) requires GPUs/TPUs and longer training times. Future work: explore beam search vs. greedy decoding for captioning, implement CIDEr/METEOR metrics, run larger-scale CLIP pretraining, and conduct user studies for generated captions.
