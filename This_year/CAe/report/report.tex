\section{Question 1: Image Captioning with Attention Mechanisms}
\label{sec:q1}

This section presents a comprehensive implementation of an image captioning system that combines computer vision and natural language processing to generate human-like textual descriptions for images. The system is designed to assist visually impaired individuals and enable automatic image understanding for various applications including content indexing, accessibility tools, and multimedia analysis.

\subsection{Problem Formulation and Mathematical Foundation}
\label{sec:q1_problem}

The image captioning task involves generating a natural language description $S = (w_1, w_2, \dots, w_T)$ given an input image $I$, where the goal is to maximize the conditional probability $P(S|I)$. Following the encoder-decoder paradigm established in neural machine translation, we decompose this probability using the chain rule:

\begin{equation}
P(S|I) = \prod_{t=1}^{T} P(w_t | I, w_{<t})
\end{equation}

where $w_{<t} = (w_1, w_2, \dots, w_{t-1})$ represents all words preceding position $t$, and $T$ is the sequence length. During training, we minimize the negative log-likelihood:

\begin{equation}
\mathcal{L} = -\sum_{t=1}^{T} \log P(w_t | I, w_{<t})
\end{equation}

The challenge lies in effectively encoding visual information and generating coherent, contextually appropriate text sequences.

\subsubsection{Text Preprocessing Pipeline}
\label{sec:q1_text_preprocessing}

The text preprocessing follows a systematic pipeline designed to handle Persian text while preserving semantic content:

\begin{enumerate}[label=\arabic*.]
  \item \textbf{Unicode Normalization:} Convert all text to NFC (Normalization Form Canonical Composition) to ensure consistent character representations and handle equivalent Unicode sequences uniformly.

  \item \textbf{Lowercasing:} Convert all characters to lowercase to reduce vocabulary size and handle case-insensitive semantics, while being mindful of Persian-specific orthographic conventions.

  \item \textbf{Punctuation Handling:} Remove punctuation marks except for sentence-ending periods, which are preserved to maintain sentence boundaries. Persian-specific punctuation (،؛؟) is handled appropriately.

  \item \textbf{Emoji Preservation:} Emojis are treated as special tokens and preserved in the vocabulary, as they can convey important semantic information (e.g., facial expressions, objects).

  \item \textbf{Whitespace Normalization:} Multiple consecutive whitespace characters are collapsed to single spaces, and leading/trailing whitespace is removed.

  \item \textbf{Length Filtering:} Captions shorter than 3 words or longer than 50 words are filtered out to ensure meaningful content and computational efficiency.
\end{enumerate}

\subsubsection{Vocabulary Construction and Special Tokens}
\label{sec:q1_vocabulary}

The vocabulary is constructed exclusively from the training set captions using frequency-based tokenization. Four special tokens are incorporated:

\begin{itemize}
  \item \texttt{<start>} (SOS - Start of Sequence): Signals the beginning of caption generation during training and inference
  \item \texttt{<end>} (EOS - End of Sequence): Indicates caption termination, allowing variable-length output
  \item \texttt{<pad>}: Enables batch processing by padding shorter sequences to match the longest in the batch
  \item \texttt{<unk>} (UNK - Unknown): Handles out-of-vocabulary words during inference, maintaining robustness
\end{itemize}

These special tokens are crucial for:
\begin{itemize}
  \item \textbf{SOS/EOS:} Enabling variable-length sequence generation and proper sequence termination
  \item \textbf{PAD:} Computational efficiency through batch processing without information loss
  \item \textbf{UNK:} Graceful handling of rare words not seen during training
\end{itemize}

\subsection{Tokenizer Implementation}
\label{sec:q1_tokenizer}

The \texttt{Tokenizer} class provides bidirectional text processing:

\subsubsection{Forward Tokenization (Text to Indices)}
\begin{lstlisting}
def text_to_sequence(self, text):
    # Preprocessing pipeline
    text = self.preprocess(text)
    # Word-level tokenization
    tokens = text.split()
    # Convert to indices with UNK handling
    indices = [self.word2idx.get(token, self.word2idx['<unk>'])
               for token in tokens]
    # Add SOS and EOS tokens
    return [self.word2idx['<start>']] + indices + [self.word2idx['<end>']]
\end{lstlisting}

\subsubsection{Reverse Tokenization (Indices to Text)}
\begin{lstlisting}
def sequence_to_text(self, sequence):
    # Remove SOS/EOS/PAD tokens
    tokens = [self.idx2word[idx] for idx in sequence
              if idx not in [self.word2idx['<start>'],
                           self.word2idx['<end>'],
                           self.word2idx['<pad>']]]
    return ' '.join(tokens)
\end{lstlisting}

\subsubsection{Advanced Collate Function}
The \texttt{collate\_fn} implements sophisticated batch processing:
\begin{lstlisting}
def collate_fn(batch):
    # Separate images, captions, lengths
    images, captions, lengths = zip(*batch)

    # Stack images (already transformed)
    images = torch.stack(images)

    # Sort by caption length (for efficient packing)
    lengths = torch.tensor(lengths)
    sorted_indices = torch.argsort(lengths, descending=True)
    images = images[sorted_indices]
    captions = [captions[i] for i in sorted_indices]
    lengths = lengths[sorted_indices]

    # Pad captions to max length in batch
    max_len = max(lengths)
    padded_captions = []
    for caption in captions:
        padding_needed = max_len - len(caption)
        padded = torch.cat([caption, torch.full((padding_needed,),
                        tokenizer.word2idx['<pad>'])])
        padded_captions.append(padded)

    return images, torch.stack(padded_captions), lengths
\end{lstlisting}

\subsection{Model Architecture: Encoder-Decoder with Attention}
\label{sec:q1_architecture}

\subsubsection{Visual Encoder: Pre-trained CNN Feature Extractor}
\label{sec:q1_encoder}

The encoder leverages transfer learning from ImageNet-pretrained models:

\textbf{Architecture Choice:} VGG16 provides rich hierarchical features while being computationally tractable. The final classification layers are removed, retaining the convolutional feature extractor.

\textbf{Freezing Strategy:} The encoder weights are frozen during initial training to:
\begin{itemize}
  \item Leverage pre-trained ImageNet features
  \item Reduce training time and memory requirements
  \item Prevent catastrophic forgetting of learned representations
\end{itemize}

\textbf{Feature Extraction Process:}
\begin{enumerate}
  \item Input image $I \in \mathbb{R}^{3 \times 224 \times 224}$
  \item Convolutional feature extraction through 13 conv layers + 5 max-pooling
  \item Output feature map $F \in \mathbb{R}^{512 \times 14 \times 14}$
  \item Spatial flattening to $A = [a_1, \dots, a_L] \in \mathbb{R}^{L \times D}$ where $L = 196, D = 512$
\end{enumerate}

\textbf{Mathematical Formulation:}
\begin{equation}
F = \phi_{cnn}(I; \theta_{frozen})
\end{equation}
\begin{equation}
A = \text{flatten}(F) \in \mathbb{R}^{196 \times 512}
\end{equation}

\subsubsection{Attention Mechanism: Bahdanau-style Additive Attention}
\label{sec:q1_attention}

The attention mechanism enables the decoder to focus on relevant image regions:

\textbf{Attention Computation:}
\begin{align}
e_{t,i} &= v^\top \tanh(W_a a_i + U_a h_{t-1} + b_a) \\
\alpha_{t,i} &= \frac{\exp(e_{t,i})}{\sum_{j=1}^{L} \exp(e_{t,j})} \\
c_t &= \sum_{i=1}^{L} \alpha_{t,i} a_i
\end{align}

Where:
\begin{itemize}
  \item $h_{t-1} \in \mathbb{R}^{512}$: Previous decoder hidden state
  \item $a_i \in \mathbb{R}^{512}$: $i$-th spatial feature vector
  \item $v, W_a, U_a, b_a$: Learned attention parameters
  \item $\alpha_{t,i}$: Attention weight for position $i$ at timestep $t$
  \item $c_t \in \mathbb{R}^{512}$: Context vector (weighted sum of features)
\end{itemize}

\textbf{Advantages over Standard Decoder:}
\begin{itemize}
  \item \textbf{Dynamic Focus:} Attention weights change per timestep, allowing different regions to influence different words
  \item \textbf{Interpretability:} Attention maps reveal which image regions contribute to each generated word
  \item \textbf{Variable Length:} Handles images of different sizes and focuses on relevant content
  \item \textbf{Reduced Information Loss:} Avoids fixed-dimensional global pooling
\end{itemize}

\subsubsection{LSTM Decoder with Attention Integration}
\label{sec:q1_decoder}

The decoder combines word embeddings, attention context, and recurrent state:

\textbf{Input Formation:}
\begin{equation}
x_t = [E(w_{t-1}); c_t] \in \mathbb{R}^{300 + 512 = 812}
\end{equation}

\textbf{LSTM Update:}
\begin{align}
i_t &= \sigma(W_i x_t + U_i h_{t-1} + b_i) \\
f_t &= \sigma(W_f x_t + U_f h_{t-1} + b_f) \\
o_t &= \sigma(W_o x_t + U_o h_{t-1} + b_o) \\
\tilde{c}_t &= \tanh(W_c x_t + U_c h_{t-1} + b_c) \\
c_t &= f_t \odot c_{t-1} + i_t \odot \tilde{c}_t \\
h_t &= o_t \odot \tanh(c_t)
\end{align}

\textbf{Output Generation:}
\begin{equation}
p_t = \text{softmax}(W_p h_t + b_p) \in \mathbb{R}^{|V|}
\end{equation}

\textbf{Initialization Strategies:}
\begin{itemize}
  \item \textbf{Zero Initialization:} $h_0 = 0, c_0 = 0$
  \item \textbf{Learned Projection:} $h_0 = W_{init} \cdot \bar{a}, c_0 = 0$ where $\bar{a} = \frac{1}{L} \sum a_i$
  \item \textbf{Attention-based:} $h_0 = c_0 = W_{attn} \cdot c_{init}$ using initial attention context
\end{itemize}

\subsection{Training Methodology and Optimization}
\label{sec:q1_training}

\subsubsection{Loss Function: Masked Cross-Entropy}
\label{sec:q1_loss}

Training minimizes the negative log-likelihood with masking for padded tokens:

\begin{equation}
\mathcal{L} = -\sum_{i=1}^{B} \sum_{t=1}^{T_i} m_{i,t} \log p_t^{(i)}(w_t^{(i)})
\end{equation}

Where:
\begin{itemize}
  \item $B$: Batch size
  \item $T_i$: Actual length of $i$-th caption (excluding padding)
  \item $m_{i,t} = 1$ if $w_t^{(i)} \neq \text{<pad>}$, else $0$
  \item $p_t^{(i)}$: Output probability distribution at timestep $t$ for sample $i$
\end{itemize}

\subsubsection{Teacher Forcing Strategy}
\label{sec:q1_teacher_forcing}

\textbf{Training Phase:} Uses ground truth tokens as input:
\begin{equation}
x_t = [E(w_t^{\text{true}}); c_t]
\end{equation}

\textbf{Inference Phase:} Uses model's own predictions:
\begin{equation}
x_t = [E(\arg\max p_{t-1}); c_t]
\end{equation}

\textbf{Scheduled Sampling:} Teacher forcing probability decays:
\begin{equation}
p_{tf}(\text{epoch}) = \max(0, p_0 - k \cdot \text{epoch})
\end{equation}

\subsubsection{Optimization Configuration}
\label{sec:q1_optimization}

\textbf{Optimizer:} AdamW with $\beta_1 = 0.9, \beta_2 = 0.999, \epsilon = 10^{-8}$

\textbf{Learning Rate Schedule:}
\begin{itemize}
  \item Initial LR: $3 \times 10^{-4}$
  \item Warmup: 1000 steps with linear increase
  \item Decay: ReduceLROnPlateau with factor 0.5, patience 3
\end{itemize}

\textbf{Regularization:}
\begin{itemize}
  \item Weight Decay: $10^{-5}$
  \item Gradient Clipping: $\max\|\nabla\| = 1.0$
  \item Dropout: 0.5 in decoder classifier
\end{itemize}

\subsubsection{Training Loop Implementation}
\label{sec:q1_training_loop}

The training procedure includes:
\begin{enumerate}
  \item \textbf{Data Loading:} Efficient batch processing with padding
  \item \textbf{Forward Pass:} Encoder feature extraction + attention-based decoding
  \item \textbf{Loss Computation:} Masked cross-entropy with teacher forcing

  \item \textbf{Monitoring:} Loss tracking, learning rate scheduling, early stopping

\end{enumerate}

\subsection{Inference and Caption Generation}
\label{sec:q1_inference}

\subsubsection{Greedy Decoding}
\label{sec:q1_greedy}

Simple autoregressive generation:
\begin{lstlisting}
def greedy_decode(encoder, decoder, image, tokenizer, max_len=50):
    # Encode image
    features = encoder(image)

    # Initialize decoder state
    h, c = decoder.init_hidden(1)
    start_token = tokenizer.word2idx['<start>']
    input_token = torch.tensor([[start_token]])

    caption = []

    for _ in range(max_len):
        # Get attention and output
        output, attention = decoder(input_token, features, h, c)

        # Get next token (greedy)
        next_token = output.argmax(dim=-1).item()

        if next_token == tokenizer.word2idx['<end>']:
            break

        caption.append(next_token)
        input_token = torch.tensor([[next_token]])

    return tokenizer.sequence_to_text(caption)
\end{lstlisting}

\subsubsection{Beam Search Implementation}
\label{sec:q1_beam_search}

Advanced decoding with multiple hypotheses:
\begin{itemize}
  \item Maintain top-$k$ sequences at each step
  \item Score sequences with log-probability normalization
  \item Length normalization to prevent bias toward shorter sequences
  \item Early stopping when EOS is reached for all beams
\end{itemize}

\textbf{Scoring Function:}
\begin{equation}
\text{score} = \frac{1}{|S|^\alpha} \sum_{t=1}^{|S|} \log p_t(w_t | w_{<t})
\end{equation}

Where $\alpha = 0.7$ provides length normalization.

\textbf{BLEU Scores:} N-gram precision with brevity penalty:

\begin{equation}
\text{BLEU-n} = BP \cdot \exp\left(\sum_{i=1}^{n} \frac{1}{n} \log p_i\right)
\end{equation}

Where $BP = \min(1, e^{1 - r/c})$ is the brevity penalty, $r$ is reference length, $c$ is candidate length.

\textbf{Limitations of Automatic Metrics:} BLEU and similar n-gram overlap metrics capture surface similarity but miss semantic correctness (e.g., correct attributes with different wording). We therefore report human judgments and recommend adding CIDEr and SPICE in follow-up runs for a richer evaluation.

\begin{itemize}
  \item Missing objects: Model omits secondary objects
  \item Attribute confusion: Wrong colors or sizes
  \item Spatial errors: Incorrect object relationships
  \item Verb tense issues: Grammatical inconsistencies
\end{itemize}

\subsection{Question 1.4-1.5: Contrastive Language-Image Pre-training (CLIP)}
\label{sec:q1_clip}

\subsubsection{Problem Formulation}
\label{sec:q1_clip_problem}

CLIP learns a joint embedding space for images and text where semantically similar pairs have high cosine similarity. The objective is zero-shot transfer to downstream tasks.

\subsubsection{Architecture: Vision Transformer + Text Encoder}
\label{sec:q1_clip_architecture}

\textbf{Vision Encoder (ViT):}
\begin{itemize}
  \item Input: $224 \times 224$ RGB images
  \item Patch size: $16 \times 16$ (196 patches)
  \item Embedding dimension: 768
  \item Transformer layers: 12
  \item Output: [CLS] token embedding
\end{itemize}

\textbf{Text Encoder:}
\begin{itemize}
  \item Input: 77-token sequences (BPE encoded)
  \item Embedding dimension: 512
  \item Transformer layers: 12
  \item Output: [EOS] token embedding
\end{itemize}

\subsubsection{InfoNCE Loss for Contrastive Learning}
\label{sec:q1_clip_loss}

For batch size $N$ with $N$ image-text pairs:

\begin{align}
\mathcal{L}_{img \to txt} &= -\frac{1}{N} \sum_{i=1}^{N} \log \frac{\exp(z_{img,i} \cdot z_{txt,i} / \tau)}{\sum_{j=1}^{N} \exp(z_{img,i} \cdot z_{txt,j} / \tau)} \\
\mathcal{L}_{txt \to img} &= -\frac{1}{N} \sum_{i=1}^{N} \log \frac{\exp(z_{txt,i} \cdot z_{img,i} / \tau)}{\sum_{j=1}^{N} \exp(z_{txt,i} \cdot z_{img,j} / \tau)} \\
\mathcal{L}_{CLIP} &= \frac{1}{2} (\mathcal{L}_{img \to txt} + \mathcal{L}_{txt \to img})
\end{align}

Where $\tau = 0.07$ is the learned temperature parameter.

\subsubsection{Zero-Shot Classification}
\label{sec:q1_clip_zero_shot}

Zero-shot classification uses text embeddings of class descriptions:

\begin{enumerate}
  \item Create text prompts: "a photo of a [class]"
  \item Compute text embeddings for all classes
  \item For test image, find class with highest cosine similarity to image embedding
\end{enumerate}

\section{CLIP-style Contrastive Learning}\label{sec:clip}
\subsection{Model}
The image encoder is a ViT from `timm` (e.g., vit\_small\_patch16\_224) with a projection head: $z_{img}=\mathrm{proj}(f_{vit}(I))$. The text encoder is a lightweight LSTM or small Transformer producing $z_{txt}=\mathrm{proj}(g_{txt}(S))$. Both outputs are L2-normalized.

\subsection{InfoNCE and Temperature}
For a batch of $N$ pairs we compute similarities $s_{ij}=z_{img,i}^\top z_{txt,j}/\tau$, where $\tau$ is a learned scalar temperature. The symmetric loss is the average cross-entropy when matching images to text and text to images \cite{radford2021learning}.

\subsection{Zero-shot and retrieval}
We evaluate retrieval (text->image and image->text) using recall@k (k=1,5,10). For small-scale tests we report recall on held-out sets; larger-scale evaluation is possible when dataset sizes permit.

The system classifies urban sounds into ten categories, enabling applications in smart city monitoring, acoustic surveillance, and audio-based context awareness.

\subsection{Problem Formulation and Challenges}
\label{sec:q2_problem}

Urban sound classification involves mapping raw audio waveforms to semantic categories. Unlike speech recognition or music classification, urban sounds are:
\begin{itemize}
  \item \textbf{Environmentally variable:} Affected by background noise, distance, and acoustic conditions
  \item \textbf{Temporally diverse:} Events can be instantaneous (horn) or sustained (traffic)
  \item \textbf{Spectrally complex:} Wide frequency ranges with harmonic and percussive components
  \item \textbf{Class imbalanced:} Some sound types occur more frequently than others
\end{itemize}

The mathematical formulation seeks to learn a function $f: \mathbb{R}^{T \times C} \to \{1, \dots, K\}$ that maps audio waveforms to class labels, where $T$ is the time dimension, $C$ is the number of channels, and $K=10$ is the number of urban sound classes.

X[k,m] &= \sum_{n=0}^{N-1} x[n+mH] w[n] e^{-j 2\pi k n / N} \\

\begin{itemize}

  \item Output: 49×512 feature sequence (for 4-second input)
  \item Stride: Total downsampling factor of 320
\end{itemize}

\textbf{Contextual Representations:} 12 transformer layers:
\begin{itemize}
  \item Hidden dimension: 768
  \item Attention heads: 12
  \item Feed-forward dimension: 3,072
  \item Layer normalization and residual connections
\end{itemize}

\subsubsection{Pre-training Objectives}
\label{sec:q2_wav2vec_pretraining}

\textbf{Contrastive Loss:} Distinguishes true quantized targets from distractors:
\begin{equation}
\mathcal{L}_m = -\log \frac{\exp(\mathbf{c}_t^\top \mathbf{q}_t / \kappa)}{\exp(\mathbf{c}_t^\top \mathbf{q}_t / \kappa) + \sum_{q' \in Q_t} \exp(\mathbf{c}_t^\top q' / \kappa)}
\end{equation}

\textbf{Diversity Loss:} Encourages codebook usage:
\begin{equation}
\mathcal{L}_d = \frac{1}{|V|} \sum_{g \in V} (p_g - \frac{1}{|V|})^2
\end{equation}

\subsubsection{HuBERT: Masked Prediction and Clustering}
\label{sec:q2_hubert}

HuBERT (\textbf{H}idden-\textbf{u}nit \textbf{B}ERT) takes a different self-supervised approach compared to Wav2Vec 2.0. Instead of using a contrastive objective with negative examples, HuBERT formulates pretraining as a masked prediction task where the model predicts discrete cluster IDs for masked time-steps.

\textbf{Key differences from Wav2Vec 2.0:}
\begin{itemize}
  \item \textbf{Objective:} HuBERT uses a masked prediction loss (similar to BERT) where the target for each masked frame is a pseudo-label (cluster ID) obtained from an offline clustering step.
  \item \textbf{No explicit negatives:} Unlike contrastive losses that require distractor negatives sampled from the batch or memory bank, HuBERT learns by predicting cluster assignments and therefore avoids large negative sets.
  \item \textbf{Clustering Role:} An offline clustering (e.g., K-Means) is performed on low-level features or intermediate representations to produce a finite set of discrete targets. These cluster IDs act as pseudo-labels that the model learns to predict for masked positions.
\end{itemize}

\textbf{Masked Prediction Loss (HuBERT-style):}
\begin{equation}
\mathcal{L}_{hubert} = -\sum_{t \in \mathcal{M}} \log p(c_t \mid \mathbf{h}_{\neg \mathcal{M}})
\end{equation}
where $\mathcal{M}$ is the set of masked time steps, $c_t$ is the cluster ID target for time $t$, and $\mathbf{h}_{\neg \mathcal{M}}$ denotes model representations computed from unmasked inputs.

\textbf{Practical notes:}
\begin{itemize}
  \item The clustering step can be iterated: initial clusters on MFCCs or shallow features, then recluster using internal representations for improved targets.
  \item HuBERT is particularly effective at learning phonetic and acoustic units without transcripts and is complementary to contrastive methods.
\end{itemize}

\subsubsection{Fine-tuning Strategies}
\label{sec:q2_wav2vec_finetuning}

\textbf{Three Experimental Regimes:}

\begin{enumerate}[label=\arabic*.]
  \item \textbf{Freeze All:} Only train classification head
     \begin{itemize}
       \item Wav2Vec backbone frozen
       \item Linear classifier trained on extracted features
       \item Fast training, limited adaptation
     \end{itemize}

  \item \textbf{Partial Freeze:} Fine-tune upper layers
     \begin{itemize}
       \item Freeze first 6 transformer layers
       \item Fine-tune last 6 layers + classifier
       \item Balance between adaptation and stability
     \end{itemize}

  \item \textbf{Full Fine-tuning:} End-to-end training
     \begin{itemize}
       \item All parameters trainable
       \item Maximum adaptation capability
       \item Risk of overfitting, requires regularization
     \end{itemize}
\end{enumerate}

\subsection{Question 3: LoRA Fine-tuning}
\label{sec:q3}

This section presents the implementation of Low-Rank Adaptation (LoRA) for parameter-efficient fine-tuning of large language models. LoRA enables fine-tuning massive models with minimal parameter updates by learning low-rank adaptations to pre-trained weights.

\subsubsection{LoRA Mathematical Foundation}
\label{sec:q3_lora_theory}

\textbf{Parameter-Efficient Fine-tuning Problem:}
Traditional fine-tuning updates all parameters $\theta_0 \in \mathbb{R}^d$ to $\theta_0 + \Delta\theta$. For large models (d > 10^9), this is computationally expensive.

\textbf{LoRA Solution:}
Instead of updating all parameters, LoRA constrains $\Delta\theta$ to a low-rank subspace:
\begin{equation}
\Delta\theta = B A, \quad B \in \mathbb{R}^{d \times r}, \quad A \in \mathbb{R}^{r \times k}
\end{equation}

Where $r \ll \min(d, k)$ is the rank parameter, significantly reducing trainable parameters.

\subsubsection{LoRA Implementation Details}
\label{sec:q3_lora_implementation}

\textbf{Forward Pass:}
For a pre-trained weight matrix $W_0 \in \mathbb{R}^{d \times k}$:
\begin{equation}
W = W_0 + B A
\end{equation}

During inference, this becomes:
\begin{equation}
h = W_0 x + B (A x) = W_0 x + B (\tilde{x})
\end{equation}

\textbf{Training:}
Only $A$ and $B$ are trained, $W_0$ remains frozen:
\begin{equation}
\mathcal{L}_{LoRA} = \mathcal{L}(W_0 + B A)
\end{equation}

\subsection{Question 3.1: LoRA Formulation and Benefits}
\label{sec:q3_lora_theory}

\textbf{Parameter-Efficient Fine-tuning Problem:}
Traditional fine-tuning updates all parameters $\theta_0 \in \mathbb{R}^d$ to $\theta_0 + \Delta\theta$. For large models (d > 10^9), this becomes computationally expensive and memory-intensive.

\textbf{LoRA Solution:}
Instead of updating all parameters, LoRA constrains $\Delta\theta$ to a low-rank subspace:
\begin{equation}
\Delta\theta = B A, \quad B \in \mathbb{R}^{d \times r}, \quad A \in \mathbb{R}^{r \times k}
\end{equation}

Where $r \ll \min(d, k)$ is the rank parameter, significantly reducing trainable parameters from $d \times k$ to $r \times (d + k)$.

\subsubsection{LoRA Forward Pass and Training}
\label{sec:q3_lora_forward}

\textbf{Mathematical Formulation:}
For a pre-trained weight matrix $W_0 \in \mathbb{R}^{d \times k}$:
\begin{equation}
W = W_0 + \frac{\alpha}{r} B A
\end{equation}

Where $\alpha$ is a scaling hyperparameter and $r$ is the rank. The forward pass becomes:
\begin{equation}
h = W_0 x + \frac{\alpha}{r} B (A x) = W_0 x + \frac{\alpha}{r} B \tilde{x}
\end{equation}

\textbf{Training Strategy:}
Only $A$ and $B$ are trained, while $W_0$ remains frozen:
\begin{equation}
\mathcal{L}_{LoRA} = \mathcal{L}(W_0 + \frac{\alpha}{r} B A)
\end{equation}

This reduces the trainable parameters by factors of $10^3$ to $10^4$ for large models.

\subsubsection{LoRA Configuration and Hyperparameters}
\label{sec:q3_lora_config}

\textbf{LoRA Hyperparameters:}
\begin{itemize}
  \item \textbf{Rank $r$}: Controls adaptation capacity (typically 8, 16, 32, 64)
  \item \textbf{Scaling $\alpha$}: Stabilizes training (typically 16, 32)
  \item \textbf{Dropout}: Prevents overfitting of LoRA layers
  \item \textbf{Target Modules}: Which transformer layers to adapt (attention, MLP)
\end{itemize}

\textbf{Integration with Quantization:}
LoRA combines effectively with model quantization:
\begin{itemize}
  \item Quantize $W_0$ to 4-bit/8-bit for memory efficiency
  \item Train LoRA adapters on quantized weights
  \item Deploy quantized model + trained LoRA adapters
\end{itemize}

\subsubsection{Implementation Architecture}
\label{sec:q3_lora_implementation}

\textbf{LoRA Layer Structure:}
```python
class LoRALayer(nn.Module):
    def __init__(self, weight, rank, alpha):
        super().__init__()
        self.weight = weight  # Frozen original weight
        self.rank = rank
        self.alpha = alpha
        
        # LoRA parameters
        self.lora_A = nn.Parameter(torch.randn(rank, weight.shape[1]))
        self.lora_B = nn.Parameter(torch.zeros(weight.shape[0], rank))
        
        # Scaling factor
        self.scaling = alpha / rank
        
    def forward(self, x):
        # Original computation
        out = F.linear(x, self.weight)
        
        # LoRA adaptation
        lora_out = F.linear(x, self.lora_A.t())
        lora_out = F.linear(lora_out, self.lora_B.t())
        
        return out + self.scaling * lora_out
```

\end{itemize}

\textbf{Training recipe and practical tips:}
\begin{itemize}
  \item Use an 8-bit optimizer (bitsandbytes AdamW8bit) to reduce memory footprint when training LoRA adapters on large models.
  \item Warmup for a small number of steps (e.g., 100) and use a cosine or linear LR schedule; typical LR for LoRA adapters is in [1e-4, 5e-4] depending on batch size.
  \item Use gradient accumulation to increase effective batch size when GPU memory is limited.
  \item Monitor adapter-specific metrics: track trainable parameter norm and adapter gradients to detect collapsed adapters early.
\end{itemize}

\textbf{Saving and merging adapters:} After training, `peft_model.save_pretrained(out_dir)` stores only the adapter weights and config. To create a single deployable model, use `peft_model.merge_and_unload()` (or the PEFT utilities to merge into the base model) producing a merged checkpoint for inference.

\textbf{Hyperparameter tuning guidelines:}
\begin{itemize}
  \item Try ranks r \in \{4,8,16,32\} and evaluate the accuracy vs parameter trade-off.
  \item Set `lora_alpha` = r by default and tune if training is unstable.
  \item Apply dropout (0.05--0.2) to prevent overfitting on small instruction-tuning datasets.
\end{itemize}

\textbf{Deployment considerations:}
\begin{itemize}
  \item For low-latency inference, merge adapters into the base model if you do not need runtime adapter switching.
  \item LoRA adapters are lightweight (tens of MB), enabling shipping multiple task adapters alongside a single base model for multi-domain inference.
  \item Quantization (4-bit/8-bit) is compatible with LoRA if the base model weights are quantized and adapters remain in FP16/FP32 for stability.
\end{itemize}

\textbf{Safety and bias considerations:} Instruction-tuning datasets must be carefully curated to avoid amplifying harmful or biased behaviors. We recommend human review of generated outputs and the use of safety filters where appropriate.

\section{Question 4: Adversarial Attacks and Robust Training}
\label{sec:q4}

This section presents a comprehensive analysis of adversarial attacks and defense strategies for deep neural networks. We implement and evaluate multiple attack algorithms, analyze their effectiveness, and develop robust training techniques to improve model resilience against adversarial perturbations.

\subsection{Adversarial Threat Model and Mathematical Foundation}
\label{sec:q4_threat_model}

\subsubsection{Adversarial Examples Definition}
\label{sec:q4_definition}

An adversarial example is a perturbed input $x_{adv}$ that causes a model $f$ to misclassify, while remaining imperceptible to humans:

\begin{equation}
x_{adv} = x + \delta, \quad \|\delta\|_p \leq \epsilon, \quad f(x) = y, \quad f(x_{adv}) \neq y
\end{equation}

Where:
\begin{itemize}
  \item $x$: Original input
  \item $\delta$: Perturbation (adversarial noise)
  \item $\epsilon$: Maximum perturbation magnitude
  \item $p$: Norm type ($\ell_\infty$, $\ell_2$, $\ell_0$)
  \item $f$: Target model
  \item $y$: True label
\end{itemize}

\subsubsection{Threat Models}
\label{sec:q4_threat_models}

\textbf{White-box Attacks:} Complete knowledge of model architecture, parameters, and gradients
\textbf{Black-box Attacks:} Limited model information, query access only
\textbf{Transfer Attacks:} Train surrogate model, transfer adversarial examples

\subsubsection{Attack Goals}
\label{sec:q4_attack_goals}

\begin{enumerate}[label=\arabic*.]
  \item \textbf{Untargeted Attacks:} Any misclassification (most common)
  \item \textbf{Targeted Attacks:} Force specific wrong prediction
  \item \textbf{Universal Attacks:} Single perturbation affecting multiple inputs
\end{enumerate}

\subsection{Fast Gradient Sign Method (FGSM)}
\label{sec:q4_fgsm}

\subsubsection{Mathematical Formulation}
\label{sec:q4_fgsm_math}

FGSM generates adversarial examples using first-order gradients:

\begin{equation}
x_{adv} = x + \epsilon \cdot \sign(\nabla_x \mathcal{L}(\theta, x, y))
\end{equation}

Where:
\begin{itemize}
  \item $\nabla_x \mathcal{L}(\theta, x, y)$: Gradient of loss w.r.t. input
  \item $\sign(\cdot)$: Sign function (element-wise)
  \item $\epsilon$: Step size controlling perturbation magnitude
\end{itemize}

\subsubsection{Algorithm Implementation}
\label{sec:q4_fgsm_algorithm}

\begin{algorithm}[H]
\caption{FGSM Attack}
\begin{algorithmic}[1]
\Require Model $f$, input $x$, label $y$, perturbation budget $\epsilon$
\State Compute loss $\mathcal{L} = \ell(f(x), y)$
\State Compute gradient $g = \nabla_x \mathcal{L}$
\State Generate perturbation $\delta = \epsilon \cdot \sign(g)$
\State Create adversarial example $x_{adv} = x + \delta$
\State Clip to valid range: $x_{adv} = \clip(x_{adv}, x_{min}, x_{max})$
\Ensure $x_{adv}$
\end{algorithmic}
\end{algorithm}

\subsubsection{FGSM Properties and Limitations}
\label{sec:q4_fgsm_properties}

\textbf{Advantages:}
\begin{itemize}
  \item Computationally efficient (single backward pass)
  \item Easy to implement and understand
  \item Good baseline for evaluating robustness
\end{itemize}

\textbf{Limitations:}
\begin{itemize}
  \item May not find optimal perturbations
  \item Sensitive to gradient masking
  \item Can be defended by gradient obfuscation
\end{itemize}

\subsection{Projected Gradient Descent (PGD)}
\label{sec:q4_pgd}

\subsubsection{Mathematical Foundation}
\label{sec:q4_pgd_math}

PGD is an iterative version of FGSM with projection onto the $\ell_\infty$ ball:

\begin{align}
x^{t+1}_{adv} &= \Pi_{x,\epsilon}(x^t_{adv} + \alpha \cdot \sign(\nabla_x \mathcal{L}(\theta, x^t_{adv}, y))) \\
x^0_{adv} &= x + \eta, \quad \eta \sim \mathcal{U}(-\epsilon, \epsilon)
\end{align}

Where $\Pi_{x,\epsilon}(\cdot)$ projects onto the $\ell_\infty$ ball centered at $x$ with radius $\epsilon$.

\subsubsection{Algorithm Details}
\label{sec:q4_pgd_algorithm}

\begin{algorithm}[H]
\caption{Projected Gradient Descent (PGD) Attack}
\begin{algorithmic}[1]
\Require Model $f$, input $x$, label $y$, $\epsilon$, $\alpha$, $T$
\State Initialize $x^0_{adv} \leftarrow x + \mathcal{U}(-\epsilon, \epsilon)$
\For{$t = 0$ to $T-1$}
  \State Compute loss $\mathcal{L}^t = \ell(f(x^t_{adv}), y)$
  \State Compute gradient $g^t = \nabla_{x^t_{adv}} \mathcal{L}^t$
  \State Update: $x^{t+1}_{adv} \leftarrow x^t_{adv} + \alpha \cdot \sign(g^t)$
  \State Project: $x^{t+1}_{adv} \leftarrow \Pi_{x,\epsilon}(x^{t+1}_{adv})$
\EndFor
\Ensure $x^T_{adv}$
\end{algorithmic}
\end{algorithm}

\subsubsection{Convergence and Optimization}
\label{sec:q4_pgd_convergence}

PGD converges to locally optimal adversarial examples:
\begin{itemize}
  \item \textbf{Step Size ($\alpha$):} Controls update magnitude per iteration
  \item \textbf{Iterations ($T$):} More iterations find stronger adversaries
  \item \textbf{Random Initialization:} Improves chance of finding strong attacks
  \item \textbf{Projection:} Ensures constraint satisfaction
\end{itemize}

\subsection{Carlini-Wagner (CW) Attack}
\label{sec:q4_cw}

\subsubsection{Optimization-based Attack}
\label{sec:q4_cw_math}

CW formulates adversarial attack as an optimization problem:

\begin{mini}
{\delta}{\|\delta\|_2^2 + c \cdot f(x + \delta)}
{\label{eq:cw_optimization}}{}
\end{mini}

Where:
\begin{itemize}
  \item $f(z) = \max(\max_{j \neq y} Z_j - Z_y, -\kappa)$ enforces misclassification
  \item $c > 0$ balances perturbation size vs. attack success
  \item $\kappa$ controls confidence in misclassification
\end{itemize}

\subsubsection{CW vs. Gradient-based Attacks}
\label{sec:q4_cw_comparison}

\textbf{CW Advantages:}
\begin{itemize}
  \item Finds minimal perturbations
  \item High success rate even against defenses
  \item Works with any differentiable model
\end{itemize}

\textbf{CW Disadvantages:}
\begin{itemize}
  \item Computationally expensive
  \item Requires hyperparameter tuning
  \item May be overkill for many applications
\end{itemize}

\subsection{Attack Evaluation and Metrics}
\label{sec:q4_evaluation}

\subsubsection{Attack Success Metrics}
\label{sec:q4_attack_metrics}

\textbf{Attack Success Rate (ASR):}
\begin{equation}
ASR = \frac{1}{|D_{test}|} \sum_{(x,y) \in D_{test}} \mathbb{I}[f(x_{adv}) \neq y \land f(x) = y]
\end{equation}

\textbf{Robust Accuracy (RA):}
\begin{equation}
RA = \frac{1}{|D_{test}|} \sum_{(x,y) \in D_{test}} \mathbb{I}[f(x_{adv}) = y]
\end{equation}

\textbf{Average Perturbation Magnitude:}
\begin{equation}
\delta_{avg} = \frac{1}{|D_{test}|} \sum_{(x,y) \in D_{test}} \|\delta\|_p
\end{equation}

  \item When proposing new defenses, include adaptive attacks tailored to the defense to avoid gradient-masking artifacts.
\end{itemize}

\subsubsection{Perturbation Analysis}
\label{sec:q4_perturbation_analysis}

\textbf{Perceptibility Threshold:}
\begin{itemize}
  \item $\epsilon = 2/255 \approx 0.78\%$ pixel change: Barely perceptible
  \item $\epsilon = 8/255 \approx 3.14\%$ pixel change: Clearly visible artifacts
  \item $\epsilon = 16/255 \approx 6.27\%$ pixel change: Obvious perturbations
\end{itemize}

\textbf{Attack Transferability:}
\begin{itemize}
  \item FGSM attacks transfer well between similar architectures
  \item PGD attacks are less transferable but more powerful
  \item Ensemble attacks improve transfer success rates
\end{itemize}

\subsection{Adversarial Training Defense}
\label{sec:q4_adversarial_training}

\subsubsection{Adversarial Training Formulation}
\label{sec:q4_adv_training_math}

Adversarial training augments the training objective:

\begin{equation}
\theta^* = \arg\min_\theta \mathbb{E}_{(x,y) \sim D} [\max_{\|\delta\|_\infty \leq \epsilon} \mathcal{L}(\theta, x + \delta, y)]
\end{equation}

In practice, we use a relaxed version with PGD-generated adversaries:

\begin{equation}
\mathcal{L}_{adv}(\theta) = \mathbb{E}_{(x,y) \sim D} \mathcal{L}(\theta, x + \delta^*(x,y))
\end{equation}

Where $\delta^*(x,y)$ is generated using PGD attack.

\subsubsection{Training Strategies}
\label{sec:q4_training_strategies}

\textbf{1. Standard Adversarial Training:}
\begin{itemize}
  \item Generate adversarial examples on-the-fly
  \item Train on mixture of clean and adversarial examples
  \item Balance ratio: 50\% clean, 50\% adversarial
\end{itemize}

\textbf{2. Curriculum Adversarial Training:}
\begin{itemize}
  \item Start with small $\epsilon$, gradually increase
  \item Allows model to learn robust features incrementally
  \item Reduces training instability
\end{itemize}

\textbf{3. Multi-step Adversarial Training:}
\begin{itemize}
  \item Use different attack strengths during training
  \item Improves robustness across perturbation magnitudes
  \item More computationally expensive
\end{itemize}

\subsubsection{Implementation Details}
\label{sec:q4_adv_training_impl}

\textbf{Training Loop with Adversarial Examples:}

\begin{algorithm}[H]
\caption{Adversarial Training Loop}
\begin{algorithmic}[1]
\Require Model $\theta$, dataset $D$, $\epsilon$, $\alpha$, $T$
\For{each epoch}
  \For{each batch $(x, y)$ in $D$}
    \State Generate adversarial examples: $x_{adv} \leftarrow PGD(\theta, x, y, \epsilon, \alpha, T)$
    \State Compute loss: $\mathcal{L} \leftarrow \ell(\theta(x), y) + \ell(\theta(x_{adv}), y)$
    \State Update parameters: $\theta \leftarrow \theta - \eta \nabla_\theta \mathcal{L}$
  \EndFor
\EndFor
\end{algorithmic}
\end{algorithm}

\textbf{Alternative defense strategies and best practices:}
\begin{itemize}
  \item \textbf{TRADES:} Trade-off between robustness and accuracy via a regularized loss that penalizes changes in model logits under small perturbations; often yields better robustness-accuracy trade-offs than vanilla adversarial training.
  \item \textbf{Free Adversarial Training (FreeAT):} Reuses backward passes to generate adversarial examples cheaply and reduces training overhead.
  \item \textbf{MART (Misclassification Aware Adversarial Training):} Focuses training on examples near the decision boundary and can improve robustness for hard classes.
  \item \textbf{Randomized Smoothing:} Provides certified robustness guarantees under $\ell_2$ norm by averaging predictions over Gaussian noise; computationally expensive but gives provable bounds.
\end{itemize}

\textbf{Evaluation guidelines (to avoid overestimating robustness):}
\begin{itemize}
  \item Use strong, iterative attacks (PGD with 50--100 steps) and include multi-start random restarts to approximate worst-case attacks.
  \item Use AutoAttack (an ensemble of parameter-free strong attacks) as a standardized evaluation to report robust accuracy.
  \item Evaluate across a range of $\epsilon$ values and report full robust accuracy curves (not only a single point) to understand robustness-accuracy trade-offs.
  \item Test adaptive attacks that are specifically designed for the defense (e.g., gradient obfuscation checks) to ensure the defense does not rely on gradient masking.
\end{itemize}

\textbf{Practical training tips:}
\begin{itemize}
  \item Use mixed-precision and larger batch sizes where possible; adversarial training scales with batch size.
  \item Use curriculum adversarial training (increase $\epsilon$ over epochs) to stabilize training.
  \item Log both clean accuracy and robust accuracy during training and save checkpoints at multiple $\epsilon$ values.
\end{itemize}

\subsection{Appendix: Metrics and Statistical Reporting}\label{appendix:metrics}
For reproducibility we state the exact formulas used for all automatic metrics reported in the main text.

\textbf{BLEU-4} (sentence-level brevity-penalty form used, corpus BLEU computed via geometric mean of n-gram precisions):
\begin{align}
P_n &= \frac{\sum_{s\in S} \text{clip\_count}_n(s)}{\sum_{s\in S} \text{count}_n(s)} \\
BP &= \begin{cases} 1 & \text{if } c>r \\ e^{1-r/c} & \text{if } c \le r \end{cases} \\
\text{BLEU-4} &= BP \cdot \exp\left( \sum_{n=1}^4 w_n \log P_n \right)
\end{align}
with weights \(w_n = 1/4\).

\textbf{CIDEr} (consensus-based image description evaluation) summary:
\begin{equation}
\text{CIDEr} = \frac{1}{|S|} \sum_{s \in S} \frac{1}{M} \sum_{n=1}^{M} w_n \cdot \frac{\mathbf{g}_n(s)\cdot \mathbf{r}_n}{\|\mathbf{g}_n(s)\| \|\mathbf{r}_n\|}
\end{equation}
where \( \mathbf{g}_n \) and \( \mathbf{r}_n \) are TF-IDF weighted n-gram vectors for generated and reference captions and \(M=4\) by default. Full implementation follows \cite{vedantam2015cider}.

\textbf{METEOR}: We follow the standard F-mean combining unigram precision/recall with alignment fragmentation penalty \cite{banerjee2005meteor}.

\textbf{Macro-F1 (classification tasks):}
\begin{equation}
\text{Macro-F1} = \frac{1}{C} \sum_{c=1}^{C} \frac{2 \cdot \text{Precision}_c \cdot \text{Recall}_c}{\text{Precision}_c + \text{Recall}_c}
\end{equation}
All reported metrics are computed over 3 random seeds (seed=42, 123, 2024) and we report mean ± standard deviation. When comparing models we use paired t-tests at significance level \(\alpha=0.05\).

\subsection{Appendix: CLIP / Contrastive Learning Details}\label{appendix:clipdetails}
We expand the InfoNCE loss used for CLIP and describe how the temperature is parameterized and learned. For a batch of \(N\) matched image-text pairs, with L2-normalized embeddings \(z_{img,i}\) and \(z_{txt,j}\), we compute logits:
\begin{equation}
s_{ij} = \frac{z_{img,i}^\top z_{txt,j}}{\tau}
\end{equation}
The symmetric InfoNCE loss used is:
\begin{align}
\mathcal{L}_{img\to txt} &= -\frac{1}{N}\sum_{i=1}^N \log\frac{\exp(s_{ii})}{\sum_{j=1}^N \exp(s_{ij})} \\
\mathcal{L}_{txt\to img} &= -\frac{1}{N}\sum_{i=1}^N \log\frac{\exp(s_{ii})}{\sum_{j=1}^N \exp(s_{ji})} \\
\mathcal{L}_{CLIP} &= \frac{1}{2}(\mathcal{L}_{img\to txt} + \mathcal{L}_{txt\to img})
\end{align}

To ensure numerical stability and positivity, the temperature is implemented as a log-parameter:
\begin{equation}
\tau = \exp(\log\tau_\theta),\qquad \log\tau_\theta \in \mathbb{R}\ \text{is learned.}
\end{equation}
Gradients flow to \(\log\tau_\theta\) during optimization. In practice we initialize \(\log\tau_\theta=\log(0.07)\).

\textbf{Hard-negative mining (implementation note):} when enabled we compute in-batch similarities and select top-k highest-similarity mismatched pairs per anchor as additional negatives for an auxiliary margin loss. See `codes/q1_clip/train.py` (function `mine_hard_negatives`) for the implementation used in experiments.

\subsection{Appendix: Beam Search and Decoding}\label{appendix:decoding}
We include beam search pseudocode and clarify hyperparameters used in captioning evaluations.
\begin{algorithm}
\caption{Beam search decoding (beam width \(B\))}
\begin{algorithmic}[1]
\State Initialize beam with \(\langle\text{<start>}\rangle\) and score 0
\For{time step \(t=1\) to \(T_{max}\)}
  \State For each hypothesis in beam, compute next-token log-probabilities
  \State Expand each hypothesis with top-K next tokens producing \(B\times K\) candidates
  \State Keep top \(B\) hypotheses by cumulative log-probability (length normalization applied)
  \State If all hypotheses ended with \(\langle\text{<end>}\rangle\), break
\EndFor
\State Return highest-scoring hypothesis (after removing special tokens)
\end{algorithmic}
\end{algorithm}
We use beam size \(B\in\{1,3,5\}\) in ablations and length normalization with exponent \(\alpha=0.7\).

\subsection{Appendix: LoRA implementation details}\label{appendix:lora}
We reiterate the LoRA parameterization used and provide an implementation note. For a pretrained matrix \(W_0\in\mathbb{R}^{d\times k}\), LoRA injects low-rank matrices \(A\in\mathbb{R}^{r\times k}\) and \(B\in\mathbb{R}^{d\times r}\) and applies:
\begin{equation}
W = W_0 + \frac{\alpha}{r} BA
\end{equation}
where \(\alpha\) is a scalar scaling factor. During fine-tuning \(W_0\) remains frozen and only \(A,B\) (and optional layernorm and bias terms) are trained.

Minimal pseudocode for a LoRA-injected linear layer:
\begin{lstlisting}
class LoRALinear(nn.Module):
    def __init__(self, in_dim, out_dim, r=8, alpha=32):
        self.W0 = nn.Linear(in_dim, out_dim, bias=False)  # pretrained, frozen
        self.A = nn.Parameter(torch.zeros(r, in_dim))
        self.B = nn.Parameter(torch.zeros(out_dim, r))
        self.scaling = alpha / r
    def forward(self, x):
        return self.W0(x) + self.scaling * (x @ self.A.T @ self.B.T)
\end{lstlisting}
Reference implementation used: `codes/q3_lora/lora_layer.py`.

\subsection{Appendix: Adversarial Attacks — Algorithms and Evaluation Protocol}\label{appendix:adv}
We provide exact algorithmic steps used for FGSM and PGD evaluations.

\textbf{FGSM (single-step):}
\begin{align}
\eta &= \epsilon \cdot \text{sign}(\nabla_x \mathcal{L}(\theta, x, y)) \\
x_{adv} &= \text{clip}(x + \eta, x_{min}, x_{max})
\end{align}

\textbf{PGD (iterative projected gradient descent):}
\begin{algorithmic}[1]
\State Initialize \(x_0 = x + \mathcal{U}(-\epsilon,\epsilon)\) (random start optional)
\For{t = 0 to T-1}
  \State \(g_t \leftarrow \nabla_x \mathcal{L}(\theta, x_t, y)\)
  \State \(x_{t+1} \leftarrow \text{clip}_{\mathcal{B}_\epsilon(x)}(x_t + \alpha \cdot \text{sign}(g_t))\)
\EndFor
\State Return \(x_T\)
\end{algorithmic}

Evaluation protocol:
\begin{itemize}
  \item Report clean accuracy and robust accuracy at multiple \(\epsilon\) levels (e.g., {2/255, 4/255, 8/255}).
  \item Use PGD with \(T\in\{10,20\}\) steps and 5 random restarts for strong evaluation.
  \item When possible, include AutoAttack as a final sanity check.
\end{itemize}

\subsection{Appendix: Wav2Vec / HuBERT training hyperparameters}\label{appendix:audiohp}
Masking and clustering details:
\begin{itemize}
  \item Wav2Vec mask probability: 0.065, average mask length: 10 frames (as in \cite{baevski2020wav2vec}).

\section{Q3: LoRA Fine-tuning for Sentiment Analysis}\label{sec:q3}
\subsection{LoRA Formulation and Benefits}
LoRA (Low-Rank Adaptation) is a parameter-efficient fine-tuning technique that addresses the challenge of adapting large pre-trained models to downstream tasks without incurring high computational costs or storage overhead. For a pre-trained weight matrix $W_0 \in \mathbb{R}^{d \times k}$ (e.g., in a query or value projection layer of a Transformer), LoRA proposes to update it by adding a low-rank decomposition $BA$, where $B \in \mathbb{R}^{d \times r}$ and $A \in \mathbb{R}^{r \times k}$, and $r \ll \min(d, k)$. The updated weight matrix becomes $W = W_0 + BA$. During fine-tuning, $W_0$ is kept frozen, and only the low-rank matrices $A$ and $B$ (and optionally bias terms and layer normalization parameters) are trained. This significantly reduces the number of trainable parameters, typically by factors of $10^3$ to $10^4$, making fine-tuning more memory-efficient and faster. The rank $r$ controls the expressiveness of the adaptation; a higher rank allows for more flexibility but increases the number of trainable parameters.

\subsection{Prompting and Evaluation}
We fine-tune `meta-llama/Llama-3.2-1B` on a stratified subset of the Emotion dataset (train=1500, val=50, test=100) using LoRA with $r=8, \alpha=32,\mathrm{dropout}=0.1$. The scaling factor $\alpha$ is used to rescale the updates from $BA$, typically set such that $BA \cdot (\alpha/r)$ is applied. Evaluation metrics include classification accuracy and macro-F1 score, along with confusion matrices and sample model outputs to provide a qualitative assessment of the fine-tuned model's performance on sentiment classification. Prompts are formatted using specific templates provided in the `codes/q3_lora` module, ensuring consistent input to the language model.

\section{Q4: Adversarial Attacks and Adversarial Training}
\subsection{Attack Algorithms}
FGSM (Fast Gradient Sign Method) perturbs inputs in the direction of the sign of the gradient of loss w.r.t input (one-step). PGD (Projected Gradient Descent) performs iterative perturbations constrained to an $\ell_\infty$ ball of radius $\epsilon$, with step size $\alpha$ and $T$ iterations. We implement both and evaluate their effect on model accuracy.

\subsection{Adversarial Training}
We implement adversarial training by generating PGD adversarial examples on-the-fly during each training batch and training on a mixture of clean and adversarial images. We report robust accuracy and compare trade-offs between clean accuracy and robustness.

We evaluate models under FGSM and PGD attacks across various $\epsilon$ values (e.g., $\epsilon\in\{0.01,0.03,0.05\\}$ for normalized pixel data). \subsection{Ablation studies}
We systematically varied several key factors in the experiments:
\begin{itemize}
  \item Encoder freeze schedule (fully frozen vs. partial unfreeze vs. full fine-tune).
  \item Decoder attention dimensionality and attention mechanism (additive vs. dot-product).
  \item Tokenizer choices (word-level vs. subword/BPE) and vocabulary size.
  \item LoRA rank $r$ (tested $r\in\{4,8,16\}$) and effect on validation accuracy and model size.
  \item PGD iterations and step sizes when performing adversarial training.
\end{itemize}
Ablation tables are generated automatically by the experiment scripts and stored under `codes/q*_results/` for reference and inclusion into the article.

\subsection{Statistical significance and uncertainty}
To determine whether differences between models are statistically significant, we: (1) run multiple independent training runs with different seeds (recommended at least 3--5), (2) compute paired metrics (e.g., BLEU or accuracy) on the same test set, and (3) apply paired t-tests or bootstrap confidence intervals. For example, to test whether Model A's improvement in BLEU-4 over Model B is significant, compute per-sample BLEU (or use corpus-level metric with bootstrap resampling) and apply a two-sided paired t-test or report 95\% bootstrap confidence intervals.

\subsection{Error analysis and qualitative evaluation}
We conduct a qualitative error analysis for image captioning by sampling diverse images and categorizing failure modes, such as:
\begin{itemize}
  \item Missing objects (model omits an entity present in the image).
  \item Hallucinated relations (model asserts a spatial relationship not supported by the image).
  \item Incorrect attributes (wrong color or count of objects).
\end{itemize}
For each failure type we provide illustrative examples saved as annotated images (e.g., `q1_pred_example_failure_01.pdf`) and include suggested mitigations (larger data, stronger attention, or object detectors to ground nouns).

\subsection{Runtime, memory, and model complexity}
We measure training wall-clock time, GPU memory consumption, and parameter counts for each model configuration. Example notes:
\begin{itemize}
  \item VGG16-based encoder + LSTM decoder (decoder params only up to ~10M parameters depending on vocab size); frozen encoder reduces gradient memory substantially.
  \item ViT-small (timm) has N parameters; adding projection head increases parameter count slightly.
  \item Wav2Vec full fine-tuning is memory-intensive; using 16-bit mixed precision and gradient checkpointing helps to fit larger batches.
\end{itemize}
We include a small table of parameter counts and a runtime profile for standard experiments in the supplementary materials.

\subsection{Human evaluation}
Automatic metrics have known limitations. We outline an optional human evaluation protocol: recruit N evaluators, present randomized pairs of (GT, prediction), and collect Likert-scale judgments on relevance, correctness, and fluency. Inter-annotator agreement (Krippendorff's alpha or Cohen's kappa) should be reported.

\subsection{Limitations of the current experiments}
Major limitations include compute resources (limiting full fine-tuning for large models) and dataset size. Additionally, BLEU and related metrics emphasize n-gram overlap and may not capture semantic correctness; hence we encourage combining BLEU with human evaluation and other metrics (CIDEr, METEOR).

\subsection{Recommendations for final experiments}
For a final, publication-ready evaluation, we recommend:
\begin{enumerate}
  \item Running full-scale training for captioning for at least 30--50 epochs with scheduled LR decay and checkpointing.
  \item Running 3--5 independent runs for each major experiment to capture variance and compute confidence intervals.
  \item Performing beam search (beam size 3--5) during inference and comparing beam vs greedy outputs.
  \item Reporting CIDEr and METEOR in addition to BLEU, and providing human evaluation results if possible.
  \item Documenting exact compute used (GPU model, memory, wall time) and making final checkpoints available if licensing permits.
\end{enumerate}
